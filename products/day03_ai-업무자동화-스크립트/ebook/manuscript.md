# 반복 업무는 이제 그만
### 클로드(Claude)로 만드는 나만의 업무 자동화 스크립트

---

## 프롤로그 — 같은 일을 세 번째 반복하고 있다면

매주 월요일 아침, 똑같은 순서로 엑셀을 정리하고, 똑같은 형식으로 보고서를 씁니다.
매일 들어오는 문의 메일에 거의 똑같은 답장을 붙여넣기 합니다.
매달 말, 똑같은 파일을 뒤져서 인보이스를 만듭니다.

이 책은 그 "똑같은 일"을 클로드에게 대신 시키는 법을 다룹니다. 코딩을 몰라도 괜찮습니다. **당신은 "무엇을 반복하고 있는지"만 정확히 설명하면 되고, 스크립트는 클로드가 씁니다.**

자동화라고 하면 개발자의 영역처럼 느껴지지만, 실제로 돈이 되는 자동화의 90%는 화려한 시스템이 아니라 "엑셀 정리 5분 걸리던 걸 5초로 줄이는" 수준의 작은 스크립트입니다. 그리고 이런 작은 자동화를 대신 만들어주는 것 자체가 훌륭한 부업이 됩니다 — 주변 소상공인, 1인 기업가들은 이런 반복 업무에 매달 몇 시간씩 쓰고 있고, 그걸 없애주는 대가로 기꺼이 돈을 지불합니다.

이 책은 **오늘 컴퓨터 앞에서 바로 따라 할 수 있는 12가지 자동화 방법**과, 클로드에게 그대로 던지는 프롬프트를 담았습니다. 실제로 동작하는 소스코드 모음은 다음 편(실전 소스코드 모음)에서 이어집니다.

## 1. 자동화를 코딩 없이 만든다는 것

"자동화"라고 하면 파이썬, API, 서버 같은 단어부터 떠오릅니다. 하지만 클로드와 함께라면 순서가 바뀝니다.

- **당신이 할 일**: 반복되는 업무를 말로 설명하기 (예: "매주 이 엑셀 파일에서 이 컬럼 합계를 내서 이메일로 보내고 싶어")
- **클로드가 할 일**: 그 설명을 실제로 동작하는 스크립트(Google Apps Script, Python, 노코드 워크플로우 등)로 바꾸기
- **당신이 다시 할 일**: 스크립트를 실행해보고, 안 되는 부분을 다시 클로드에게 설명해서 고치기

2026년 기준으로 자동화 생태계는 이미 "AI가 도구를 부르는" 방향으로 완전히 넘어왔습니다. Zapier, Make, n8n 같은 노코드 자동화 플랫폼들은 모두 AI 에이전트가 워크플로우를 직접 설계하거나 실행하는 기능을 갖췄고, n8n은 LangChain 기반 AI 노드를 70개 이상 내장해 시각적 편집기 안에서 바로 AI 자동화를 구성할 수 있게 됐습니다. 즉 지금은 "자동화 툴을 배우는 시간"보다 "무엇을 자동화할지 정확히 설명하는 능력"이 훨씬 중요해진 시점입니다.

이 책이 가르치는 건 코딩이 아니라 **이 설명하는 능력**입니다.

## 2. 시작 전에 준비할 것

<div class="method-meta">준비물은 딱 4가지 — 다 무료로 시작 가능합니다</div>

1. **클로드 계정** — 스크립트를 길게 짜고 여러 번 수정할 일이 많으니, 무료 플랜의 대화 횟수 제한이 부담되면 Pro 플랜을 권장합니다.
2. **자동화할 업무 하나** — 완벽한 걸 고르려 하지 마세요. "매주 반복되고, 규칙이 명확한" 가장 단순한 업무 하나면 충분합니다.
3. **실행 환경 하나** — 구글 스프레드시트(Apps Script), 혹은 노코드 툴(Zapier/Make/n8n) 중 이미 쓰고 있거나 익숙한 것 하나.
4. **테스트용 샘플 데이터** — 실제 자료를 그대로 쓰지 말고, 민감한 정보를 지운 샘플로 먼저 검증하세요.

**이 책의 방법을 읽는 순서**: 방법 1(진단)은 반드시 먼저 읽고, 그다음은 순서와 상관없이 지금 당장 필요한 방법으로 건너뛰어도 됩니다.

## 3. 방법 1 — 반복 업무 진단표 만들기

자동화에서 가장 많이 실패하는 지점은 "너무 큰 업무"부터 시작하는 것입니다. 처음엔 반드시 작게 시작하세요.

### 진행 순서
1. 최근 2주간 내가 했던 반복 업무를 떠오르는 대로 10개 적는다 (완벽하지 않아도 됨)
2. 각 업무를 "빈도 × 소요시간 × 규칙성(같은 방식으로 반복되는가)" 3가지 기준으로 클로드에게 점수를 매겨달라고 요청
3. 점수가 가장 높은 업무 1개를 첫 자동화 대상으로 확정
4. 그 업무의 "입력(무엇을 보고) → 처리(어떻게 판단/가공) → 출력(무엇을 만드는가)"을 한 문장씩 적는다

### 왜 이 순서가 중요한가
"규칙성"이 낮은 업무(매번 판단 기준이 달라지는 일)는 자동화 난이도가 훨씬 높습니다. 처음엔 규칙이 명확한 업무부터 골라야 1주일 안에 성공 경험을 만들 수 있습니다.

<div class="worksheet-note">예시 — "매주 월요일 지난주 매출 엑셀을 열어 합계를 내고 팀 채팅방에 공유한다" → 빈도 높음, 소요시간 짧지만 매주 반복, 규칙 명확 → 자동화 1순위</div>

## 4. 방법 2 — 구글 시트 + Apps Script로 보고서 자동화

구글 스프레드시트를 이미 쓰고 있다면 가장 진입장벽이 낮은 자동화 방법입니다. Apps Script는 별도 설치 없이 스프레드시트 안에서 바로 실행되는 스크립트 환경입니다.

### 진행 순서
1. 자동화할 시트의 구조(어떤 컬럼에 무엇이 있는지)를 클로드에게 설명
2. "이 데이터를 요약해서 매주 월요일 오전 9시에 이메일로 보내는 Apps Script를 짜줘"라고 요청
3. 스프레드시트 상단 메뉴 `확장 프로그램 → Apps Script`에 클로드가 준 코드를 붙여넣기
4. `트리거` 메뉴에서 "매주 월요일 실행"으로 예약 설정
5. 테스트 실행 후 에러가 나면 에러 메시지를 그대로 클로드에게 붙여넣어 수정 요청

### 조심할 점
- 처음 실행 시 구글이 "권한 승인"을 요구합니다 — 본인 계정이 맞는지 확인 후 승인하세요.
- 이메일 발송 스크립트는 하루 발송량 제한(개인 계정 기준 약 100통)이 있습니다. 대량 발송이 필요하면 다른 방법(방법 4)을 고려하세요.

---

## 5. 방법 3 — 이메일 자동 분류 · 요약

문의 메일, 주문 메일, 스팸이 뒤섞여 들어올 때 매번 열어보는 시간을 줄이는 방법입니다.

### 진행 순서
1. 최근 받은 메일 20통 정도의 제목/발신자 패턴을 클로드에게 보여주고 분류 기준을 함께 설계
2. Gmail이라면 "필터 + 라벨" 규칙을 클로드에게 요청해서 1차 자동 분류
3. 규칙만으로 안 걸러지는 메일은 Apps Script로 "본문을 읽고 카테고리를 판단해 라벨을 붙이는" 스크립트를 요청
4. 매일 아침 "어제 온 문의 메일 요약"을 만들어주는 스크립트를 추가로 요청

### 실전 팁
완벽한 분류를 처음부터 노리지 마세요. "확실한 것만 자동 분류하고, 애매한 건 사람이 보는 폴더로 모으기" 방식이 실패율이 훨씬 낮습니다.

## 6. 방법 4 — 노코드 자동화 툴에 클로드 연결하기

Zapier, Make, n8n은 "이 앱에서 이런 일이 생기면 저 앱에서 이런 일을 해라"는 흐름을 코딩 없이 연결해주는 도구입니다. 2026년 기준 셋 다 AI 기능이 크게 강화됐습니다.

| 도구 | 강점 | 이런 사람에게 |
|---|---|---|
| Zapier | 7,000개 이상 앱 연동, 가장 쉬운 온보딩 | 처음 자동화를 시작하는 사람 |
| Make(구 Integromat) | 시각적 분기/필터가 강력함 | 조건이 여러 갈래인 복잡한 흐름 |
| n8n | 오픈소스, AI 에이전트 노드 내장, 직접 호스팅 가능 | 비용을 아끼고 싶거나 데이터를 직접 관리하고 싶은 사람 |

### 진행 순서
1. 자동화하려는 흐름을 "A 앱에서 B 이벤트가 생기면 → C 앱에서 D를 한다" 한 문장으로 정리
2. 클로드에게 이 문장을 보여주고 "이 흐름을 Zapier(또는 Make/n8n)로 만들려면 어떤 단계(Trigger·Action)로 쪼개야 하는지" 설계 요청
3. 설계안대로 툴 화면에서 단계를 하나씩 만든다 (모르는 설정값은 스크린샷을 클로드에게 보여주고 물어봐도 됩니다)
4. 테스트 실행 → 실패하면 에러 로그를 클로드에게 그대로 전달해서 원인 파악

### 조심할 점
무료 플랜은 대부분 "실행 횟수 제한"이 있습니다. 처음엔 무료로 시작하되, 실제로 매일 여러 번 도는 자동화라면 유료 전환 시점을 미리 계산해두세요.

## 7. 방법 5 — 엑셀/스프레드시트 데이터 정리 스크립트

"파일을 열어서 형식을 맞추고, 중복을 지우고, 표를 다시 만드는" 작업은 반복성이 가장 높은 업무 중 하나입니다.

### 진행 순서
1. 정리 전/후 데이터 예시(가짜 데이터로)를 클로드에게 보여준다
2. "이 형태를 저 형태로 바꾸는 스크립트를 짜줘"라고 요청 (Python + pandas, 또는 Apps Script 중 선택)
3. 실제 파일 대신 샘플 파일로 먼저 실행해서 결과 확인
4. 문제없으면 실제 파일에 적용, 원본은 항상 백업해둘 것

### 왜 사람이 직접 검증해야 하는가
데이터 정리 자동화는 "겉보기엔 맞는데 특정 케이스에서만 틀리는" 실수가 잘 드러나지 않습니다. 처음 몇 번은 결과를 손으로 대조해서 확인하는 과정을 꼭 거치세요.

## 8. 방법 6 — 견적서 · 인보이스 자동 생성

프리랜서, 소상공인에게 매달 반복되는 대표적인 업무입니다.

### 진행 순서
1. 기존에 쓰던 견적서/인보이스 양식(포맷)을 클로드에게 보여준다
2. "이 양식대로, 고객명·품목·수량·단가만 입력하면 자동으로 문서를 만들어주는 스크립트"를 요청
3. 구글 시트에 고객 정보를 입력하면 자동으로 PDF가 생성되는 방식(Apps Script)이나, 간단한 웹페이지 형태(Claude로 직접 제작) 중 선택
4. 완성본 1개를 실제 발송해보고 형식이 틀어지지 않는지 확인

### 확장 아이디어
인보이스 생성과 동시에 "발송 완료" 상태를 시트에 기록하고, 결제 기한이 지나면 자동으로 리마인드 메일을 보내는 흐름까지 방법 4(노코드 툴)와 연결하면 완전한 자동 청구 시스템이 됩니다.

## 9. 방법 7 — 카카오톡 · 슬랙 알림 자동화

중요한 일이 생겼을 때 사람이 직접 확인하지 않아도 알림이 오게 만드는 방법입니다.

### 진행 순서
1. "언제 알림을 받고 싶은지" 조건을 명확히 한다 (예: 시트에 새 행이 추가될 때, 매출이 목표치를 넘을 때)
2. 슬랙이라면 Incoming Webhook을, 카카오톡이라면 카카오톡 채널의 알림톡/친구톡 API 연동을 클로드와 함께 설계
3. 조건이 맞을 때 메시지를 보내는 스크립트를 Apps Script나 노코드 툴로 구현
4. 테스트 메시지를 먼저 본인에게만 보내보고 문구/타이밍을 확인한 뒤 실제 대상에게 적용

### 조심할 점
알림이 너무 잦으면 오히려 무시당합니다. "정말 사람이 봐야 하는 순간"만 골라서 알림을 설계하세요.

## 10. 방법 8 — 고객 문의 자동 응대 스크립트

자주 묻는 질문에 매번 같은 답을 직접 타이핑하고 있다면 자동화 대상 1순위입니다.

### 진행 순서
1. 최근 문의 중 반복되는 질문 유형 10개를 정리
2. 클로드에게 유형별 답변 스크립트를 요청 (친절하되 로봇 같지 않은 톤으로)
3. 카카오톡 채널 관리자센터의 "자동응답" 기능, 혹은 인스타그램/스레드 DM 자동 응답 기능에 그대로 등록
4. "패턴에 안 걸리는 질문"은 사람에게 넘어가도록 예외 처리 문구를 반드시 넣는다

### 실전 팁
자동 응답이라는 걸 숨기지 않는 편이 신뢰를 더 얻습니다. "빠른 안내를 위해 자동 답변이 먼저 나가고, 추가 문의는 담당자가 확인합니다" 같은 문구 하나면 충분합니다.

---

## 11. 방법 9 — 파일 · 폴더 정리 자동화

다운로드 폴더, 공유 드라이브가 뒤죽박죽인 경우 의외로 수요가 큰 자동화입니다.

### 진행 순서
1. 정리 규칙을 말로 정의 (예: "파일명에 날짜가 있으면 연도별 폴더로, 확장자별로 하위 분류")
2. 클로드에게 이 규칙을 그대로 스크립트(Python 또는 구글 드라이브 Apps Script)로 요청
3. 테스트 폴더에서 먼저 실행해보고 결과 확인
4. 문제없으면 실제 폴더에 적용, 삭제가 아니라 "이동"으로 설계해서 되돌릴 수 있게 한다

### 조심할 점
자동 삭제 기능은 절대 처음부터 넣지 마세요. 몇 주간 "이동/분류"만 시켜보고 확실히 신뢰가 쌓인 다음에 고려해도 늦지 않습니다.

---

## 12. 방법 10 — 정기 실행 자동화 (스케줄링 · 크론)

만든 스크립트를 사람이 매번 눌러서 실행하지 않고, 정해진 시간에 저절로 돌게 만드는 마지막 단계입니다.

### 진행 순서
1. 구글 Apps Script라면 `트리거` 메뉴에서 시간 기반 트리거 등록 (매일/매주/매월)
2. GitHub 저장소로 관리하는 스크립트라면 GitHub Actions의 `schedule`(cron) 기능으로 정기 실행 설정을 클로드에게 요청
3. 노코드 툴이라면 Trigger를 "스케줄"로 설정
4. 처음 1~2주는 실행 로그(성공/실패 여부)를 꼭 직접 확인하는 습관을 들인다

### 왜 이 단계가 마지막인가
스케줄링은 "이미 손으로 여러 번 실행해서 검증이 끝난 스크립트"에만 적용해야 합니다. 검증 안 된 스크립트를 자동 반복시키면 실수도 그만큼 반복됩니다.

## 13. 방법 11 — SNS/콘텐츠 발행 자동화

블로그, SNS에 꾸준히 올려야 하는데 매번 잊어버린다면 이 방법이 유용합니다.

### 진행 순서
1. 발행 주기와 콘텐츠 유형을 정한다 (예: 매주 화/목, 카드뉴스 형태)
2. 클로드에게 "이번 주 발행할 콘텐츠 초안 2개"를 미리 만들어달라고 요청
3. 초안을 검수 후, 예약 발행 기능이 있는 채널은 그 기능을 활용
4. 예약 발행이 없는 채널은 방법 4(노코드 툴)의 스케줄 기능과 연결

### 조심할 점
전량 자동 발행(사람 검수 없이 바로 게시)은 추천하지 않습니다. 초안까지는 자동화하되, 최종 게시 버튼은 사람이 누르는 구조를 권장합니다 — 실계정 신뢰도와 직결되기 때문입니다.

## 14. 방법 12 — 자동화를 부업으로 파는 법

지금까지의 11가지를 직접 한 번씩 해봤다면, 이 경험 자체가 상품이 됩니다.

### 진행 순서
1. 가장 자신 있게 만든 자동화 1개를 "사례"로 다시 정리 (전/후 비교, 걸린 시간)
2. 주변 소상공인/1인 기업가 중 비슷한 반복 업무를 가진 사람에게 무료로 1건 시범 적용
3. 후기와 사례를 근거로 크몽/숨고에 "업무 자동화 대행" 서비스 등록
4. 처음엔 건당 요금, 신뢰가 쌓이면 월 유지보수 구독 요금으로 확장

### 가격 감각 잡는 법
"자동화로 절약되는 시간 × 그 사람의 시급"을 기준으로 설명하면 가격 저항이 훨씬 줄어듭니다. 예를 들어 매주 2시간이 절약된다면, 월 8시간 절약 — 그 값어치를 숫자로 먼저 보여주세요.
