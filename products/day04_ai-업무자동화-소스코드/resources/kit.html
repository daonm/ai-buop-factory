『야근 없는 사무실』을 읽은 다음날 바로 붙여넣는 실행용 코드 패키지입니다.

전자책은 "어떻게 자동화하는지"를 설명했다면, 이 패키지는 "그 코드 자체"입니다.

『야근 없는 사무실』의 12가지 방법 중 실제로 코드가 필요한 7가지를 골라, 직접 실행해서 동작을 확인한 소스코드로 담았습니다. 각 스크립트는 폴더 하나에 코드 파일 + 사용법 README + (해당하는 경우) 테스트용 샘플 데이터까지 포함되어 있어서, 폴더를 열자마자 바로 따라 할 수 있습니다.

사용법 — 먼저 이 문서(설명서)에서 내 상황에 맞는 스크립트를 찾고, 해당 폴더의 README를 열어 그대로 따라 하세요. 막히면 README 안의 "클로드에게 요청하는 법" 문구를 그대로 복사해서 쓰세요.

  1. 내 반복 업무와 가장 가까운 스크립트 1개를 아래 목록에서 고른다.
  2. 해당 폴더의 README.md를 열어 설치 → 실행 순서를 따라 한다.
  3. 샘플 데이터로 먼저 검증한 뒤, 내 실제 데이터로 바꿔서 재실행한다.

034주 정착 체크리스트

7개를 한꺼번에 도입하려 하지 마세요. 순서대로 한 주에 1~2개씩 정착시키는 게 성공률이 높습니다.

1주차가장 아픈 반복 업무부터

  • 전자책 방법 1(진단표)로 자동화 1순위 업무 확정
  • 1순위 업무에 해당하는 스크립트 폴더의 README 정독
  • 샘플 데이터로 먼저 실행해서 결과 확인

2주차내 데이터로 전환

  • 실제 데이터(민감정보 제거한 사본)로 재실행
  • 결과를 손으로 대조해 정확도 확인
  • 문제 있으면 에러 메시지를 클로드에게 그대로 붙여넣어 수정

3주차두 번째 스크립트 확장

  • 같은 카테고리 또는 연결되는 다음 스크립트 1개 추가 도입
  • 예 — 03(데이터 정리) 다음엔 05(슬랙 알림)로 결과 자동 통보
  • 두 스크립트를 이어붙이고 싶으면 클로드에게 "두 스크립트를 연결해줘"로 요청

4주차정기 실행으로 전환

  • 손으로 3회 이상 성공한 스크립트만 07(GitHub Actions) 또는 Apps Script 트리거로 등록
  • 첫 1~2주는 실행 로그를 직접 확인하는 습관 들이기
  • 절약된 시간을 숫자로 기록 — 전자책 방법 12(부업으로 파는 법)의 근거 자료가 됨

이 표로도 안 풀리면 — 에러 메시지 전문 + 어느 스크립트인지를 클로드에게 그대로 붙여넣으세요. "다음 에러가 떴어: [메시지]. [스크립트명]의 어느 부분이 문제인지 알려줘."

코드를 이해하지 못해도 괜찮습니다. 폴더를 열고, README를 따라가고, 막히면 에러를 그대로 클로드에게 보여주세요.
