# AI 부수입 실전 프롬프트팩 — 60선

> 이 문서는 **『이 책은 AI가 썼습니다』(Day01 전자책)** 를 읽고 "그래서 오늘 뭘 입력해야 하지?"에서 막히는 분들을 위한 실행 키트입니다. 책에 담긴 20개 프롬프트를 각 방법별로 5단계(기획→설계→제작→홍보→개선)로 쪼개고 확장해서, **총 60개**를 준비했습니다.

## 사용법 3줄 요약

1. `[대괄호]` 부분만 내 상황에 맞게 바꿔서 클로드에 그대로 붙여넣으세요.
2. 한 번에 완벽한 답을 기대하지 말고, 나온 결과에 **"더 구체적으로", "예시 포함해서", "표로 정리해줘"** 를 이어서 요청하세요.
3. 무료 플랜은 하루 대화 수 제한(약 30~50회)이 있습니다. 전자책 원고처럼 긴 결과물을 여러 번 만들어야 한다면 Pro 플랜(월 $20)을 권장합니다.

## 카테고리 A — 전자책 · 디지털 콘텐츠 제작 (10개)

**A1. 주제 발굴**
```
나는 [분야]에 대해 [경력/경험]이 있어. 이 지식으로 팔릴 만한 전자책 주제 5개와
각각의 타겟 독자, 예상 판매 포인트를 표로 정리해줘.
```

**A2. 경쟁 콘텐츠 분석**
```
[주제]로 이미 나와 있는 전자책/강의들이 보통 어떤 내용을 다루는지 추정해줘.
그리고 내가 다르게 접근할 수 있는 차별점 3가지를 제안해줘.
```

**A3. 목차 설계**
```
[주제]에 대한 전자책 목차를 12개 챕터로 구성해줘. 각 챕터는 실행 가능한
방법 1개씩 담고, 챕터 순서는 "왜 필요한가 → 어떻게 하는가 → 무엇을 조심해야 하는가"
흐름으로 짜줘.
```

**A4. 챕터 본문 작성**
```
[챕터 제목]에 대한 본문을 써줘. 실제로 따라 할 수 있는 순서와 예시를 포함해서
1500자 내외로. 마지막엔 바로 쓸 수 있는 프롬프트 1개도 같이 넣어줘.
```

**A5. 도입부/훅 강화**
```
이 원고의 도입부(프롤로그)를 다시 써줘. 첫 두 문장 안에 "이걸 읽어야 하는 이유"가
드러나게 하고, 뻔한 표현("이 시대에", "누구나 할 수 있는")은 빼줘.
```

**A6. 쉬운 문장으로 다듬기**
```
이 원고를 더 쉬운 문장으로, 중학생도 이해할 수 있게 다듬어줘. 전문용어가 나오면
괄호로 짧은 설명을 붙여줘: [원고]
```

**A7. 표지/제목 카피 10개**
```
[주제]에 대한 전자책 제목 후보 10개를 만들어줘. 숫자를 넣은 것, 질문형,
결과 중심(예: "~하는 법"이 아니라 "~해서 얻은 것") 3가지 스타일을 섞어서.
```

**A8. 챕터 순서/분량 재배치**
```
지금 목차에서 [챕터명]이 너무 이론적이야. 실행 단계를 앞으로 당기고 이론은
뒤로 미루는 식으로 순서를 다시 짜줘. 이유도 설명해줘.
```

**A9. 자가 검수 (품질 체크)**
```
이 원고를 "실제로 따라 할 수 있는가" 기준으로 검토해줘. 추상적이거나
실행 단계가 빠진 부분을 찾아서 구체적으로 뭐가 부족한지 알려줘: [원고]
```

**A10. 시리즈 확장 아이디어**
```
[주제] 전자책이 잘 팔린다면, 같은 독자층에게 다음으로 팔 수 있는 후속
전자책/실습자료 주제 3개를 제안해줘. 왜 이 순서가 자연스러운지도 설명해줘.
```

## 카테고리 B — SNS(스레드) 홍보 · 콘텐츠 자동 생성 (10개)

**B1. 핵심 메시지 1줄 뽑기**
```
[상품 설명]을 한 문장으로 요약해서, SNS에서 스크롤을 멈추게 할 후킹 문장
5개를 만들어줘.
```

**B2. 톤별 홍보 글 7종 세트**
```
[상품/서비스]를 홍보하는 스레드 글 7개를 서로 다른 톤(질문형, 스토리형,
리스트형, 반박형, 공감형, 증거형, 긴급성형)으로 각 300자 이내로 써줘.
```

**B3. 댓글 답글 초안**
```
다음 댓글에 친근하고 자연스러운 톤으로 답글을 써줘. 너무 영업하는 느낌은
빼고 대화하듯이: [댓글 내용]
```

**B4. 반응 분석 & 개선**
```
이 글의 반응(좋아요/댓글 수)이 [좋았다/안 좋았다]. 이유를 추정하고, 같은
패턴 혹은 반대 패턴을 적용한 새 글 3개를 써줘: [글 내용 + 반응 데이터]
```

**B5. 주간 발행 캘린더**
```
이번 주에 올릴 홍보 글 일정표를 요일별로 짜줘. 각 글의 목적(인지/관심/전환)과
발행 시간대 추천도 함께 표로 정리해줘.
```

**B6. 반박 대응 문구**
```
[타겟 고객]이 이 상품을 안 사는 이유(반박/의심 포인트) 5가지와, 그에 대한
짧고 담백한 대응 문구를 만들어줘. 방어적으로 들리지 않게.
```

**B7. 프로필/바이오 최적화**
```
[상품/서비스]를 파는 스레드 계정 프로필 소개글을 3가지 버전(전문가형,
친근형, 결과중심형)으로 써줘. 각 100자 이내로.
```

**B8. 시리즈 콘텐츠 기획**
```
[주제]에 대해 일주일 동안 매일 다른 각도로 올릴 수 있는 콘텐츠 시리즈
7개를 기획해줘. 각각 제목과 핵심 메시지만 간단히.
```

**B9. 후기/사회적 증거 활용**
```
다음 구매 후기를 SNS 홍보 글로 재구성해줘. 과장하지 않고 담백하게,
후기 원문의 핵심 표현은 그대로 살려서: [후기 원문]
```

**B10. 재발행(리사이클) 변형**
```
2주 전에 올렸던 이 글을 완전히 새로운 글처럼 느껴지게 다시 써줘. 같은
메시지, 다른 표현과 구성으로: [기존 글]
```

## 카테고리 C — 판매 페이지 · 가격 전략 (8개)

**C1. 상세페이지 3버전**
```
[상품명]의 판매 페이지 카피를 감성형/정보형/후기형 3버전으로 써줘.
각 버전은 제목-소개-혜택-CTA 구조로.
```

**C2. FAQ 초안**
```
[상품명]을 살까 말까 고민하는 사람이 물어볼 만한 질문 8개와, 신뢰가 가는
답변을 만들어줘. 과장된 약속은 피하고.
```

**C3. 가격 책정 근거**
```
[상품명]의 가격을 어떻게 책정하면 좋을지, 비슷한 상품 사례를 참고해서
근거와 함께 3가지 시나리오(저가/중가/고가)로 제안해줘.
```

**C4. 얼리버드/한정 이벤트 문구**
```
[상품명]의 런칭 얼리버드 이벤트 문구를 만들어줘. 압박감은 주되 과장되거나
거짓된 긴급성은 쓰지 말고.
```

**C5. 혜택 vs 기능 재구성**
```
다음은 [상품]의 기능 목록이야. 이걸 "고객이 얻는 결과" 중심 문장으로
바꿔줘: [기능 목록]
```

**C6. 타겟 독자 페르소나**
```
[상품명]을 살 것 같은 사람의 페르소나 3명을 만들어줘. 각각의 고민,
검색할 것 같은 키워드, 구매를 망설이는 이유까지 포함해서.
```

**C7. 경쟁 비교 문구**
```
[상품군]에서 비슷한 상품들과 비교했을 때 내 상품이 가진 차별점을
비교표로 정리해줘. 상대를 비방하지 않는 톤으로.
```

**C8. 가격 인상 타이밍 판단**
```
지금까지 판매 데이터를 정리했어: [판매 개수/후기 수/기간]. 가격을
올려도 될지, 올린다면 얼마가 적당할지 근거와 함께 제안해줘.
```

## 카테고리 D — 실습자료(템플릿·소스코드·워크시트) 제작 (8개)

**D1. 실습자료 구조 설계**
```
[전자책 주제]를 읽은 사람이 "바로 써먹을 수 있는" 실습자료를 만들려고 해.
어떤 형태(체크리스트/워크시트/템플릿/소스코드)가 적합할지, 구성 항목과
함께 제안해줘.
```

**D2. 체크리스트 항목화**
```
[주제]를 처음 시작하는 사람이 순서대로 따라 할 수 있는 체크리스트를
일 단위/주 단위로 나눠서 만들어줘. 각 항목은 5분 안에 이해되는 문장으로.
```

**D3. 워크시트 질문 설계**
```
[주제]에 대해 사용자가 직접 빈칸을 채우면서 생각을 정리할 수 있는
워크시트 질문 10개를 만들어줘. 너무 추상적이지 않게, 바로 답할 수 있는
수준으로.
```

**D4. 노션 템플릿 구조 설계**
```
[상품]에 어울리는 노션 템플릿 구조(데이터베이스 속성, 뷰 구성 포함)를
설계해줘.
```

**D5. 소스코드 README 작성**
```
다음 코드/스크립트의 사용법을 처음 보는 사람도 이해할 수 있게 README로
정리해줘. 설치 방법, 실행 방법, 자주 나는 에러와 해결법 포함: [코드/스크립트 설명]
```

**D6. 예시/샘플 데이터 생성**
```
[템플릿/워크시트]에 넣을 예시 데이터(가상의 완성 사례)를 만들어줘.
너무 완벽하지 않게, 실제로 쓸 법한 현실적인 수준으로.
```

**D7. 업셀 구조 설계**
```
[전자책 주제]를 읽은 사람에게 바로 다음으로 팔 수 있는 실습자료 상품을
기획해줘. 전자책과 자연스럽게 이어지는 "그다음 단계" 느낌으로.
```

**D8. 사용성 검수**
```
이 실습자료를 처음 보는 사람 입장에서 검토해줘. 설명이 부족하거나
바로 따라 하기 애매한 부분이 있으면 구체적으로 짚어줘: [자료 내용]
```

## 카테고리 E — 운영 · 회고 · 확장 (24개 중 발췌, 각 방법 공통 5개)

**E1. 반복 업무 자동화 설계**
```
이 반복 업무를 자동화하려면 어떤 방법이 있을지 단계별로 설명해줘.
코딩 지식이 없어도 따라 할 수 있는 수준으로: [업무 내용]
```

**E2. 주간 회고**
```
이번 주에 만든 상품/올린 글/판매 결과를 정리했어: [데이터]. 잘된 점 2가지,
개선할 점 2가지를 뽑고, 다음 주 우선순위 1가지를 제안해줘.
```

**E3. 월간 전략 재점검**
```
지금까지 한 달간의 결과를 정리했어: [데이터]. 지금 방향을 계속 갈지,
다른 주제/형식으로 전환할지 판단해줘. 근거도 함께.
```

**E4. 새 주제 발굴 (반응 기반)**
```
지금까지 반응이 좋았던 콘텐츠는 [내용/데이터]야. 이 패턴과 비슷한 새
주제 5개를 제안해줘. 왜 비슷한 반응이 나올 거라 예상하는지도 설명해줘.
```

**E5. 고객 문의 대응 스크립트**
```
[상품]에 대해 고객이 자주 묻는 질문과 불만을 정리하고, 친절하면서도
간결한 응대 스크립트를 만들어줘.
```

## 프롬프트 조합 레시피 — 하루 30분 루틴

혼자 쓰기보다 **이어 붙여서** 쓸 때 효과가 큽니다. 예시 루틴:

1. (아침, 10분) **E2 주간 회고** → 어제 올린 글 반응을 넣고 오늘 우선순위 확인
2. (10분) **B2 톤별 홍보 글** 또는 **A4 챕터 본문** 중 오늘 할 일에 맞는 프롬프트 실행
3. (10분) 나온 결과에 **"더 짧게", "예시 추가해서", "이 표현은 빼고"** 처럼 1~2번 다듬기 요청
4. 완성된 결과를 그대로 발행/저장

이 루틴을 30일 반복하는 상세 일정은 `checklist.md`를 참고하세요.
