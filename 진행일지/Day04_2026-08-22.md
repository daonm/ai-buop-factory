# Day 04 — 2026-08-22

## 목표
로드맵.md의 대기 항목 중 가장 위(Day 04) — "AI로 업무 자동화 스크립트 만들기 — 실전 소스코드 모음" (유형: 실습자료)을 제작한다. Day03 전자책(『야근 없는 사무실』)이 "개념·순서·프롬프트" 중심으로 남겨둔 "실제 동작하는 코드"를 이번 편에서 채우는 것이 핵심 목표. Day03 일지의 계획대로, 이번 실습자료는 Apps Script/Python 원본 파일을 실제로 제공하는 방향으로 진행.

## 진행 과정

### 1. 세션/저장소 상태 점검
- `git status` 확인 결과 이번에도 `HEAD detached` 상태로 세션 시작(Day02·Day03에서 반복 확인된 패턴). `git fetch origin main`으로 로컬 origin 참조가 오래된 캐시(7db94bb, Day01 시점)임을 확인 — 실제 origin/main은 0a7db37(Day03 두 번째 홍보글 기록)까지 진행돼 있었음.
- 로드맵.md를 "진행중"으로 갱신한 커밋(dd408dc)이 detached HEAD 위에 쌓인 상태에서, `git checkout -B main HEAD`로 로컬 `main` 브랜치를 현재 HEAD(= origin/main + 이번 커밋)에 맞춰 재생성. Day03 일지에서 남긴 메모("작업 시작 전 fetch로 로컬이 origin보다 뒤처졌는지 확인")를 그대로 따름 — `git merge --ff-only` 대신 이번엔 애초에 origin/main 위에서 시작했으므로 `checkout -B`로 간단히 정리됨.

### 2. Day02/Day03 산출물 및 디자인 시스템 검토
- `products/day02_ai-부수입-가이드-실행키트/resources/kit.html`을 실습자료 디자인의 정확한 참고 예시로 재사용 — CSS 색상 토큰(`--cat-a`~`--cat-e`), `.prompt-grid`(2단 그리드), `.worksheet`(골드 바+원형 배지), `.checklist-group`(알약형 배지) 클래스명 관례를 그대로 가져옴.
- `products/day03_ai-업무자동화-스크립트/ebook/manuscript.md`를 완독해 전자책이 다룬 12가지 방법의 구체적 내용(진단표/구글시트/이메일분류/노코드툴/데이터정리/견적서·인보이스/카톡·슬랙알림/고객응대/파일정리/스케줄링/SNS발행/부업화)을 파악 — 이 실습자료가 "코드가 실제로 필요한" 방법들과 자연스럽게 짝을 이루도록 스크립트 종류를 선정하는 기준으로 삼음.

### 3. 콘텐츠 설계 결정
- 전자책 12가지 방법 중 **실제로 재사용 가능한 독립 스크립트가 나올 수 있는 7가지**를 선별: ① 구글 시트 주간 보고서(방법2) ② Gmail 자동분류(방법3) ③ 엑셀/CSV 정리(방법5) ④ 견적서·인보이스 생성(방법6) ⑤ 슬랙 알림(방법7) ⑥ 파일정리(방법9) ⑦ GitHub Actions 스케줄링(방법10). 노코드 툴 연결(방법4)·고객응대(방법8)·SNS발행(방법11)·부업화(방법12)는 툴 UI 조작이나 카피 작성이 중심이라 "소스코드" 성격에 맞지 않는다고 판단해 이번 편에서는 제외.
- "실제로 동작하는 코드"라는 이 상품의 핵심 약속을 지키기 위해, **환경이 갖춰진 스크립트(Python 4종)는 이 세션에서 직접 실행해 검증**하기로 결정. Google Apps Script 2종은 실제 Google 계정 없이는 실행 불가하므로 문법 검사(`node --check`)와 API 사용법(SpreadsheetApp/GmailApp/MailApp 등) 재확인으로 대체.
- 카테고리를 4개(A 리포트·메일=구글워크스페이스, B 데이터·문서=파이썬, C 알림=파이썬, D 파일정리=파이썬(설치불필요), E 운영·스케줄링=GitHub Actions)로 나누고 kit.html의 cat-a~e 색상을 그대로 매핑. 스크립트 수가 7개로 Day02(60개 프롬프트)보다 적어 "10개 이상 나열 금지" 기준의 강한 적용 대상은 아니었지만, 시리즈 톤 통일을 위해 동일한 카테고리 카드+2단 그리드 패턴을 그대로 적용.
- 인보이스 생성 스크립트는 PDF 라이브러리(reportlab/fpdf) 의존을 피하기로 결정 — 이 클라우드 세션에서 `pip install fpdf2` 시도 중 `cryptography`/`cffi` 관련 환경 오류(`pyo3_runtime.PanicException`)가 발생해 안정적으로 검증할 수 없었음. 대신 표준 라이브러리만으로 스타일이 적용된 HTML 인보이스를 생성하고 "브라우저에서 인쇄(Ctrl+P) → PDF 저장"으로 안내하는 방식으로 설계 변경 — 의존성 0개로 어떤 구매자 환경에서도 실행 가능하다는 장점도 있어 더 나은 선택으로 판단.

### 4. 스크립트 작성 및 실행 검증
- **03 엑셀/CSV 정리(`clean_data.py`, pandas)**: `pip install pandas`(3.0.5) 후 `sample_before.csv`(중복행·빈값·공백 포함)로 실행 → 중복 1행 제거, 지점별 합계/평균 요약 시트 정상 생성 확인. 최초 버전에서 `select_dtypes(include="object")`가 pandas 3.x 마이그레이션 경고(`Pandas4Warning`)를 띄우는 것을 발견해, dtype을 직접 확인하는 방식으로 수정 후 경고 없이 재실행 확인.
- **06 파일정리(`organize_files.py`, 표준 라이브러리만)**: `mktemp -d`로 임시 폴더에 확장자가 다른 파일 5개를 만들어 `--preview` → 실제 실행 순서로 테스트, 이미지/문서/스프레드시트/압축파일/기타 5개 폴더로 정확히 분류되고 원본 삭제 없이 이동만 됨을 확인.
- **04 인보이스 생성(`generate_invoice.py`, 표준 라이브러리만)**: `sample_clients.csv`(고객 2명, 품목 3건)로 실행 → 고객별 HTML 인보이스 2개 생성, 합계 금액(800,000원/300,000원) 계산 정확함을 HTML 내용 직접 확인.
- **05 슬랙 알림(`slack_notify.py`, requests)**: 실제 Webhook 없이도 검증 가능하도록 `--dry-run` 모드를 설계 — 조건 미충족(500,000 < 1,000,000) 시 전송 안 함, 조건 충족 시 dry-run 메시지 정상 출력, webhook 미설정 시 명확한 에러로 종료하는 3가지 경로를 모두 실행 확인.
- **01 구글 시트 주간 리포트 / 02 Gmail 자동분류(Apps Script, `.gs`)**: `node --check`로 문법 검증(파일 확장자 문제로 임시로 `.js` 복사본을 만들어 검사) 통과. `SpreadsheetApp`/`MailApp`/`GmailApp`/`Utilities`/`Session` 등 실제 Apps Script 전역 API 이름과 시그니처를 재확인해 오타 없이 작성.
- **07 GitHub Actions 스케줄링(`scheduled_run.yml`)**: `python3 -c "import yaml; yaml.safe_load(...)"`로 YAML 문법 검증 통과 (`on:` 키가 PyYAML 1.1 규칙상 boolean `True`로 파싱되는 건 GitHub Actions yml의 잘 알려진 특성이며 실제 GitHub 파서는 정상 인식하므로 문제 아님).

### 5. kit.html 제작 및 PDF/썸네일 검증
- Day02 kit.html 구조를 그대로 복사해 표지(VOL.04 배지), 스크립트 7종 카드(카테고리 색상별 `.prompt-grid`), 환경별 설치 체크리스트(`.worksheet` 3개: Python/Google Apps Script/GitHub), 4주 정착 체크리스트(`.checklist-group` 4개), 공통 트러블슈팅 표(`.worksheet` 1개)로 구성. 지침대로 카드/섹션 padding을 Day02 원본 수치(`.worksheet` 18px 20px 14px, `section.chapter` 30px 0 34px 등) 그대로 유지해 처음부터 PDF 빈공간 위험을 줄임.

- `scripts/screenshot_pdf_pages_cloud.js`로 7페이지 전부 스크린샷 후 육안 확인 — 카드/섹션 중간에 30% 이상 빈 공간이 남는 페이지 없음을 확인(에필로그가 있는 마지막 페이지는 책 관례상 여백 정상). Day03에서 발견했던 `break-after:avoid-page` 버그는 이번 kit.html에 해당 규칙 자체가 없어 재발하지 않음(사전에 Day03 일지 교훈을 참고해 `@media print` 블록을 미리 grep해 확인함).

- 같은 673px 캡처를 1000×1000 뷰포트로 다시 캡처해 `marketing/thumbnail.png`로 저장 — 별도 AI 이미지 생성 없이 표지 그대로 사용(Day01~03과 동일 원칙 준수). 실제 렌더링 결과 1600×1262px로 저장됐는데, Day02(1600×1064)·Day03(1560×1272) 썸네일도 정확히 1000×1000이 아닌 것으로 확인해 기존 관례와 일치한다고 판단.

## 이슈/트러블슈팅
- **`HEAD detached` 상태로 세션 시작 (3회 연속 재발)**: Day02·Day03과 동일 패턴. 이번엔 로컬 origin 참조 캐시만 오래됐을 뿐 실제 origin/main과 로컬 커밋 히스토리에는 괴리가 없어서(로드맵.md "진행중" 커밋 하나만 detached 위에 얹혀 있었음) `git checkout -B main HEAD`로 간단히 정리. 데이터 유실 없었음.
- **`fpdf2` 설치 시 `cryptography`/`cffi` 환경 오류**: 인보이스 생성 스크립트에 PDF 라이브러리를 쓰려 했으나 `pip install fpdf2` 후 import 시 `pyo3_runtime.PanicException`(Rust 백엔드 충돌) 발생 — 이 클라우드 세션 특유의 환경 문제로 추정(별도 조사 없이 우회). `pypdf`로 PDF 페이지 수를 확인하려 할 때도 동일한 `cryptography` 계열 오류가 재현되어, PDF 페이지 수 확인은 `pdfinfo`/`pypdf` 대신 `scripts/screenshot_pdf_pages_cloud.js`(Chrome 내장 뷰어)의 페이지네이션 UI("N / 전체")를 육안으로 읽는 방식으로 대체.
- **이 문제를 계기로 인보이스 스크립트 설계를 표준 라이브러리 전용으로 변경**: 처음엔 PDF를 직접 생성하려 했으나, 위 환경 문제를 만난 뒤 "의존성 없는 HTML 인보이스 + 브라우저 인쇄 안내" 방식이 더 안정적이고 구매자 환경에도 더 안전하다고 판단해 설계를 변경함. 결과적으로 03/05만 pip 설치가 필요하고 04/06은 설치 없이 바로 실행 가능 — 이 차이를 `kit.html`의 "환경별 설치 체크리스트" 섹션에 명시함.
- **pandas 3.x의 `select_dtypes(include="object")` deprecation 경고**: 이 세션의 pip 환경에 pandas 3.0.5(매우 최신 버전)가 설치되어 있어 발생. 실제 구매자 대부분은 pandas 2.x를 쓸 가능성이 높지만, 두 버전 모두에서 경고 없이 동작하도록 dtype 확인 방식을 명시적으로 고쳐 하위 호환성을 확보함.
