## 진행 과정

### 1. 저장소 상태 점검 및 git 정리
- 세션 시작 시 `git status`가 "HEAD detached from refs/heads/main" 상태였음. `git log`로 확인해보니 origin/main과 동일한 커밋(`4fbe612`)에서 detached된 상태였고, 로컬 `main` 브랜치 포인터는 그보다 9커밋 뒤(`c71fc17`, Day08 시점)에 머물러 있었음.
- `git checkout -B main`으로 현재 HEAD 위치(최신 커밋)에 `main` 브랜치를 재생성하고 `origin/main`으로 업스트림 연결. `git push`로 확인해보니 로컬과 원격이 이미 동일해서 "Everything up-to-date" — 즉 문제는 로컬 브랜치 포인터가 낡아있던 것뿐, 실제 데이터 손실은 없었음. `git fetch`로 재확인 완료.

### 3. 노션 템플릿 5종 실제 제작
"템플릿 주제 → 실제 템플릿 파일" 원칙에 따라, 각 니치마다 노션에 바로 가져올 수 있는 **CSV 임포트 파일**(실제 동작하는 예시 데이터 포함)과 **README.md**(속성 타입 재설정표, 노션 수식 문법 그대로의 수식 레시피, 뷰 구성, 페이지 구조, 커스터마이징 프롬프트)를 제작:

1. `01_교대근무_스케줄관리` — 근무유형(주간/야간/오프/휴가)·컨디션·수면계획 열을 가진 스케줄 CSV. 수식 2개(야간경고 뱃지, 컨디션 상태 이모지).
2. `02_대학원생_논문자료정리` — 실제 유명 논문(Attention Is All You Need, ResNet, BERT 등) 5건을 예시 데이터로 채운 논문 트래커 CSV. 수식 2개(우선순위 점수, 서지 인용 텍스트 자동 생성).
3. `03_ADHD_저마찰_습관관리` — "최소단위" 속성을 핵심으로 목표를 의도적으로 잘게 쪼갠 습관 CSV. 수식 2개(연속기록 상태 뱃지, 오늘 대상 필터용). 홈 화면에 통계를 넣지 않는다는 설계 원칙을 README에 명시.
4. `04_1인_디지털상품_판매파이프라인` — **이 프로젝트 자체의 실제 상품 라인업**(Day01~09)을 예시 데이터로 사용 — 메타적으로 가장 설득력 있는 예시라고 판단해 실제 로드맵.md 데이터를 CSV에 반영. 수식 3개(평균단가 검증, 경과일, 조치 필요 뱃지).
5. `05_소상공인_예약재고_통합관리` — 유일하게 데이터베이스 2개(예약목록+재고목록)로 구성, 관계형(Relation) 연결 방법을 README에 별도 설명. 수식 2개(재고 부족 경고, 재고가치 계산).

이 프로젝트 환경에는 노션 API/브라우저 자동화가 없어 실제 노션 워크스페이스를 만들 수는 없으므로, "CSV 가져오기(Import)"가 노션에서 실제로 지원하는 가장 실물에 가까운 배포 형태라고 판단해 이 방식을 택함 (CSV 임포트 시 모든 열이 텍스트로 들어오는 노션의 특성을 README의 "속성 타입 재설정" 표로 보완).

### 5. PDF 렌더링 및 검증
- `NODE_PATH=/opt/node22/lib/node_modules node scripts/render_pdf_cloud.js`로 `노션_템플릿_5종_실전키트.pdf` 생성 (총 11페이지, A4, 여백 18mm/16mm).
- **표지 실제 인쇄 폭 검증**: `screenshot_element_cloud.js`로 뷰포트 673×950에서 `.cover` 요소를 캡처해 육안 확인. "5종", "12개 수식", "19개 프롬프트" 등 숫자+단위 조합이 모두 `<span class="nowrap">`으로 감싸져 있어 좁은 폭에서도 어색하게 끊기지 않음을 확인.
- **페이지 여백(빈 공간) 검증**: poppler(pdftoppm)와 pymupdf가 이 환경에 없어서, 먼저 `screenshot_pdf_pages_cloud.js`로 전체 11페이지를 스크린샷한 뒤 육안으로 훑어봄 — 한 페이지(3번째 스크린샷)에서 워크시트 카드 하나가 끝난 뒤 페이지 하단에 상당한 여백이 있는 것처럼 보여 문제로 의심함.
  - 육안 판단만으로는 정확한 비율을 알기 어려워, `pip install pillow`로 Pillow를 설치하고 각 스크린샷의 세로 픽셀 컬러를 분석하는 스크립트를 즉석에서 작성. 먼저 PDF 뷰어의 흰색 여백(마진)·어두운 페이지 구분선·본문(paper 배경색 포함) 밴드를 색상 임계값으로 구분해 각 논리적 페이지의 시작/끝 좌표를 특정.
  - 그다음 각 페이지 밴드 내에서 "본문 배경색(#EEF0E8)과 다른 픽셀이 마지막으로 나타나는 행"을 찾아 실제 콘텐츠가 페이지 하단 여백 시작점(마진)까지 거의 맞닿아 있는지 정량 측정. 측정 결과 모든 페이지에서 콘텐츠가 하단 여백 직전(6~7px 이내)까지 채워져 있음을 확인 — 처음의 육안 판단은 스크린샷 도구가 한 화면에 두 페이지를 걸쳐서 보여주는 방식(뷰포트 1250px, 실제 페이지 높이 약 675px) 때문에 생긴 착시였고, 실제로는 페이지 하단 여백 문제가 없었음.
  - 표지(1페이지)만 도서 표지 관례상 자연스러운 여백을 갖고, 나머지 본문 페이지는 30% 기준을 크게 밑돔.

## 이슈/트러블슈팅
1. **HEAD detached 상태** — 세션 시작 시 로컬 저장소가 detached HEAD였고 `main` 브랜치 포인터가 9커밋 뒤처져 있었음. `git checkout -B main` + `git branch -u origin/main main`으로 정리. 실제 데이터 손실은 없었음(원격과 이미 동기화된 상태에서 detached된 것뿐).
2. **PDF 페이지 여백 육안 오판** — `screenshot_pdf_pages_cloud.js`가 한 스크린샷에 두 페이지를 걸쳐 보여주는 특성 때문에 실제로는 문제없는 페이지를 "하단 여백 과다"로 오판할 뻔함. `pip install pillow`로 정량 분석 스크립트를 즉석 작성해 페이지 경계(흰색 마진 밴드)를 픽셀 컬러로 정확히 특정하고, 각 페이지 콘텐츠가 하단 여백 직전까지 채워져 있음을 수치로 확인한 뒤 문제 없음으로 최종 판단. 이 환경엔 poppler(pdftoppm)도 pymupdf도 기본 설치돼 있지 않아 Pillow를 즉석 설치해 우회함 — 다음에도 정밀한 PDF 페이지 여백 검증이 필요하면 동일한 방식(Playwright로 페이지별 스크린샷 → Pillow로 배경색 대비 마지막 콘텐츠 행 탐지)을 재사용할 수 있음.
3. **CSV 가져오기의 한계** — 노션 CSV 임포트는 모든 열을 텍스트로 만들고(선택/숫자/날짜/체크박스/관계형 타입이 살지 않음), 다중선택 값도 자동 분리되지 않는 등 제약이 있음. 각 README에 "속성 타입 재설정" 표를 필수 섹션으로 넣어 구매자가 헷갈리지 않도록 보완.
