### 4. 계산기 4종 설계

전자책 방법 5·6·7·9를 각각 독립된 엑셀 파일로 구현하기로 결정(Day24가 4개 파일로 나눈 방식과 동일):
- **A. 상품_마진_계산기.xlsx** — 방법3의 7단계 구조를 그대로 수식화. 판매가·원가·플랫폼수수료율·결제수수료율·배송비·반품률·광고비배분액을 입력하면 개당 순마진·마진율 자동 계산. 방법4의 플랫폼별(스마트스토어/쿠팡/자사몰) 수수료 참고표를 별도 시트로 포함.
- **B. 손익분기점_BEP_계산기.xlsx** — "고정비 ÷ 개당 순마진" 수식(방법6)에 목표 판매 기간을 더해 일 평균 필요 판매량까지 계산. 방법6 4단계에서 언급한 "시나리오 3개"를 판매가 인상/원가 절감/광고비 절감 비교표로 구현.
- **C. 광고비반영_실질마진_계산기.xlsx** — 방법7의 CPA(건당 광고비) 계산 → 광고 포함 실질 마진 분리. "손해/주의/양호" 자동 판정 셀 추가.
- **D. 다상품_마진비교_계산기.xlsx** — 방법9의 "매출 순위 vs 마진율 순위 비교"를 RANK 함수로 구현, 순위 격차가 큰 상품을 IF 수식으로 자동 판정("매출은 높지만 마진 낮음" 등). 최대 10개 상품 행 지원.

Python(openpyxl)으로 4개 파일을 생성하는 일회성 빌드 스크립트를 세션 스크래치패드에 작성해 실행(저장소에는 커밋하지 않음 — Day24도 생성 스크립트를 커밋하지 않은 선례를 따름).

### 5. 계산기 값 검증 — LibreOffice 자동 재계산 실패, 수식 손계산으로 대체 검증

`soffice --headless --convert-to`로 xlsx 수식을 자동 재계산·검증하려 했으나, 최소 예제 파일(`A1=1, A2=2, A3=A1+A2`)조차 "source file could not be loaded" 에러로 변환에 실패 — 이 클라우드 세션의 LibreOffice 설치 자체가 깨져있는 것으로 판단(HOME 디렉터리 변경, dangerouslyDisableSandbox 등 여러 방법 시도했으나 동일하게 실패). 대신 4개 계산기의 모든 수식을 손으로 재계산해 교차검증:
- A 계산기: 판매가 30,000원·원가 12,000원·수수료 3.5%+2.8%·배송비 3,000원·반품률 3% → 개당 순마진 12,660원(마진율 42.2%) 확인.
- B 계산기: 고정비 500,000원 ÷ 순마진 12,660원 → BEP 40개, 일평균 1.4개(30일 기준) 확인. 시나리오 1~3(순마진 +2,000/+1,500/+1,000원)의 BEP 감소량(5개/4개/3개)도 방향성이 올바름을 확인.
- C 계산기: CPA 300,000÷40=7,500원, 실질마진 12,660-7,500=5,160원, 광고의존율 40/65=61.5% 확인.
- D 계산기: 샘플 데이터(상품A~E)로 RANK/판정 수식 결과가 "매출 1위 상품이 마진 꼴찌"(상품C) 시나리오를 정확히 짚어내는지 확인.

이 과정에서 D 계산기 "합계" 행의 마진율 계산식이 합계 행 자신이 아니라 한 행 위(빈 행)를 참조하는 off-by-one 버그를 발견해 수정(`C{start+n_rows}` → `C{start+n_rows+1}`).

### 6. kit.html 제작 — Day24 패턴 그대로 재사용

Day24 kit.html의 CSS(색상 토큰, `.worksheet`/`.domain-block`/`.checklist-group`/`.cat`~`.cat-d` 클래스, padding 값 18px대·margin 12px대 등 PDF 여백 문제를 이미 겪고 조정된 수치)를 그대로 복사해 Day34 콘텐츠로 교체. 계산기 A~D를 cat-a(gold)~cat-d(olive) 4색으로 구분한 도메인 블록에 입력·결과 예시를 담고, Worksheet 1(패키지·가격)·Worksheet 2(교차검증)·4단계 체크리스트(검증→다듬기→등록→갱신관리)를 Day24와 동일한 구조로 작성.

### 7. PDF 렌더링 및 페이지 여백 검증

`scripts/render_pdf_cloud.js`로 렌더링 → 5페이지 생성(Day24와 동일하게 컴팩트). PDF를 PyMuPDF(pip로 설치, `pdftoppm` 바이너리가 이 환경에 없어 대체)로 페이지별 PNG 래스터화 후 `scan_page_margins.py`로 정량 스캔 — 표지(1p, 40.8%)만 30% 기준 초과(의도된 정상), 본문(2~5p)은 8.9%~23.9%로 전부 정상 범위. Read 툴로 5페이지 전부 육안 확인 — 도메인 블록 4색, worksheet 카드, 원형 배지 체크리스트가 페이지 경계에서 자연스럽게 이어지는 것을 확인.

### 8. 표지 인쇄 폭(673px) 검증 — 실제 어색한 줄바꿈 발견 및 수정

`scripts/screenshot_element_cloud.js`로 `.cover`를 673×950으로 캡처했을 때는 부제가 자연스럽게 2줄로 보였으나, **실제 PDF(150dpi 래스터화 후 육안 확인)에서는 3줄로 줄바꿈되면서 "광고비 반영"이 "광고비 반" / "영 실질마진…"으로, "이미"가 "이" / "미"로 단어 중간에서 갈라지는 문제를 발견**(673px 브라우저 스크린샷 테스트와 실제 PDF 인쇄 결과가 서로 다른 줄바꿈을 보인 원인은 특정하지 못함 — 다음 세션에서 재현되면 원인 조사 필요). Day33 ebook.html 표지가 부제 전체를 여러 개의 짧은 `<span class="nowrap">` 구문으로 잘게 감싸 이 문제를 피해간 패턴을 그대로 적용 — "마진 계산기"/"손익분기점(BEP) 계산기"/"광고비 반영"/"실질마진 계산기"/"다상품 비교"/"계산기"/"수식이 이미"/"짜인 엑셀 4종"/"숫자만 넣으면"/"결과가 나옵니다" 10개 구문 단위로 nowrap 처리 후 재렌더링 → 줄바꿈이 항상 구문 경계에서만 일어나는 것을 재확인(2줄, 단어 중간 절단 없음).

수정된 kit.html로 PDF를 다시 렌더링(5페이지, 표지 제외 페이지들은 diff 없음 — 픽셀 단위로 동일함을 `ImageChops.difference`로 확인)하고 `감_대신_계산기로_파세요.pdf`로 저장. `screenshot_element_cloud.js`로 `.cover`를 1000×1000, deviceScaleFactor 2로 캡처해 `marketing/thumbnail.png` 생성 — 별도 이미지 생성 도구 없이 표지와 완전히 동일한 에디토리얼 스타일 유지.

## 이슈/트러블슈팅

- **저장소가 detached HEAD 상태로 시작**: Day29~33과 동일한 패턴 재현. `git fetch` + `git checkout -B main origin/main`으로 복구. 다만 이번엔 실제로는 `origin/main`이 이미 최신이었고 로컬 참조만 뒤처져 있었음 — push 실패가 아니라 로컬 브랜치 갱신 누락이었던 것으로 추정. 다음 세션에서도 계속 기본 점검 항목으로 유지할 것.
- **LibreOffice(soffice) headless 변환이 이 클라우드 세션에서 완전히 깨져있음**: 최소 예제 파일조차 "source file could not be loaded"로 실패. xlsx 수식 자동 재계산 검증 경로가 막혀, 대신 모든 수식을 손으로 재계산해 교차검증하는 방식으로 대체함. **다음에 엑셀 계산기를 만들 때도 같은 문제가 재현될 가능성이 높으니, 수식 검증은 처음부터 손계산 방식으로 계획할 것.** (원인 조사는 이번 세션에서는 생략 — 본 작업에 필수적이지 않아 시간을 더 쓰지 않기로 판단.)
- **673px 브라우저 스크린샷과 실제 PDF 인쇄 렌더링의 줄바꿈이 서로 다르게 나타남**: 동일한 CSS 폭(673px 상당)임에도 브라우저 스크린샷 테스트에서는 자연스러웠던 표지 부제가 실제 PDF에서는 단어 중간이 갈라지는 문제가 발생. 원인은 특정하지 못했으나(print 미디어 레이아웃과 screen 미디어 레이아웃의 폰트 메트릭 차이로 추정), Day33 ebook.html의 "부제 전체를 짧은 nowrap 구문으로 잘게 나누기" 패턴을 적용해 해결. **이후 세션에서는 673px 브라우저 스크린샷만으로 표지 문구를 확정하지 말고, 반드시 실제 PDF 래스터화 이미지까지 육안 확인할 것** (이번 세션에서 실제로 이 단계 덕분에 문제를 잡아냄).
- D 계산기(다상품 마진비교)의 합계 행 마진율 수식에서 참조 행이 한 칸 어긋나는 버그를 스스로 발견해 수정함(생성 스크립트 단계에서 수정 후 재생성, 최종 파일에는 반영됨).
