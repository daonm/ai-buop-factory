## 목표

### 2. 리서치(WebSearch) — 2026년 키워드 리서치·검색의도 분류 실무
- "2026년 블로그 키워드 리서치 롱테일 저경쟁 애드센스 방법" 검색 → 롱테일 키워드가 검색량은 적지만 의도가 분명해 경쟁이 낮다는 점, 2026년 전략은 자연어·구체적 질문형 키워드에 집중해야 한다는 점, 네이버 키워드도구·구글 키워드플래너·검색창 자동완성이 여전히 기본 발굴 도구라는 점 확인.
- "AI 키워드 리서치 검색의도 분류 방법 블로그 SEO 2026" 검색 → 검색의도 4분류(정보형/상업조사형/거래형/탐색형) 체계와 키워드 리서치 5단계 실무 프로세스(시드 도출→검색량·경쟁도 확인→검색의도 분류→연관키워드 확장·클러스터링→의도별 콘텐츠 매핑) 확인. 이 4분류·5단계 구조를 그대로 채택해 프롬프트팩 C그룹(C1 검색의도 분류)과 kit.html "리서치 5단계 빠른 참고표"(섹션 01)의 뼈대로 사용.
- **판단**: Day27과 마찬가지로 "2026년 몇 월부터 정확히 이렇게 바뀌었다"는 단일 공식 발표는 확보하지 못함(운영자 경험담·SEO 대행사 블로그 기반 정보가 대부분). 특정 수치·날짜를 단정하지 않고 "롱테일·검색의도 분류·클러스터링"이라는 공통 방향성만 워크시트·프롬프트 설계에 반영.

### 3. 콘텐츠 설계 — 프롬프트 20개 신규 구성
- Day27 프롬프트 16개(A1~D4)와 겹치지 않도록 **완전히 새로운 5그룹 20개**를 설계: A(니치 세분화·클러스터링) · B(롱테일 키워드 발굴·확장) · C(검색의도·콘텐츠 갭 분석) · D(캘린더 설계·클러스터링) · E(발행 후 리라이트·업데이트·확장). Day27이 "니치를 어떻게 좁힐까/어떻게 쓸까"를 다뤘다면, Day28은 "그 니치 안에서 어떤 키워드를 몇 번째로 쓸까"를 다루도록 역할을 명확히 분리.
- E그룹(발행 후 리라이트·카니발라이제이션 점검·인접 니치 확장)은 Day27에 전혀 없던 새 축으로, "발행을 시작한 지 1~2개월 지난 뒤 매달 정기적으로 돌리는 용도"임을 프롬프트팩 사용 팁에 명시.
- 니치별 서브카테고리를 나누고 시드 키워드를 배정한 뒤(A) 롱테일로 확장하고(B) 검색의도를 분류·경쟁 분석하고(C) 30일 캘린더로 배치하고(D) 발행 후 데이터로 다음 사이클을 준비하는(E) 흐름이 곧 kit.html 섹션 01의 "리서치 5단계"가 되도록 설계.

### 4. 키워드 스코어링 방법론 설계 (신규)
- Day26에는 없던 새로운 도구로 **키워드 우선순위 점수표**를 설계. 채점 기준: 체감 검색량(상=3/중=2/하=1) + 경쟁 강도(낮음=3/보통=2/높음=1, 경쟁이 낮을수록 고득점) + 니치 적합도(직접 평가 1~5점) + 상업성 보너스(거래형+2/상업조사형+1/정보형+0). 합산 최대 13점, **9점 이상 우선 채택·5점 이하 탈락**을 기준선으로 제시해 "감이 아니라 숫자로 결정"하는 실전 도구로 구체화.
- 이 점수표는 `니치_키워드_스코어링_워크시트.md`(전체 버전)와 `kit.html` 섹션 03(채점 기준 + 미리보기)에 동일하게 배치.

### 7. PDF 렌더링 및 페이지 여백 검증
- 이 세션에도 `pdftoppm`(poppler-utils)이 설치돼 있지 않아 `apt-get update` 먼저 실행 후 `apt-get install -y poppler-utils` 진행 — Day26/27 로그의 교훈대로 update를 먼저 실행하니 PPA 저장소(`deadsnakes`, `ondrej/php`) 403 경고만 뜨고 poppler 자체는 정상 설치됨(경고는 무관한 별개 저장소 이슈).
- `scripts/render_pdf_cloud.js`로 렌더링 → **8페이지** 생성.
- `scan_page_margins.py` 실행 시 `ModuleNotFoundError: No module named 'PIL'` 발생 → `pip install pillow numpy`로 해결 후 재실행.
- 절대 임계값 기반 스캔 결과: 1페이지(표지) 46.1%, 8페이지(에필로그+체크리스트 하단) 34.2%가 30% 기준을 초과, 나머지 6페이지(2~7p)는 12.5%~18.9%로 정상 범위.
- **Read 툴로 8페이지 전부 육안 확인**: 1페이지(표지)는 Day27과 마찬가지로 표지 특성상 여백이 큰 것이 의도된 디자인(하단 룰라인 아래는 원래 비워두는 레이아웃). 8페이지는 3~5단계 체크리스트와 에필로그가 상단에 채워지고 문서 마지막 페이지라 하단이 비는 것으로, Day27 진행일지의 표지(42.8%)·에필로그(51.2%) 페이지와 동일한 유형이라 정상으로 판단. 2~7페이지는 domain-block, prompt-grid(2단), worksheet 카드, 체크리스트 카드 모두 페이지 경계에서 라벨-콘텐츠 분리나 카드 잘림 없이 자연스럽게 이어지는 것을 확인 — 별도 CSS 수정 불필요.

## 이슈/트러블슈팅
- **`scan_page_margins.py`에 PIL/numpy 미설치** — Day27에서 이 스크립트를 신규 작성해 정식 커밋해뒀지만, 이 세션 컨테이너에는 의존 패키지(`pillow`, `numpy`)가 설치돼 있지 않았음. `pip install pillow numpy`로 즉시 해결. 앞으로도 새 세션(컨테이너)마다 이 설치가 필요할 수 있으므로, 스캔 스크립트 실행 전 `ModuleNotFoundError` 발생 시 당황하지 말고 pip 설치부터 할 것.
- poppler-utils 설치는 `apt-get update`를 먼저 실행해 1차 시도로 성공 — Day26/27 로그의 "update 먼저 실행" 교훈이 이번에도 유효함을 재확인.
- PDF 여백·표지 폭 검증 모두 문제 없이 통과해 별도 CSS 수정은 발생하지 않음. Day26 kit.html의 CSS를 그대로 재사용한 것이 안전하게 작동함을 다시 확인 — 이 디자인 시스템(특히 `.cat-label{display:table}`, `section.chapter`에 `break-inside:avoid-page` 미적용, 개별 카드 단위 `break-inside:avoid`)은 계속 이대로 재사용해도 될 것으로 보임.
