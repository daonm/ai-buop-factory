### 3. 엑셀 계산기·체크리스트 제작 및 수식 설계
- `pip install openpyxl python-docx`로 로컬에 없던 패키지 설치. `/tmp/.../scratchpad/make_xlsx.py`(A), `make_xlsx_b.py`(B·C), `make_xlsx_d.py`(D), `make_docx.py`(E) 4개 스크립트로 분리 작성(스타일 헬퍼 함수는 파일마다 복제).
- **A. 연봉실수령액_계산기.xlsx** — 2026년 4대보험 요율(국민연금 4.75%·건강보험 3.595%·장기요양 13.14%·고용보험 0.9%) 참고표 + 비과세 한도(식대 30만·자가운전 20만·출산보육 20만) 참고표를 먼저 넣고, 연봉·부양가족 수·비과세 적용 여부 입력 시 4대보험 공제와 **연간 추정 소득세**(근로소득공제 구간별 계산 → 인적공제·표준공제 반영 과세표준 → 소득세 구간별 산출세액 → 총급여 기준 한도가 적용된 근로소득세액공제 → 결정세액)까지 자동 계산하도록 설계. 전자책 본문이 언급한 "국세청 근로소득 간이세액표"는 매달 원천징수용 조견표라 작은 엑셀 파일에 그대로 넣기 어려워, 실제 다수의 연봉계산기가 쓰는 **연말정산 방식 연간 추정 계산**으로 대체하고 안내 시트·결과 셀 옆에 "간이세액표상의 월별 원천징수와는 다를 수 있음"이라는 설명을 명시해 과대 정확도를 주장하지 않도록 함.
- **B. 오퍼비교_계산기.xlsx** — A사·B사 오퍼(기본급·고정성과급·변동성과급 최소/기대·사이닝보너스·복지포인트)를 입력하면 확정 실수령액(A와 동일한 4대보험·소득세 로직 재사용, 단 세액공제는 총급여 기준 한도 계산을 66만원 고정으로 간이화)부터 1년차·2년차 총합까지 비교하고 우위를 자동 판정. 예시값은 A사(기본급 5,000만+고정 500만=5,500만 확정)와 B사(기본급 5,200만+고정 100만=5,300만 확정, 대신 변동성과급 기대 700만+사이닝 300만)로 설계해 "확정 기준은 A사 우위, 변동 요소까지 반영하면 B사가 역전"하는 시나리오가 재현되도록 직접 숫자를 조정 — 세전 연봉만 보고 판단하면 안 된다는 책의 메시지를 예시만으로도 체감할 수 있게 함.
- **C. 퇴직금_연차수당_이직손익_계산기.xlsx** — 입사일·퇴사일·최근 3개월 평균급여·미사용 연차 입력 시 근속연수→예상 퇴직금(1일 평균임금×30×근속연수)→연차수당→정산 합계, 새 회사 입사일 입력 시 공백기 일수와 4대보험 공백 여부, 끝으로 현재 회사 유지 vs 이직의 단기(올해)·중기(1~2년) 손익 비교까지 체인으로 연결.
- **D. 처우협의서_검토_체크리스트.xlsx** — 숫자 조건(4)·지급 조건(4)·제도 조건(5) 총 13개 항목을 O 표시 + `COUNTIF/COUNTA` 완료율 자동 집계로 구성.
- **E. 희망연봉_협상멘트_템플릿.docx** — 희망연봉 산정 워크시트(표 채우기형) + 협상 이메일(격식체) + 협상 멘트(구어체) + 대안 제안 멘트 3종 + 의뢰 접수 질문지(9문항)를 하나의 문서로 구성, 전자책 방법 5~6·9의 프롬프트 결과물을 그대로 따라가는 흐름으로 설계.

### 4. 수식 검증 — soffice 재확인 실패, Python 재구현으로 대체 검증
- Day42·44 진행일지에 기록된 대로 이번에도 `soffice --headless --convert-to`가 "source file could not be loaded" 오류로 실패(한글 파일명·영문 파일명·새 프로필 디렉토리 모두 시도했지만 동일). 클라우드 세션 환경 제약이 계속되는 것으로 확인.
- 대신 이번에는 **모든 계산기 수식을 Python으로 동일하게 재구현해 openpyxl이 생성한 수치 예시와 대조**하는 방식으로 검증 강도를 높임(Day44는 손 계산 대조였다면, 이번은 스크립트 대조). 이 과정에서 실제 버그 2건을 발견해 수정함:
  1. **순환참조 버그** — `오퍼비교_계산기.xlsx`의 "확정 연 실수령액" 셀(B27)이 `=B26*12`여야 하는데 반복문 로직 실수로 `=B27*12`(자기 자신 참조)로 생성되고 있었음. Python 재구현 중 결과값이 맞지 않아 발견, 셀 좌표를 재출력해 확인 후 수정.
  2. **날짜가 텍스트로 저장되는 버그** — `퇴직금_연차수당_이직손익_계산기.xlsx`의 입사일·퇴사일·새 입사일 입력 셀을 파이썬 문자열(`"2022-03-01"`)로 채워 넣어, 엑셀에서 날짜 연산(`B5-B4`)이 `#VALUE!` 오류를 낼 뻔했음. `datetime.date` 객체 + `number_format="yyyy-mm-dd"`로 교체해 해결.
  - 이 두 버그는 셀 좌표를 눈으로 훑는 것만으로는 잡기 어려웠고, Python으로 동일 로직을 재구현해 수치를 대조하는 과정에서만 드러났음 — **다음에도 openpyxl로 다단계 수식 체인을 만들 때는 반드시 별도 Python 함수로 같은 계산을 재구현해 예시값을 대조할 것**(soffice 재계산이 막혀 있는 한 사실상 유일한 신뢰 가능한 검증 수단).

### 6. PDF 렌더링 및 페이지 여백 검증 — 33.5% 빈 공간 발견 및 수정
- `scripts/render_pdf_cloud.js`로 1차 렌더링 → 6페이지. `pdftoppm -r 100`으로 페이지별 PNG 변환 후, 이번엔 `scan_page_margins.py` 대신 Python(Pillow)으로 **배경색(흰색/페이퍼색 EEF0E8)과 다른 픽셀이 나타나는 마지막 행**을 페이지별로 스캔하는 스크립트를 즉석에서 작성해 빈 공간 비율을 정량화.
- 4페이지(Worksheet 1 뒤)에서 **33.5%** 빈 공간 발견 — 임계값(30%) 초과. 원인 파악: (1) 섹션 01에 E 블록이 누락되어 섹션이 실제보다 짧게 끝났고, (2) Worksheet 2(교차검증표)가 페이지 4에 들어갈 공간(약 321px)이 Worksheet 2의 실제 높이(약 320px)보다 근소하게 부족해 통째로 페이지 5로 밀려남.
- 먼저 누락된 **E. 희망연봉·협상멘트 템플릿** cat-e 블록을 섹션 01에 추가(6→7페이지로 증가, 섹션이 한 페이지에 다 들어가며 자연스럽게 채워짐). 이어서 여전히 페이지 4가 35.4%로 측정되어, `th,td` padding(6px→5px), `.worksheet` padding/margin(15px 17px 12px→13px 16px 10px, margin 12px→10px), `h2.chapter` margin/padding(14px→10px, 14px→12px), `.lede` margin(14px→10px), `.worksheet-note` padding(8px 12px→6px 10px), `.worksheet h3` margin(4px 0 8px→2px 0 6px)을 소폭씩 줄여 Worksheet 2가 페이지 4에 들어가도록 조정. 재렌더링 후 페이지 4 빈 공간이 **7.3%**로 해소됨을 확인.
- 전체 7페이지를 Python 스캔 + Read 도구 육안 확인을 병행해 재검토: 1페이지(표지, 36.2%)와 7페이지(에필로그, 50.9%)는 표지·책 마무리 페이지 특성상 정상으로 판단(책 마지막 페이지가 짧게 끝나는 것은 일반적인 인쇄 관례), 2~6페이지는 7.0~22.5%로 모두 기준 이내. 각 페이지를 Read로 재확인해 카드가 중간에 밀려 생기는 비정상적 공백이 없음을 확인.

## 이슈/트러블슈팅
- **`soffice`(LibreOffice) headless 변환이 이번에도 이 클라우드 환경에서 동작하지 않음.** Day42·44와 동일하게 "source file could not be loaded" 오류. 대신 이번엔 모든 계산기 수식을 Python 함수로 재구현해 수치를 대조하는 방식으로 검증을 강화했고, 그 과정에서 순환참조 1건·날짜-텍스트 저장 1건의 실제 버그를 잡아냈음(아래 참고). **openpyxl로 다단계 수식 체인을 짤 때는 셀 좌표를 눈으로 훑는 것에 의존하지 말고, 반드시 같은 로직을 Python으로 재구현해 예시 입력값의 결과를 수치로 대조할 것.**
- **순환참조 버그**: `오퍼비교_계산기.xlsx` B27/C27 셀("확정 연 실수령액")이 자기 자신을 참조하는 `=B27*12`로 잘못 생성됨(딕셔너리 키-행번호 매핑 스크립트 작성 중 오프바이원 실수). Python 재구현 결과와 비교하다 발견, `=B26*12`로 수정.
- **날짜 텍스트 저장 버그**: `퇴직금_연차수당_이직손익_계산기.xlsx`의 입사일·퇴사일 입력 셀에 Python 문자열을 그대로 넣어, 엑셀에서 날짜 뺄셈 수식이 깨질 뻔함. `datetime.date` 객체로 교체해 해결 — **앞으로 엑셀 날짜 입력 셀은 처음부터 문자열이 아니라 `datetime.date`/`datetime.datetime` 객체 + `number_format`으로 작성할 것.**
- **kit.html 섹션 01에 E(희망연봉·협상멘트 템플릿) 블록 누락** — 5종 중 1종을 빠뜨린 채 1차 PDF를 렌더링함. 페이지 여백 정량 스캔 단계에서 발견해 보강. **콘텐츠 블록을 카테고리 수(cat-a~e)만큼 다 채웠는지, 작성 직후 `grep -c "cat cat-"` 등으로 개수를 세어 교차 확인하는 습관이 필요함.**
- **PDF 페이지 4에 33.5~35.4% 빈 공간 발생** — Worksheet 2가 남은 공간(약 321px)에 근소하게 들어가지 못하고 통째로 다음 페이지로 밀려난 사례. 카드·섹션 padding/margin을 Day44 기준보다 한 단계 더 줄여(`.worksheet` 15/12→13/10, `th,td` 6→5, `h2.chapter`/`.lede`/`.worksheet-note`/`worksheet h3` margin 각각 소폭 축소) 해결. 이번처럼 특정 페이지에서만 여백이 큰 경우, 전체 문서의 여백을 다 줄이기보다 해당 페이지 직전 요소들의 margin/padding을 몇 px씩만 줄여 "근소하게 모자란" 상황을 해소하는 방식이 효율적이었음.
