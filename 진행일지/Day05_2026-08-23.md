### 3. 최신 트렌드 조사
- `WebSearch`로 "2026 상세페이지 카피라이팅 트렌드 AI 활용 전환율" 검색.
- 핵심 발견: (1) 콘텐츠 마케터의 90% 이상이 2026년 AI로 콘텐츠를 제작 중이지만 직접 구매 전환율은 오히려 하락하는 추세, (2) AI 확산 속에서 "정보형 콘텐츠는 줄고 설득의 언어(카피라이팅)는 남는다"는 진단이 나옴 — AI 시대일수록 카피라이팅의 전략적 가치가 커진다는 논지.
- 이 인사이트를 그대로 책의 핵심 훅으로 채택: "AI가 문장을 대신 써주는 시대이기 때문에 오히려 설득 구조(무엇을 먼저 말할지)를 아는 사람이 유리하다"는 메시지를 1장과 프롤로그에 명시적으로 반영. 출처: [카피라이팅이 다시 핵심 경쟁력으로 떠오른다 - 매드타임스](https://www.madtimes.co.kr/news/articleView.html?idxno=26416), [2026년 상세페이지 디자인 트렌드 - draph.art](https://draph.art/blog/insights/detail-page-design-trends-2026)

### 4. 콘텐츠 설계 결정
- 상품명을 "이 책은 AI가 썼습니다"/"야근 없는 사무실" 시리즈 톤에 맞춰 도발적이고 기억에 남는 문구로 결정: **"사장님, 그 카피로는 안 팔립니다"**. 부제는 "AI로 쓰는 상세페이지 — 후킹 헤드라인부터 CTA까지, 그대로 쓰는 프롬프트 18개".
- 목차 구성(16개 섹션, Day01/03과 동일 골격): 왜 지금인가 → 준비물 3가지 → 방법 1~12(기능→결과 전환, 헤드라인 공식 10가지, PAS 구조, 페르소나, 후기 활용, FAQ, CTA, 업종별 템플릿 5종, 가격 심리학, A/B 테스트, SEO, 데이터 기반 개선) → 프롬프트 18선 → 실전 체크리스트.
- 프롬프트 18개를 5개 카테고리(A. 헤드라인·구조 설계 3개 / B. 타겟·신뢰 확보 4개 / C. CTA·업종·가격 3개 / D. 버전·SEO·데이터 3개 / E. 다듬기·확장 5개)로 분류해 kit.html/Day03 ebook.html의 `cat-a`~`cat-e` 색상 체계를 그대로 매핑.
- 챕터 4(헤드라인 공식 10가지)는 10개 항목이 반복되는 구간이라 "본문 디자인 기준"에 따라 동일 박스 단순 나열을 피하기로 결정 — 기존 시리즈에 없던 새 컴포넌트 `.formula-grid`/`.formula`(2단 그리드, 골드 좌측 바 카드)를 신설해 적용. 챕터 9(CTA)와 챕터 10(업종별 템플릿)은 항목 수가 4~5개로 적어 기존 `.table-wrap` 표 스타일을 그대로 재사용.

### 6. PDF 렌더링 및 검증
- `NODE_PATH=/opt/node22/lib/node_modules node scripts/render_pdf_cloud.js`로 1차 렌더링 → 총 **14페이지**, 약 1.2MB.
- `scripts/screenshot_pdf_pages_cloud.js`로 14페이지 전부 스크린샷 후 육안 확인 — 대부분 페이지는 카드/텍스트가 페이지 하단까지 밀도 있게 채워져 있었으나, "방법 12(판매 데이터로 카피 고쳐나가기)" 챕터 마지막에 짧은 마무리 문단(2문장)이 통째로 다음 페이지로 밀리면서 이전 페이지 하단에 **약 29%의 빈 공간**이 남는 것을 발견 (Day01 진행일지의 12~14번 항목에서 다뤄진 것과 동일 계열의 "짧은 블록이 안 들어가면 통째로 다음 페이지로 밀리는" 문제).
- **원인 분석**: 해당 `<p>` 자체에는 `break-inside:avoid` 같은 명시적 규칙이 없었음에도 밀렸던 것으로 보아, Chromium 인쇄 엔진의 기본 `orphans`/`widows` 값(보통 2)이 "문단의 마지막 몇 줄만 다음 페이지에 남기지 않도록" 문단 전체를 다음 페이지로 넘긴 것으로 판단.
- **수정**: 전역 `p{ }` 규칙에 `orphans:1; widows:1;` 추가 — 브라우저가 문단을 "최소 몇 줄씩 묶어서" 페이지 경계를 피하려는 기본 동작을 끄고, 필요하면 문단이 페이지 중간에서 자연스럽게 잘리도록 허용. 재렌더링 후 같은 위치를 재확인한 결과, 문단이 "…살아있는" / "문서라고 생각하세요." 두 줄로 자연스럽게 나뉘어 페이지 경계를 넘어가면서 빈 공간이 거의 사라짐(책 조판에서 흔한 자연스러운 줄바꿈 수준).
- 이 수정은 시리즈 전체에 재사용 가능한 일반적 해법으로 판단됨 — 기존 Day01~04의 `break-inside:avoid`류 대응(큰 컨테이너에는 걸지 않기)과는 별개로, **문단 단위 위잉/오펀 문제는 `orphans:1; widows:1;`로 별도 대응해야 함**을 이번에 처음 확인.
- 나머지 13개 페이지는 재검토 결과 페이지 중간에 30% 이상 빈 공간이 남는 곳이 없음을 확인(체크리스트 챕터 끝부분에 약 16~20% 수준의 여백이 있었으나 챕터 경계 마무리 여백으로 정상 범위, 마지막 에필로그 페이지 여백은 책 관례상 정상).

### 7. 표지 인쇄 폭 검증 및 썸네일 제작
- `scripts/screenshot_element_cloud.js`로 뷰포트 673px(A4 실제 인쇄 폭)에서 `.cover`를 캡처해 육안 확인. 부제("AI로 쓰는 상세페이지 — 후킹 헤드라인부터 CTA까지, 그대로 쓰는 프롬프트 18개")와 통계 숫자(12/18/3) 모두 숫자+단위가 갈라지지 않음을 확인. "헤드라인부터"가 "헤드라인부" / "터"로 줄바꿈되는 지점이 있었으나, 이는 숫자+단위 조합이 아니라 일반 한글 단어의 음절 단위 줄바꿈으로 한국어 조판에서 자연스러운 현상이라 별도 조치 없이 유지(지침에서 명시적으로 문제 삼은 것은 "30일" 같은 숫자+단위 분리였음).
- 같은 673px 캡처 구도를 1000×1000 뷰포트(`deviceScaleFactor:2`)로 다시 캡처해 `marketing/thumbnail.png`로 저장 — 별도 AI 이미지 생성 없이 표지 그대로 사용(Day01~04와 동일 원칙 준수).

## 이슈/트러블슈팅
- **`HEAD detached` 상태로 세션 시작 (4회 연속 재발)**: Day02~04와 동일 패턴. 이번엔 로컬 HEAD가 origin/main과 완전히 같은 커밋이라 `git checkout -B main HEAD`로 간단히 정리, 데이터 유실 없음.
- **문단 단위 orphan/widow로 인한 PDF 페이지 하단 빈 공간(신규 유형)**: 기존 Day01 일지에 기록된 "큰 컨테이너(`break-inside:avoid`)가 안 들어가면 통째로 다음 페이지로 밀리는" 문제와는 원인이 달랐음 — 이번엔 명시적 break 규칙이 없는 짧은 `<p>` 태그가 브라우저의 기본 orphans/widows 값 때문에 통째로 다음 페이지로 밀린 경우였음. `p{ orphans:1; widows:1; }`을 전역으로 추가해 해결. **이후 Day의 ebook.html/kit.html에서도 챕터 마지막에 짧은 마무리 문단을 두는 패턴을 쓸 경우, 이 규칙을 CSS에 기본 포함해두는 것을 권장.**
