## 진행 과정

### 1. 저장소 상태 점검 및 착수 표시
- `git status`가 "HEAD detached from refs/heads/main"을 출력 — Day42 진행일지에 기록된 것과 동일한 패턴이 이번에도 반복됨. 로컬 `main`은 Day43 완료 커밋(`b651638`)에 머물러 있었음.
- 먼저 `로드맵.md`를 읽고 Day01~43이 모두 "완료", Day44가 가장 앞선 "대기" 항목임을 확인 → 상태를 "진행중"으로 갱신하고 커밋(이 시점에는 detached HEAD 상태인 줄 모르고 커밋해, 커밋이 detached HEAD 위에 쌓임).
- 본문 제작을 마친 뒤 커밋을 모으는 단계에서 `git branch -a` / `git rev-parse HEAD main origin/main`으로 재점검 → detached HEAD가 로컬 `main`보다 1커밋 앞서 있고(방금 만든 "작업 시작" 커밋), 로컬 `main`과 `origin/main`은 또 Day43의 커밋 2개만큼 뒤처져 있었음(이전 세션이 Day43 완료 후 push를 하지 않았던 것으로 추정). `git checkout -B main`으로 detached HEAD 위치에 로컬 `main`을 다시 맞추고, `git push -u origin main`으로 밀린 3개 커밋(Day43 착수·완료 2개 + 이번 Day44 착수 1개)을 한 번에 origin에 반영. **다음 세션도 시작 시 `git branch -a`로 detached 여부를 먼저 확인하고, 이번처럼 작업 커밋을 detached HEAD 위에 쌓지 않도록 가급적 착수 단계에서 바로 `main`으로 정리할 것.**

### 3. 엑셀 계산기·체크리스트 5종 설계 및 제작
- 로컬에 `openpyxl`이 없어 `pip install openpyxl`로 설치. `/tmp/.../scratchpad/make_xlsx.py` 스크립트 하나로 5개 파일을 한 번에 생성하도록 작성(스타일 헬퍼 함수 공유).
- 전자책 방법 1~8을 5개 파일로 재구성:
  1. **이사비용_계산기.xlsx** — 평수 구간별(원룸~4룸 이상) 포장이사 기준가 참고표 + 이사 방식·거리·엘리베이터·사다리차·날짜 유형·성수기 여부를 입력하면 기준가(`VLOOKUP`) → 거리 할증(`IF` 구간) → 작업 난이도 할증 → 방식별 조정 → 날짜 프리미엄 배율 → 성수기 배율까지 수식 체인으로 최종 예상 비용과 ±10% 범위를 자동 계산.
  2. **중개수수료_계산기.xlsx** — 전자책에 명시된 매매 6구간/임대차 5구간 법정 상한 요율표를 그대로 옮기고, 거래 종류·거래금액(또는 보증금·월세)을 입력하면 환산보증금(월세는 보증금+월세×100) → 적용 요율(중첩 `IF`) → 법정 상한 중개수수료(부가세 전/후) → 실제 청구액과의 차이까지 자동 계산.
  3. **견적서_비교_검증표.xlsx** — 업체 2~3곳의 항목별(기본운임·사다리차·포장재·에어컨탈부착·폐기물처리·기타) 금액을 입력하면 `SUM`/`MIN`/`MAX`/`INDEX-MATCH`로 합계·최저가 업체·차이를 자동 계산, 이사비용 계산기 결과와 교차검증하는 셀, 견적서에 명시 안 된 추가비용 7항목 확인 체크리스트 포함.
  4. **전입신고_확정일자_전월세신고_체크리스트.xlsx** — 이사일·계약일·보증금·월세 입력 시 전입신고 마감일(이사일+14일), 전월세신고 대상 여부(보증금 6천만원 또는 월세 30만원 초과)와 마감일(계약일+30일)을 자동 계산, 이사 당일~+30일 타임라인 7단계 체크리스트(`COUNTIF`/`COUNTA` 진행률 집계).
  5. **의뢰접수_상담진행_체크리스트.xlsx** — 접수 질문지(13개 항목) + 접수→리서치→계산→검증→행정→납품→사후관리 16단계 체크리스트, 진행률 자동 집계.
- `openpyxl`로 재오픈해 모든 수식 문자열을 셀 좌표와 함께 출력하는 방식으로 육안 검토. 특히 중개수수료 계산기의 구간 경계값(5천만/2억/9억/12억/15억, 임대차 5천만/1억/3억/6억)을 `<` 부등호 기준으로 "미만" 의미와 정확히 일치하는지, 이사비용 계산기의 텍스트 비교(`B11="25~34평(쓰리룸)"` 등 드롭다운 기본값과 참고표 라벨이 글자 단위로 완전히 일치하는지)를 직접 계산해 수기로 대조. 예: 전세 3억원·부가세 적용 입력 시 환산보증금 3억 → 적용요율 0.4%(3억~6억 구간) → 법정상한 132만원(부가세 포함)으로 계산되는 것을 손으로 재확인.
- `soffice`(LibreOffice)로 수식 재계산 검증을 시도했으나, 이번 세션에서도 트리비얼한 텍스트 파일 PDF 변환조차 "source file could not be loaded" 오류로 실패(프로필 디렉토리를 새로 지정해도 동일, Day42 진행일지에 기록된 것과 동일한 환경 제약). 대신 수식을 셀 참조 단위로 출력해 육안·수기 계산으로 대조하는 방식으로 검증을 대체.
- 파일별 시트 순서도 기존 파일과 동일한 관례(`['계산기','안내']` 또는 `['접수질문지','안내','진행체크리스트']`)로 맞추기 위해 `wb.move_sheet()`로 한 번 보정.

### 5. 표지 인쇄 폭(673px) 검증
- Playwright(Chromium, `/opt/pw-browsers/chromium`)로 `.cover`를 673×950px 뷰포트에서 캡처.
- 1차 제목("견적서 숫자는 계산기가,<br>법정 상한은 요율표가 확인합니다")으로 캡처했을 때, 두 번째 줄이 좁은 폭에서 다시 줄바꿈되며 "다" 한 글자만 세 번째 줄에 남는 어색한 결과를 확인 → Day43 전자책 표지(`그 견적서, AI한테<br>먼저 검증받으세요` — 짧은 2줄)처럼 각 줄을 더 짧게 끊은 "그 견적서, 계산기로<br>법정 상한까지 확인하세요"로 교체해 재캡처 → 두 줄 모두 안정적으로 한 줄에 들어옴을 확인.
- 부제의 숫자+단위 조합("2종", "3종", "5", "16단계", "4단계")은 처음부터 `<span class="nowrap">`으로 감싸 어색한 분리 없이 출력됨을 확인.

### 6. PDF 렌더링 및 페이지 여백 검증
- Playwright `page.pdf({format:'A4', margin:{top:'18mm',bottom:'18mm',left:'16mm',right:'16mm'}, printBackground:true})`로 렌더링 → `그_견적서_AI한테_먼저_검증받으세요_실행키트.pdf` 생성, 총 **6페이지**.
- 이번 세션에는 `pdftoppm`(poppler-utils)이 이미 설치돼 있어 `pdftoppm -png -r 150`으로 페이지별 PNG 변환 후 `scripts/scan_page_margins.py`(PIL+numpy, 잉크 기준 절대 임계값 방식)로 정량 스캔 수행 — 1페이지(표지, 41.5%)만 "확인 필요" 플래그가 떴고 이는 표지 특성상 정상으로 처리, 나머지 2~6페이지는 7.6~27.0%로 모두 30% 미만.
- 이어서 Read 도구로 6페이지 전체를 육안 재확인. 3페이지가 27.0%로 다소 여유 있었으나 이는 "02 패키지 구성 & 검증 워크시트" 섹션이 `break-after:avoid-page`로 다음 페이지로 통째로 넘어가면서 생긴 자연스러운 챕터 경계이지, 카드가 중간에 밀려서 생긴 빈 공간이 아님을 확인. 나머지 페이지도 카드 중간에 30% 이상 비는 곳 없이 하단까지 콘텐츠로 채워짐을 확인.

- **저장소가 또다시 detached HEAD로 시작함, 게다가 Day43 커밋 2개가 origin에 push되지 않은 채 남아있었음.** Day42 진행일지에서 경고했던 패턴이 재발. 이번엔 작업 착수 커밋까지 detached HEAD 위에 쌓은 뒤에야 본문 작업 도중 `git branch -a`로 재확인해 발견. `git checkout -B main`(detached HEAD 위치에 `main` 포인터를 재배치)으로 복구 후 `git push -u origin main`으로 밀려있던 3개 커밋을 한 번에 push. **다음 세션은 로드맵 상태를 "진행중"으로 바꾸고 커밋하기 전에 반드시 `git branch -a`와 `git rev-parse HEAD main origin/main`을 먼저 실행해 detached 여부·동기화 상태를 확인할 것. 이 문제가 계속 반복되는 것으로 보아, 세션 종료 시점에 로컬 `main` 브랜치 포인터가 갱신되지 않는 근본 원인이 하네스 쪽에 있을 가능성이 있음 — 사용자에게 공유 필요.**
