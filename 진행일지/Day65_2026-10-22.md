### 3. 주제 리서치 (WebSearch)
- "2026년 지역가입자 건강보험료 계산 방법 재산보험료 소득보험료 점수제" 검색 → 소득분은 더 이상 점수제가 아니라 정률제(소득월액×7.19%)로 바뀌었고, 재산분은 여전히 점수제(재산세 과세표준에서 1억 원 공제 후 점수 산정, 점수당 금액 약 208~211원)라는 점을 확인. 자동차보험료는 2024년 2월부터 전면 폐지됨도 확인. 장기요양보험료율은 약 12.95% 수준, 월 상한액은 약 459만 원 수준으로 출처마다 소폭 차이가 있어 "~수준"으로 서술.
- "2026년 건강보험 피부양자 탈락 기준 소득 재산 지역가입자 전환" 검색 → 피부양자 탈락 기준은 합산소득 연 2,000만 원 초과, 또는 재산과표 9억 원 초과(혹은 5.4억 원 초과+연소득 1,000만 원 초과)라는 2022년 하반기 개편 이후 기준이 2026년에도 유지되는 것으로 확인. 지역가입자 전환 후 소득 반영은 전년도 종합소득 신고 결과가 다음 해 11월경부터 반영되는 지연 구조도 확인.
- 검색 결과가 대부분 블로그·정보성 매체(위키독스, 더체크 리포트 등)이고 공식 공단 자료는 직접 확인하지 못함 → Day61·Day63과 동일한 패턴으로 "계산 구조를 보여주는 기준값이며 실제 적용 수치는 신청 시점 국민건강보험공단 고시로 재확인하라"는 고지를 책 전체에 반복 배치.
- 별도로 "임의계속가입 제도"(퇴사 전 18개월 중 직장가입자 보험료 납부기간 통산 1년 이상이면, 퇴사 후 일정 기간 직장가입자 수준 보험료 유지 가능)는 기존 지식과 검색 결과가 일치해 그대로 반영 — 이 주제의 핵심 차별 포인트(단순 계산이 아니라 "제도 활용까지 비교") 로 챕터 하나를 통째로 배정.

### 4. 콘텐츠 구조 설계
Day63 패턴(자격·기준값 확인 + 핵심 계산 + 부가사항 + 수익화 2챕터 + 실수 1챕터 + 시스템화 1챕터 + 프롬프트 15선 + 체크리스트, 총 16섹션)을 그대로 따라 아래 순서로 설계:
1. 왜 지금 AI로 건강보험료(지역가입자) 계산 대행인가 / 2. 준비물 3가지 / 3. 피부양자 자격 유지 가능 여부 점검(방법1) / 4. 소득보험료 계산(소득×7.19%, 방법2) / 5. 재산보험료 계산(1억 공제 후 점수제, 방법3) / 6. 장기요양보험료 추가(방법4) / 7. 월 보험료 총액·상한액 적용(방법5) / 8. 고지 시점·반영 지연 점검(방법6) / 9. 전환 시나리오별 비교(방법7) / 10. 임의계속가입 제도 활용 검토(방법8) / 11. 보험료 절감 전략 점검(방법9) / 12. 대행 부업 수익화(방법10) / 13. 흔한 실수 5가지 / 14. 대행 시스템 구축(방법12) / 15. 프롬프트 15선(A.기준값·자격확인 B.보험료계산 C.전환시나리오·절감전략 D.대행서비스화, 각 4·4·4·3개) / 16. 실전 체크리스트(오늘/이번주/이번달 3단계)
- 이 주제만의 핵심 함정(재산보험료 1억 공제 누락, 소득분을 옛날 점수제로 계산, 폐지된 자동차보험료를 더함, 소득 감소를 즉시 보험료 인하로 오안내, 임의계속가입을 안내 안 함)을 13장 실수표에 명시적으로 반영.

### 6. PDF 렌더링 및 검증
- `NODE_PATH=/opt/node22/lib/node_modules node scripts/render_pdf_cloud.js`로 PDF 생성(A4, 여백 18mm/16mm) → 16페이지.
- `python3 -m pip install --break-system-packages --force-reinstall --no-deps --ignore-installed pillow numpy`를 Day63 인수인계 메모대로 선제적으로 실행(이번에도 numpy 미설치 상태였음) → 정상 설치 확인.
- `pdftoppm -png -r 150`으로 페이지별 PNG 변환 후 `scripts/scan_page_margins.py`로 하단 여백 비율 정량 스캔.
  - 스캔 결과: 1페이지(표지) 43.3%, 16페이지(에필로그) 78.8%만 30% 초과 — 둘 다 설계상 의도된 독립 페이지라 정상. 나머지 14개 본문 페이지는 모두 7.4~15.9%로 과도한 빈 공간 없음.
- `scripts/screenshot_element_cloud.js`로 `.cover`를 673×950(PDF 실제 인쇄 폭) 뷰포트로 캡처해 육안 확인 — "건강보험료(지역가입자)", "계산 대행하는 법", "건강보험료 프롬프트 15개" 등 숫자+단위 조합이 `nowrap` 처리되어 어색하게 끊기는 곳 없음.
- Read 툴로 PDF 페이지 PNG(5페이지: 소득보험료 표+진행순서, 13페이지: 대행시스템 구축→프롬프트15선 전환부(2단 그리드 A카테고리), 15페이지: 체크리스트 3단계, 16페이지: 에필로그)를 직접 육안 확인 — 카테고리별 색상 구분·2단 그리드·배지·줄무늬 표가 의도대로 렌더링되고, 챕터 전환도 끊김 없이 자연스럽게 이어짐.
- `scripts/screenshot_element_cloud.js`로 `.cover`를 1000×1000(scale 2)로 캡처해 `marketing/thumbnail.png`로 저장 — 별도 AI 이미지 생성 도구를 쓰지 않고 책 표지 디자인을 그대로 재사용.

## 이슈/트러블슈팅
- 세션 시작 시 `git` 작업트리가 detached HEAD 상태였음 — `git fetch` 후 origin/main과 로컬 HEAD SHA가 동일함을 확인해 데이터 손실 위험은 없었고, `git checkout main && git reset --hard origin/main`으로 정상 브랜치 상태로 복구 후 작업. (매번 새 컨테이너로 시작되는 클라우드 세션 특성상 다음 Day에도 동일 현상이 재발할 수 있으니, 작업 시작 시 `git status`/`git branch`로 detached 여부를 먼저 확인하는 습관을 유지할 것.)
- pillow/numpy 네이티브 확장 깨짐은 Day63 인수인계 메모대로 `--force-reinstall --no-deps --ignore-installed` 옵션을 선제적으로 사용해 한 번에 해결 — 이번에는 별도 디버깅 시간 소요 없었음.
- 건강보험료 지역가입자 계산의 세부 수치(점수당 금액, 장기요양보험료율, 상한액)는 출처마다 소폭 다르게 나와 "~수준"이라는 표현과 반복된 재확인 고지로 리스크를 낮춤 — Day61(국민연금)·Day63(실업급여)과 동일한 패턴.
