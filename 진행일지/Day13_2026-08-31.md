- `로드맵.md`를 읽고 운영 규칙과 판매 반응 로그를 확인. Day 13("AI로 이력서·자소서 첨삭 서비스 운영하는 법", 전자책, 대기)이 가장 위 대기 항목임을 확인.

### 3. 최신 트렌드 조사 (WebSearch)
- "AI 이력서 자소서 첨삭 서비스 2026 부업 크몽 가격" 검색 — 크몽 스피드 첨삭 최저 5,000원, 첨삭 전문가 15,000원대, 자소서 첨삭 30,000원대 확인. 2025년 기준 제출된 자소서의 약 64.4%가 생성형 AI로 작성된 것으로 추정된다는 자료도 확인(출처가 커뮤니티 게시글 성격이라 책 본문에는 정확한 수치 대신 "절반 이상"으로 보수적으로 표현).
- "2026 채용 트렌드 AI 자소서 필터링 ATS 이력서 키워드" 검색 — 채용팀의 상당수(약 77%)가 정기적으로 AI 생성/지원 지원서를 접하고, 채용 담당자의 52.4%가 서류 검토~면접까지 AI를 활용 중이라는 조사 결과 확인. "기본적인 키워드 매칭 ATS는 모든 지원자가 동일한 최적화 키워드를 넣으면 신호가 사라진다"는 한계와, "AI가 쓴 뻔한 글 사이에서 실제 경험을 보여주는 것이 유일한 합격 비결"이라는 논지를 확인.
- **콘텐츠 설계에 반영한 핵심 논지**: "다들 AI로 자소서를 쓰는데 채용 담당자 쪽도 AI로 걸러내기 때문에, 오히려 균일한 AI 문체가 불리하게 작용한다"는 역설을 프롤로그와 방법 3("AI 티" 제거 첨삭)의 핵심 축으로 삼음 — 첨삭 서비스의 차별화 포인트를 "AI 사용을 숨기는 것"이 아니라 "AI 초안에 지원자 본인의 구체적 경험을 다시 채워 넣는 것"으로 명확히 정의.

### 4. 콘텐츠 설계
- 목차를 기존 시리즈와 동일한 16단 구조(도입 1 + 준비 1 + 방법 12 + 프롬프트 1 + 체크리스트 1)로 설계: 첨삭 기준표 → 1차 AI 스크리닝 → AI 티 제거 → ATS 키워드 최적화 → 직무별 맞춤 → 문항별 첨삭 → 이력서·자소서 일관성 → 면접 예상질문(부가서비스) → 패키지·가격 → 채널 등록 → 고객 응대 → 후기·시즌 확장.
- 표는 세 곳에 배치: 방법 1(첨삭 기준표: 항목/확인기준/흔한실수), 방법 5(직무별 강조 포인트: 개발자/마케터/디자이너/영업), 방법 9(패키지 가격표: 스피드/정식/프리미엄/정기권) — 조사한 크몽 가격대를 원화 그대로 표에 반영.
- 프롬프트는 진단·구조 첨삭(A) / 문항별 첨삭(B) / 직무·ATS 맞춤(C) / 운영·가격·확장(D) 4개 카테고리로 설계, **각 카테고리 정확히 4개씩 총 16개**로 처음부터 짝수 설계 — 작성 완료 후 A~D 각 4개, 합계 16개임을 표지·본문 수치와 대조해 일치 확인.

## 이슈/트러블슈팅
- **로컬 저장소 detached HEAD + 페치 지연**: 세션 시작 시 `git status`가 detached HEAD를 보여주고 `origin/main` 캐시가 15커밋 뒤처져 있어 "미푸시 커밋이 쌓여있는 것 아닌가" 하는 오해가 있었음. `git fetch origin main`으로 원격을 새로고침하니 실제로는 이미 최신 상태였고, `git checkout main && git merge --ff-only origin/main`으로 정상 브랜치로 정리. 다음 실행 때도 detached HEAD로 시작할 수 있으므로 작업 전 `git fetch` + `checkout main`을 먼저 하는 것을 습관화할 것.
- **표지 인쇄 폭 검증(673px)**: `.cover`를 673px 뷰포트로 캡처해 확인 — 숫자+단위 조합(12가지 방법, 16개 프롬프트, 3단계 체크리스트, "16개")이 모두 `.nowrap`으로 감싸져 있어 분리되지 않음. 어색한 줄바꿈 없음.
- **PDF 페이지별 빈 공간 검사**: 13페이지 전부 육안으로 확인. 프롬프트 카테고리를 처음부터 4개씩(짝수) 설계해서 과거(Day07) 겪었던 "홀수 카테고리 → 2열 그리드 마지막 줄 카드 1개 단독 → 페이지 하단 대형 빈 공간" 버그가 이번엔 재발하지 않음. 표가 페이지 경계를 넘어갈 때도 빈 공간 없이 자연스럽게 이어짐을 확인.
- 그 외 렌더링/스크린샷 도구(`render_pdf_cloud.js`, `screenshot_pdf_pages_cloud.js`, `screenshot_element_cloud.js`)는 Day02~12에서 이미 검증된 그대로 문제없이 재사용됨. 특이 오류 없음.
