### 6. PDF 렌더링 및 페이지 검증 — 라벨/그리드 분리 버그 재발·수정
- 이 세션에 `pdftoppm`(poppler-utils)이 설치돼 있지 않아 `apt-get install -y poppler-utils` 실행. 1차 `apt-get install`은 `security.ubuntu.com`에서 404가 나서 실패 → `apt-get update` 먼저 실행해 패키지 인덱스를 갱신한 뒤 재시도해서 성공(Day25 로그에는 없던 세부 트러블슈팅).
- `scripts/render_pdf_cloud.js`로 1차 렌더링 → 9페이지. Python(PIL/numpy)으로 각 페이지 하단 여백 비율을 정량 측정하는 스크립트를 Day25 로그의 방식대로 즉석 작성해 전체 페이지 스캔(`pip install --break-system-packages pillow numpy` 먼저 필요했음).
- **정량 스캔 결과**: 표지(1p, 43.6%)와 마지막 에필로그(9p, 87.9%)를 제외한 모든 본문 페이지가 8.5%~19.2%로 30% 미만 — 수치상으로는 문제 없었음.
- **육안 확인에서 별도 발견**: 정량 스캔에는 안 걸렸지만, 5페이지 하단에 "E. 카테고리별 고시정보 특화" 라벨만 혼자 남고 실제 프롬프트 5개(E1~E5) 그리드는 통째로 6페이지로 넘어가는 "라벨-콘텐츠 분리" 현상을 Read 툴로 육안 확인 — Day25 로그에서 정리해둔 두 번째 버그 유형("컨테이너에 아무 보호 규칙이 없어 라벨과 콘텐츠가 페이지 경계에서 분리")이 이번엔 하단 여백 비율 자체는 크지 않은 채로(다음 요소가 바로 다음 페이지 맨 위에서 시작해서) 재발한 사례. 정량 스캔만으로는 이런 "여백은 안 크지만 시각적으로 어색한 분리"를 못 잡는다는 걸 확인 → 육안 확인 병행이 여전히 필요함을 재확인.
- **1차 시도**: `.cat-label`·`.cat-flow`에 `break-after:avoid-page` 추가 → 재렌더링해도 동일 위치에서 그대로 분리됨(효과 없음).
- **원인 분석**: `.cat-label`이 `display:inline-block`으로 선언돼 있었음. CSS Fragmentation 스펙상 `break-after`/`break-before`는 블록 레벨 박스에만 적용되고 인라인 레벨 박스(inline-block 포함)에는 효과가 없음 — 그래서 `break-after:avoid-page`를 줘도 무시됨. `.cat-flow`는 기본 블록 요소라 규칙이 걸렸어야 하지만, 프롬프트팩 섹션(02)에서는애초에 `.cat-label` 바로 다음에 `.cat-flow` 없이 `.prompt-grid`가 오는 구조라 `.cat-label`의 inline-block 문제가 그대로 드러난 것.
- **최종 수정**: `.cat-label`의 `display`를 `inline-block` → `table`로 변경(테이블 박스는 외부 디스플레이가 block이라 break-after가 정상 적용되면서, 내용 너비만큼만 차지하는 배지 모양은 그대로 유지됨). 재렌더링 결과 라벨이 그 아래 그리드와 함께 다음 페이지로 자연스럽게 넘어가며 분리 현상 해소, 전체 페이지 수도 9페이지로 동일하게 유지, 나머지 페이지의 여백 비율도 8.5%~19.2% 범위에서 크게 변하지 않음.
- **교훈(신규)**: `break-after`/`break-before`로 "이 헤더는 다음 콘텐츠와 붙어있어야 한다"를 표현할 때, 대상 요소가 `inline-block`이면 규칙이 조용히 무시된다. 배지처럼 콘텐츠 너비만큼만 차지하되 break 규칙이 필요한 요소는 `display:table`(또는 `inline-block` 대신 `display:block; width:fit-content;`)로 바꿔야 한다. 정량적 여백 스캔은 "페이지 하단이 얼마나 비었는가"만 잡아내고 "헤더가 콘텐츠와 분리됐는가"는 못 잡으므로, 다음부터도 정량 스캔 후 반드시 각 섹션 전환부(챕터 제목, 카테고리 라벨 등)를 육안으로 재확인할 것.
- 전체 9페이지를 Read 툴로 순서대로 열어 재확인 완료 — 표지·본문 8페이지 모두 카드/그리드가 페이지 경계에서 부자연스럽게 끊기지 않음을 확인.

## 이슈/트러블슈팅
- **poppler-utils 설치 실패 후 재시도로 해결**: `apt-get install -y poppler-utils`가 `security.ubuntu.com` 404로 1차 실패 → `apt-get update`로 패키지 인덱스를 먼저 갱신한 뒤 재시도해서 성공. 다음 Day에서도 poppler가 없으면 이 순서(update 먼저)로 진행할 것.
- **`break-after`가 `inline-block` 요소에서 조용히 무시되는 문제(신규 유형)**: Day25 로그의 "라벨-콘텐츠 분리" 버그가 이번엔 다른 원인으로 재발했다. Day25는 카드 padding/gap을 줄여 여유 공간을 만드는 방식으로 해결했지만, 이번엔 애초에 `.cat-label`이 `inline-block`이라 `break-after:avoid-page`를 걸어도 CSS 사양상 아무 효과가 없었던 것이 원인이었다. **`display:table`로 바꿔 블록 레벨 박스로 만들자 정상 작동**했다. 앞으로 "이 작은 헤더/배지 요소가 다음 콘텐츠와 항상 붙어 있어야 한다"는 요구가 있으면, 그 요소의 `display`가 `inline`/`inline-block`이 아닌지 먼저 확인하고, 필요하면 `display:table`이나 `display:block`으로 바꿀 것.
- **정량 여백 스캔의 사각지대 재확인**: 이번 5→6페이지 분리는 여백 비율(15.0%, 19.2%)이 둘 다 30% 기준 안에 들어서 Python 스캔으로는 전혀 걸러지지 않았다. 육안 확인(Read 툴로 페이지 순서대로 열어보기)을 정량 스캔 다음 단계로 반드시 병행해야 하는 이유가 이번에 명확히 재확인됐다 — 스캔은 "빈 공간 과다"만 잡고, "요소 분리로 인한 어색한 페이지 전환"은 못 잡는다.
- 그 외 카테고리별 고시정보 리서치에서 law.go.kr 원문 전체를 WebSearch로 확보하지 못한 점은, 문서 전반에 "등록 직전 재확인 필수" 안내를 반복 배치하는 방식으로 처리(완전 해결이 아니라 리스크 관리).
