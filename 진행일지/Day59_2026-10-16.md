### 3. 육아휴직급여·출산휴가급여 리서치 (WebSearch 2회)
지급률·상한액·특례 조건이 저출생 대책으로 자주 개편되는 도메인이라, 최신(2026년 기준) 동향을 먼저 확인:
- **출산전후휴가급여**: 통상임금(실수령액이 아님) 기준 100% 지급, 고용보험 지원분에는 30일 기준 월 상한액(최근 자료 기준 약 220만 원 수준)이 있는 구조. 전체 90일(다태아 120일), 출산 후 45일(다태아 60일) 이상 확보 조건도 확인.
- **육아휴직급여**: 통상임금 80% 지급률에 구간별 상한액(1~3개월 약 250만 원 / 4~6개월 약 200만 원 / 7개월 이후 약 160만 원)이 적용되는 구조, 하한액 월 70만 원 수준, 2025년 1월부터 사후지급금 제도 폐지(복직 여부와 무관하게 매달 전액 지급)를 확인.
- **6+6 부모육아휴직제**: 자녀 생후 18개월 이내 부모 모두 사용 시 첫 6개월 통상임금 100%, 월차별 특례 상한액이 단계적으로 높아지는 구조(최대 450만 원까지 소개하는 자료도 있었음). 다만 **자료마다 월별 특례 상한액 수치가 꽤 다르게 소개되고 있어**, 정확한 구간표 대신 "제도 구조 + 재확인 필수" 수준으로만 서술하기로 결정(혼선을 막기 위한 판단, Day57에서 2026년 세제개편안 미확정 수치를 책 본문에서 뺀 것과 같은 원칙).
- **한부모·장애아 특례, 기간 연장**: 한부모 근로자는 1~3개월 구간 상한액이 더 높게(약 300만 원 수준) 적용된다는 자료, 장애아 양육 부모는 "부모 각각 3개월 이상 사용" 조건 없이도 1년 6개월 연장이 인정된다는 자료를 확인. 배우자 출산휴가는 공식 출처를 확보하지 못해, 최근 자료에서 공통적으로 언급된 20일·유급 구조로만 서술하고 리포트에 재확인 안내를 명시.
- 검색 결과가 대부분 블로그·뉴스 출처였고 고용노동부 1차 공식 자료를 직접 확보하지 못했다는 점을 감안해, Day57의 세금 수치 처리 원칙(책에 적은 숫자는 "계산 구조를 보여주는 기준값"이며 실제 적용 전 공식 채널 재확인 필수)을 이번에도 그대로 적용 — 특히 6+6 특례·한부모 특례처럼 수치 편차가 큰 항목은 매 챕터 `worksheet-note`에서 "고용24 재확인" 문구를 반복 배치했다.

### 7. PDF 렌더링 및 페이지 여백 검증
- `render_pdf_cloud.js`로 A4(margin 18mm/16mm) PDF 렌더링 → `신청전에_AI한테육아휴직급여부터물어보세요.pdf` 생성, 총 **15페이지**.
- `pdftoppm -r 150`으로 전 페이지를 PNG로 변환한 뒤, `scripts/scan_page_margins.py`로 페이지별 하단 여백 비율을 1차 스크리닝. 이 세션에도 `python3`(3.11)과 시스템 `pip3`가 가리키는 인터프리터가 달라 Pillow/numpy가 반영되지 않는 문제가 재발 — `python3 -m pip install --break-system-packages pillow numpy`로 실행 인터프리터에 직접 설치해 해결(Day57 진행일지에 기록된 것과 동일한 원인·해결법).
- 스캔 결과 표지(1페이지, 38.6%)만 임계치(30%)를 초과했고, 이는 "표지 페이지의 여백은 정상" 예외에 해당. 나머지 본문 14개 페이지는 6.8%~23.5% 사이로 전부 임계치 이내였고, 가장 높았던 14페이지(23.5%, C~D 카테고리 프롬프트 그리드 끝나는 지점)와 15페이지(21.7%, 체크리스트+에필로그)를 Read로 직접 열어 카드가 다음 페이지로 밀려 생기는 빈 공간이 아니라 섹션이 자연스럽게 끝나며 생기는 여백임을 육안 확인.
- 2페이지(목차)와 8페이지(하한액·사후지급금 챕터)도 Read로 직접 열어 표·카드·체크리스트 배지가 모두 의도대로 렌더링되는 것을 확인.

## 이슈/트러블슈팅
- **PDF 여백 스캔 스크립트 의존성 누락 재발** — `scripts/scan_page_margins.py` 실행 시 `ModuleNotFoundError: No module named 'PIL'` 발생. Day57에서 기록된 것과 동일한 원인(시스템에 여러 python3 버전이 공존, `pip install`이 세션이 실제 실행하는 인터프리터와 다른 곳에 설치됨)으로 재발. `python3 -m pip install --break-system-packages pillow numpy`로 `python3`가 실제로 가리키는 인터프리터에 직접 설치해 해결. 다음 세션에서도 재발 가능성이 높으니, PDF 여백 검증 단계에 들어가기 전에 `python3 -c "import PIL"`로 먼저 확인하고 안 되면 바로 이 명령으로 설치할 것.
