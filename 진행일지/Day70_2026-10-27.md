### 4. 콘텐츠 구조 설계 — 계산기·체크리스트·템플릿 5종
Day69 전자책의 방법 1~9를 실제로 "조건 입력 → 결과 자동 계산"하는 도구로 구현:
- **A. 이혼재산분할_순재산분할액_계산기.xlsx**(gold) — 재산목록(공동재산/특유재산-포함/특유재산-제외)·채무목록(공동채무/개인채무)을 드롭다운으로 분류하면 `SUMIF`로 분할대상 총재산·순재산을 자동 계산하고, 기여도 비율(최소~최대%) 입력 시 재산분할 예상액 범위까지 자동 계산.
- **B. 퇴직금연금분할_계산기.xlsx**(terracotta) — 전체 재직기간·혼인기간·추정가액 입력 시 혼인기간 비율(`MIN(혼인기간/재직기간,1)`)과 분할대상 가액을 계산하고, 기여도 비율 적용 후 실제 분할예상액까지 계산. 분할연금 청구기한(수급권 발생일+5년, `EDATE` 함수) D-day도 같은 파일에 포함.
- **C. 위자료_예상범위_추정_계산기.xlsx**(teal) — 유책사유 6개 항목(외도20·폭력20·유기15·부당대우15·채무도박15·기타15, 합 100점 만점)에 Y/N 체크 시 `SUMIF`로 총점을 계산하고, 혼인기간 조정계수(10년 이상 1.2배/5년 이상 1.0배/미만 0.8배)와 쌍방과실 조정계수(있으면 0.7배)를 반영해 기본범위(참고치 2천~5천만 원)에 곱한 위자료 예상범위를 계산.
- **D. 청구기한Dday_이혼서류준비_체크리스트.xlsx**(olive) — 'D-day계산기' 시트(이혼 성립일→재산분할 제척기간 2년, 연금 수급권 발생일→분할연금 청구기한 5년, 불법행위를 안 날→위자료 참고 소멸시효 3년, 모두 `EDATE`+`TODAY()`로 마감일·잔여일수 자동 계산) + '체크리스트' 시트(기본·재산분할·위자료증거·자녀관련 4개 카테고리, 서류 20종, 준비상태 드롭다운).
- **E. 의뢰접수_고객리포트_템플릿.docx**(plum) — 의뢰 접수 질문지 14문항 + 기준값·한도 체크 5개(제척기간·청구기한·소멸시효·양육비 구분·변호사법 소지 경고) + 고객용 리포트 템플릿 9단계 + 서비스 안내·가격 템플릿(4개 패키지).
- 법률 인접 주제인 만큼, Day69 전자책에서 추가했던 "계산 정리 대행 범위를 벗어나지 않게 운영"이라는 변호사법 위반 소지 경고 문구를 실습자료의 안내 시트·README·docx 템플릿에도 동일하게 반복 배치.

### 5. 환경 준비 — 파이썬 패키지 설치
- `python3 -c "import openpyxl"` 테스트 → `ModuleNotFoundError` 확인. Day63·65·67·69에서 반복됐던 pillow/numpy 네이티브 확장 깨짐과 별개로, 이번엔 openpyxl·python-docx 자체가 설치돼 있지 않음.
- `pip install --break-system-packages --force-reinstall --no-deps --ignore-installed pillow numpy openpyxl python-docx` 실행 → `et_xmlfile`(openpyxl 의존), `typing_extensions`(python-docx 의존) 누락으로 재차 `ModuleNotFoundError` 발생 → `--no-deps` 설치 특성상 의존 패키지가 따라오지 않는다는 점을 확인하고 `et_xmlfile`, `lxml`, `typing_extensions`을 순차로 추가 설치해 해결.

### 6. 엑셀 계산기 4종 제작 및 수식 검증
- `openpyxl`로 A~D 4개 xlsx 파일 생성 스크립트(`/tmp/.../scratchpad/make_xlsx.py`) 작성. 안내 시트(경계 문구) + 계산기 시트(노란 입력칸/올리브 결과칸, 데이터 유효성 드롭다운) 공통 구조로 제작.
- openpyxl은 수식을 계산하지 않고 저장만 하므로, 컨테이너에 설치된 `libreoffice`(`soffice`)로 4개 파일을 모두 `--convert-to xlsx` 재저장시켜 강제로 수식을 재계산시킨 뒤 `openpyxl(data_only=True)`로 다시 읽어 결과값을 전수 검증 — `#REF!`/`#VALUE!`/`#NAME?` 등 오류 셀 없음을 확인. 예시 조건(A: 순재산 4억 3,200만 원→기여도 40~50%→1억 7,280만~2억 1,600만 원, B: 재직22년·혼인14년→비율63.6%→분할대상 1억 1,454만 원, C: 외도만 체크→총점20점→위자료 예상범위 480만~1,200만 원, D: 날짜 3개→D-day 755/1,952/583일)이 모두 수작업 계산과 일치함을 확인.

## 이슈/트러블슈팅
- 이번 컨테이너는 openpyxl·python-docx·pillow·numpy가 모두 설치돼 있지 않은 상태로 시작했음 — Day63~69에서 반복된 "pillow/numpy 네이티브 확장만 깨짐" 패턴과 달리 패키지 자체가 없었음. `--no-deps`로 핵심 패키지만 설치했다가 `et_xmlfile`(openpyxl)·`typing_extensions`(python-docx) 누락으로 재차 실패 → 의존 패키지를 개별 확인해 추가 설치. 다음에 유사 상황이면 `--no-deps` 없이 설치하거나, 최소한 `et_xmlfile`·`lxml`·`typing_extensions`을 함께 설치할 것.
- openpyxl은 수식을 저장만 하고 계산하지 않아 결과값 검증이 어려운 문제가 있었음 — 컨테이너에 사전 설치된 `libreoffice`(`soffice --headless --convert-to xlsx`)로 재저장시켜 강제 재계산한 뒤 `data_only=True`로 다시 읽는 방식으로 해결. 이 방식을 앞으로 엑셀 계산기 제작 시 수식 검증의 표준 절차로 메모해둠 — 수작업 계산값과 반드시 대조할 것.
- `scripts/render_pdf_cloud.js`/`screenshot_element_cloud.js`의 기본 Chromium 탐색 경로 문제는 Day67·69와 동일한 패턴(`chrome-linux64` 디렉터리명)으로 재발 — `PLAYWRIGHT_CHROMIUM_PATH=/opt/pw-browsers/chromium` 환경변수를 선제적으로 사용해 즉시 해결.
- 썸네일 PNG 크기가 요청된 "1000×1000px 권장"과 다르게 1600×1306(scale 2 기준 800×653)으로 저장됨 — `.cover` 요소의 실제 렌더링 높이가 1000px 뷰포트보다 커서 요소 전체를 캡처하면 정사각형이 아니게 되는 구조적 특성. Day68·69도 동일한 비율(가로가 세로보다 긴 직사각형)로 저장되어 있어 기존 관례와 일치하므로 문제 삼지 않고 그대로 진행함.
