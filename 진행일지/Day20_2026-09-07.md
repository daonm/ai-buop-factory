### 2. 콘텐츠 설계 — 8주 커리큘럼 템플릿 5종
- 도메인 5개를 확정: A. 마케터(『브랜드 SNS, 나만 할 줄 아는 게 아니었다』, 인프런/탈잉형 실무), B. 요가 강사(『퇴근 후 20분, 내 몸과의 약속』, 클래스101형 라이프스타일), C. 재테크 유튜버(『월급쟁이의 재테크 1교시』, 탈잉형 자기계발), D. 백엔드 개발자(『실무에서 통하는 API 설계』, 인프런형 IT·개발), E. 홈베이커(『오븐 하나로 시작하는 홈베이킹』, 클래스101형 라이프스타일).
- 도메인마다 Day19 방법 3~6에서 다룬 프로세스(학습목표 5개 동사형 도출 → 8주 모듈을 난이도 순으로 배치 → 회차별 학습목표/핵심개념/실습과제/예상 소요시간 상세안)를 그대로 적용해 실제로 완성된 8주 커리큘럼을 직접 작성. 초반 1~2주는 쉬운 성취감 위주, 5~6주(전체의 60~70% 지점)에 가장 어려운 개념 배치, 마지막 주는 실습 프로젝트로 마무리하는 난이도 곡선 원칙(Day19 방법 5)을 5개 도메인 전부에 일관되게 적용.
- 산출물을 두 형태로 이원화: (1) `8주_커리큘럼_템플릿_전체모음.md` — 도메인별 8주 전체 상세안(학습목표 5개 + 회차별 모듈/핵심개념/실습과제/예상 소요시간 40개 전체)을 markdown으로 복사하기 쉽게 정리 (2) `kit.html` — 도메인별 8주 모듈 요약표(주차/모듈/이번 주 실습 3열)와 학습목표 5개를 카테고리 색상·카드형 레이아웃으로 시각화한 디자인 버전. 40회차 전체를 상세 카드로 나열하면 PDF가 지나치게 길어질 것으로 판단해, kit.html은 "한눈에 훑어보는 8주 요약표"로, 회차별 상세(핵심개념·실습과제·소요시간)는 markdown 파일에서 그대로 복사하는 역할로 분담.
- 워크시트(학습목표 도출 / 난이도 곡선 점검(8주) / 인터뷰 원료 수집)와 커리큘럼 설계 체크리스트(인터뷰→설계→상세→등록 4단계)를 markdown 파일과 kit.html 양쪽에 동일하게 반영.

### 3. 디자인 시스템 재사용 및 확장
- `kit.html`은 Day02/Day18과 동일한 CSS 변수(색상 토큰, 폰트: Gowun Batang + Noto Sans KR + Nanum Gothic Coding)와 클래스 관례를 그대로 재사용. 도메인 5개(마케터=gold, 요가 강사=terracotta, 재테크 유튜버=teal, 백엔드 개발자=olive, 홈베이커=plum)에 정확히 대응.
- **표/워크시트 패턴 확장**: 이번 실습자료는 "8주 x 5도메인" 표 형태 데이터가 핵심이라, 기존 `.worksheet`(항상 골드 강조) 패턴을 그대로 쓰는 대신, 표 헤더·좌측 바·zebra tint를 카테고리 색상으로 물들이는 `.domain-block` 변형 클래스를 신규 추가(`.cat .table-wrap`, `.cat table th`, `.cat tr:nth-child(even) td`를 accent 색상으로 override). 워크시트 패턴의 "카드로 감싸기 + 좌측 5px 컬러 바 + 표 헤더 강조색 + zebra stripe" 원칙은 그대로 지키되, 색을 도메인별로 구분해 5개 도메인 표가 한눈에 구별되도록 확장. 학습목표 5개는 기존 `.handoff-box`와 시각적으로 유사한 신규 `.goal-box`(카테고리 accent-tint 배경 + 순서 목록)로 표현.
- **표지 문구 인쇄폭 검증**: 표지 h1 "8주 커리큘럼 템플릿 5종"과 부제의 숫자+단위 조합("8주", "5종", "40개")을 `<span class="nowrap">`으로 감싼 뒤, 뷰포트 673px(A4 PDF 실제 인쇄폭)로 캡처해 확인 — 어색한 개행 없이 정상 출력됨을 확인.
- **PDF 여백 검증**: `render_pdf_cloud.js`로 PDF 렌더링 후 총 9페이지 생성. `screenshot_pdf_page_exact_cloud.js`로 페이지별 개별 캡처해 육안 검증한 결과, 도메인별 8주 표+학습목표 카드가 있는 본문 페이지(2~6페이지)는 상단부터 하단까지 카드로 빼곡히 채워져 있었고, 체크리스트 페이지(7~8페이지)도 마찬가지로 잘 채워짐을 확인. 다만 최초 렌더링에서 에필로그(`.epilogue`)의 마지막 문장 2줄이 8페이지 하단에 남고 "— 끝 —" 서명 한 줄만 9페이지로 밀려나 9페이지가 거의 빈 페이지가 되는 문제를 발견 — `.epilogue`에 `break-inside:avoid`를 추가하고 `section.chapter`/`.checklist-group` padding을 소폭(각 24px 0 26px, 12px 16px) 줄여 에필로그 전체가 한 덩어리로 9페이지에 모이도록 수정. 이후에도 9페이지 자체가 짧은 에필로그만 담아 여백이 남지만, 이는 본문 카드 사이의 여백이 아니라 책의 마지막 "콜로폰" 성격의 페이지(표지처럼 여백이 정상인 범주)로 판단해 허용 범위로 처리.
- 최종 PDF(`8주_후_강의가_시작됩니다.pdf`, 9페이지)와 썸네일(`marketing/thumbnail.png`, `.cover` 요소를 1000×1000 · deviceScaleFactor 2로 캡처)을 정식 산출물로 생성.

## 이슈/트러블슈팅
- **저장소 브랜치 상태**: 세션 시작 시 detached HEAD였고 로컬 `main`이 origin보다 6커밋 뒤처져 있었음. `git checkout main && git fetch/pull origin main`으로 해결 후 작업 진행. (원인 불명 — 이전 세션 종료 방식 때문으로 추정, 실제 작업에는 영향 없었음)
- **에필로그 페이지 분리 문제**: 최초 렌더링에서 에필로그 서명("— 끝 —")만 별도 페이지로 밀려나 사실상 빈 페이지가 생성됨. `.epilogue`에 `break-inside:avoid` 추가 + 인접 섹션 padding 축소로 에필로그 전체를 한 페이지에 모아 해결(위 3번 참고). 다만 이 조정만으로는 페이지 수(9→9, 내용 총량 대비 8페이지로 줄지는 않음) 자체는 줄지 않았고, 마지막 페이지가 에필로그만 담아 여전히 여백이 있음 — 책의 콜로폰 성격 페이지로 판단해 허용.
- 그 외 특이 이슈 없음 — `NODE_PATH=/opt/node22/lib/node_modules` 지정, `/opt/pw-browsers`의 사전 설치 Chromium 사용 등 기존 클라우드 렌더링 파이프라인이 그대로 잘 작동함을 재확인.
