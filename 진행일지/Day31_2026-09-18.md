### 6. PDF 렌더링 및 페이지 검증
- `scripts/render_pdf_cloud.js`로 렌더링 → **14페이지** 생성.
- 이 세션에 `pdftoppm`(poppler-utils)이 설치돼 있지 않아 `apt-get install -y poppler-utils`를 바로 실행했다가 404 오류로 1차 실패 → `apt-get update` 선행 후 재시도해 성공 (Day29 로그의 동일 트러블슈팅 패턴 재확인).
- `PIL`(pillow)/`numpy`가 미설치라 `scan_page_margins.py`의 정량 스캔은 건너뛰고, 대신 poppler 설치 후 **Read 툴의 PDF 네이티브 페이지 렌더링 기능으로 14페이지 전체를 육안 확인** — 표지, 목차, 방법 01~14 전체, 프롬프트 A~D 카테고리 그리드(2단 배치), 체크리스트 3그룹(원형 배지 "오늘/이번 주/이번 달"), 에필로그까지 페이지 경계에서 카드 잘림이나 과도한 하단 여백 없이 자연스럽게 이어지는 것을 확인. `scripts/screenshot_pdf_pages_cloud.js`(브라우저 PageDown 방식)는 페이지 스크롤 오프셋이 실제 PDF 페이지 번호와 어긋나는 현상이 있어(파일명 순서와 뷰어 헤더의 실제 페이지 번호가 최대 2페이지까지 밀림) 신뢰하지 않고, Read 툴 자체 PDF 렌더링으로 교차 검증함.
- 렌더링된 최종 PDF를 `계정은_있는데_릴스가_없습니다.pdf`로 저장해 `ebook/` 폴더에 포함.

"12가지 방법"/"16개 프롬프트"/"3단계 체크리스트" 등 숫자+단위 조합은 처음부터 `.nowrap`을 적용해 문제 없었음.

## 이슈/트러블슈팅
- **저장소가 detached HEAD 상태로 시작**: 이전 세션이 커밋 직후 브랜치를 갱신하지 않고 종료된 것으로 추정. `git fetch` + `git checkout -B main origin/main`으로 안전하게 복구(로컬에 origin/main과 다른 커밋이 없음을 먼저 확인한 뒤 진행).
- **poppler-utils 1차 설치 실패**: `apt-get update` 없이 바로 설치 시 404 오류. `apt-get update` 선행 후 정상 설치 — Day29에서도 동일하게 발생한 패턴이라 앞으로도 이 순서를 기본으로 삼을 것.
- **`screenshot_pdf_pages_cloud.js`의 페이지-파일명 불일치**: 브라우저 PDF 뷰어에서 PageDown 키 입력으로 캡처하는 방식이 실제 페이지 진행과 최대 2페이지까지 어긋나는 현상을 발견(예: `page_05.png` 파일이 실제로는 PDF 7페이지 내용). 원인은 미상(콘텐츠 높이에 따라 스크롤 스냅이 페이지를 건너뛰는 것으로 추정)이나, 이번에는 poppler 설치 후 Read 툴의 네이티브 PDF 페이지 렌더링으로 전체를 재검증해 실질적 문제는 없었음. 다음 세션에서 이 스크립트를 쓸 때는 파일명과 실제 페이지 번호가 다를 수 있다는 점을 감안하고, 가능하면 Read 툴의 PDF pages 기능을 우선 사용할 것.
- **PIL/numpy 미설치**: 이번엔 설치 시도 없이 Read 툴 PDF 렌더링으로 대체 검증. 정량 스캔이 필요하면 다음에도 `pip install --break-system-packages pillow numpy` 필요.
- 표지 부제 줄바꿈 1건을 제외하고 새로운 디자인/렌더링 버그는 발견되지 않음.
