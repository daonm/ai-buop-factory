### 4. 핵심 피드백 반영 — "AI가 썼다"는 훅이 약하다

## 10. Threads API 연동 (자동 포스팅)

## 11. 한글 인코딩 깨짐 버그 발견 및 수정
사용자가 실제 게시된 글을 확인 → 한글이 전부 `◆◆◆◆◆` 형태로 깨져서 게시됨 (2건: 최초 테스트 글, 파일 기반으로 고친 후 재게시한 글 둘 다 깨짐).

**원인 규명 과정**
1. 처음엔 "커맨드라인 인자로 한글 전달 시 깨짐"으로 추정 → `--file` 옵션으로 텍스트 파일을 읽는 방식으로 변경했으나 **여전히 깨짐**
2. 파일 자체의 UTF-8 바이트를 `od -tx1`로 직접 확인 → 정상 (`ec 8a a4` = "스" 정확)
3. `curl --data-urlencode "text@파일"` (파일을 curl이 직접 읽게) 방식을 httpbin.org로 테스트 → **정상 전송 확인**
4. `TEXT=$(tr -d '\r' < 파일)` 로 bash 변수에 담은 뒤 `--data-urlencode "text=${TEXT}"` 로 넘기는 방식을 동일하게 httpbin.org로 테스트 → **깨짐 재현** (`�` 유니코드 대체문자로 응답)
5. **결론**: 이 Git Bash(Windows/MSYS2) 환경에서 UTF-8 멀티바이트 문자열을 bash 변수에 담았다가 curl 인자(`--data-urlencode "name=${VAR}"`)로 넘기면 손상됨. 반면 `--data-urlencode "name@파일경로"` (curl이 파일을 직접 읽는 방식)는 손상 없음. echo로 변수를 출력했을 땐 정상으로 보였기 때문에 처음엔 원인 파악이 어려웠음 (터미널 출력과 curl 내부 처리 경로가 다르게 동작하는 것으로 추정).

**수정**
- `scripts/threads_post.sh`: 텍스트를 bash 변수에 절대 담지 않고, CRLF만 제거한 임시 파일(`scripts/.tmp_post_content_$$.txt`)을 만들어 `curl --data-urlencode "text@임시파일"` 방식으로 전달하도록 변경
- 부가 이슈: `mktemp` 기본 경로(`/tmp/...`)를 Windows용 curl.exe가 못 읽는 문제 추가 발견 → 임시 파일을 프로젝트 폴더 안(`scripts/`)에 만들도록 변경해서 해결
- `.gitignore`에 `scripts/.tmp_post_content_*.txt` 패턴 추가 (트랩으로 자동 삭제되지만 이중 안전장치)
- 재테스트 통과, 정상 게시 확인 (Post ID `18106652126128301`)
- 이전에 깨져서 올라간 테스트 글 2개는 사용자가 직접 삭제

**앞으로 이 프로젝트에서 한글(또는 비ASCII) 텍스트를 외부 API로 보낼 때는 항상 "파일에 UTF-8로 저장 → curl에 `@파일경로`로 직접 읽게 하기" 패턴을 쓸 것. bash 변수에 담아 인자로 전달하는 방식은 이 환경에서 쓰지 않는다.**

## 12. 전자책 디자인 개선 + PDF 직접 렌더링
사용자가 브라우저로 인쇄해서 받은 PDF가 "허접하다"고 피드백 → 원인은 브라우저 인쇄가 배경색/그래픽을 기본적으로 생략하고, 사용자 인쇄 설정에 따라 폰트·여백이 들쭉날쭉해지는 것.

**디자인 개선 (`ebook.html`)**
- `*{ print-color-adjust: exact; }` 추가 — 인쇄 시 배경/색상이 생략되지 않도록 강제
- 표지: 시리즈 킥커("AI 부업 시리즈 · VOL. 01") 추가, 골드 톤 방사형 그라디언트 배경, 상하 이중 룰(double rule) 프레임 — 밋밋했던 표지에 편집 디자인 느낌 부여
- 챕터 헤더: 숫자를 단순 외곽선 박스 → 골드 배경의 채워진 배지로 변경, 챕터 시작마다 왼쪽 상단 골드 액센트 바 추가
- 목차: 좌측 번호+텍스트 나열 방식 → 점선 리더(dot leader)로 제목과 챕터 번호를 잇는 클래식 도서 목차 스타일로 변경
- `@page{ margin:18mm 16mm; }` 로 인쇄 여백 명시

**PDF 생성 방식 자체를 변경**
- 브라우저 "인쇄→PDF저장"은 사용자 브라우저 설정(배경 그래픽 옵션 등)에 좌우되어 품질이 들쭉날쭉함을 확인
- 대안으로 `puppeteer-core` + 로컬에 이미 설치된 Chrome(`C:\Program Files\Google\Chrome\Application\chrome.exe`)을 사용해 **서버 사이드에서 고정 품질 PDF를 직접 생성**하는 방식으로 전환 (Chromium 재다운로드 없이 puppeteer-core만 설치, `--no-save`로 package.json 미생성)
- `scripts/render_pdf.js` 작성: HTML 파일을 file:// 로 열고, 구글 폰트 로딩 완료(`document.fonts.ready`)를 기다린 뒤 `printBackground:true` 옵션으로 PDF 저장. A4, 여백 18mm/16mm
- 실행 결과: `products/day01_ai-부수입-가이드/ebook/이_책은_AI가_썼습니다.pdf` (1.1MB) 생성 성공, 사용자에게 파일 전달
- Artifact도 같은 URL로 재발행해서 화면에서도 개선된 디자인 확인 가능

**참고**: 사용자가 이전에 브라우저로 직접 인쇄해서 받은 파일(`이 책은 AI가 썼습니다.pdf`, 공백 포함 파일명)이 프로젝트 루트에 있었음 — 이건 사용자의 로컬 다운로드 파일이라 건드리지 않고 git에서 제외함 (새 렌더링 파일은 밑줄 포함 파일명으로 구분).

**앞으로 다른 Day의 ebook.html도 PDF로 뽑을 때는 `node scripts/render_pdf.js <입력.html> <출력.pdf>` 로 통일해서 사용할 것 — 브라우저 수동 인쇄에 의존하지 않는다.**

## 13. 페이지 넘김 잘림/빈 공간 버그 두 차례 수정 + "파일이 안 바뀐다" 오해 해소

**1차 신고 (사용자)**: PDF를 페이지 단위로 캡처해서 보내주심 — 목차가 컨테이너 테두리와 함께 어중간하게 쪼개짐, 챕터 시작 부분의 골드 액센트 바가 엉뚱한 위치에 떠 있음, 리스트 항목이 중간에 끊겨서 다음 페이지에 고아처럼 남음.

**원인**: `section.chapter::before`로 만든 챕터 상단 골드 바가 `position:absolute`였는데, 인쇄 시 컨테이너가 여러 페이지에 걸쳐 조각날 때 절대 위치 요소가 원래 챕터 박스 기준을 벗어나 엉뚱한 곳에 렌더링됨. 또한 목차/프롬프트카드/체크리스트/스텝목록에 `break-inside` 보호가 없어서 페이지 경계에서 임의로 잘림.

**1차 수정**: `::before` 절대위치 바를 제거하고 `h2.chapter{ border-top:3px solid gold }`로 교체(문서 흐름 안에 있어서 페이지 분할에 영향 안 받음). `.toc`, `.prompt`, `.checklist-group`, `ol.steps`, `ol.prompt-list > li`에 `break-inside:avoid` 추가. `section.chapter`에는 `break-inside:avoid-page`를 추가해서 챕터 전체가 안 쪼개지게 함.

**"파일이 안 바뀐다" 소동**: 1차 수정 후 재렌더링해서 보냈는데 사용자가 "변경된 게 없다"고 재차 신고. 소스 HTML(`grep`)과 생성된 PDF 파일의 수정 시각을 확인해보니 실제로는 수정 사항이 정확히 반영되어 있었음 — 사용자가 예전에 다운로드했던 파일(브라우저가 자동으로 "(1).pdf" 등으로 저장)을 다시 열어보고 있었을 가능성이 높다고 판단, 원본 파일 경로를 직접 알려드림.

그래도 확신이 안 서서, **poppler(pdftoppm)가 설치되어 있지 않아 Read 툴로 PDF를 직접 못 열었기 때문에** 우회 방법을 만듦:
- `scripts/screenshot_check.js`: HTML을 print 미디어로 렌더링해서 구간별 PNG로 캡처 (텍스트 내용 확인용, 실제 페이지 분할은 반영 안 됨)
- `scripts/screenshot_pdf.js`, `scripts/screenshot_pdf_page.js`: **생성된 PDF 파일 자체**를 Chrome 내장 PDF 뷰어로 열어서(`file:///경로.pdf#page=N`) 스크린샷 — 실제 사용자가 보게 될 최종 결과물을 그대로 확인 가능
- 이 방법으로 1페이지(표지), 6페이지, 8페이지, 16페이지(에필로그)를 직접 열어봐서 수정 사항이 실제 PDF에 정확히 반영되어 있음을 시각적으로 확인 → 사용자에게 캡처 근거와 함께 "로컬 캐시/예전 파일 문제"라고 재설명

**2차 신고 (사용자)**: 이번엔 실제로 새 문제 발견 — 페이지 하단에 다음 섹션이 충분히 들어갈 만큼 큰 빈 공간이 남는 경우가 많음. 스크린샷으로 정확히 지적함.

**원인 재분석**: 1차 수정 때 추가한 `section.chapter{ break-inside:avoid-page; }`가 과했음 — "챕터 전체를 절대 쪼개지 마라"는 규칙이라, 챕터 하나가 남은 페이지 공간에 다 안 들어가면 **챕터 전체를 통째로 다음 페이지로 밀어버려서** 이전 페이지 하단이 크게 빔. 챕터가 16개나 되고 각각 길이가 짧아서 이 문제가 여러 페이지에서 반복 발생.

**2차 수정**: `section.chapter`의 `break-inside:avoid-page`를 삭제. 대신 `h2.chapter{ break-after:avoid-page; }`만 남겨서 "제목 바로 다음 줄까지는 페이지가 안 갈리게"만 보장. 나머지는 이미 걸어둔 개별 박스 단위 `break-inside:avoid`(프롬프트, 체크리스트, 스텝목록)로 충분히 보호됨. 재렌더링 결과 전체 페이지 수 16 → 14로 줄었고, `screenshot_pdf_page.js`로 여러 페이지를 다시 열어 챕터들이 빈틈없이 이어 붙는 것을 확인.

**교훈**: 인쇄용 CSS에서 `break-inside:avoid`류 규칙은 "이 블록 안에서는 절대 안 쪼개짐"을 보장하지만, 그 대가로 블록이 안 들어가면 통째로 다음 페이지로 이동시켜 빈 공간을 만들 수 있다. **큰 컨테이너(챕터 전체)에는 걸지 말고, 실제로 쪼개지면 보기 안 좋은 작은 단위(리스트 하나, 카드 하나)에만 선택적으로 걸어야 한다.**

**QA 도구화**: `scripts/screenshot_pdf.js`, `scripts/screenshot_pdf_page.js`를 앞으로 다른 Day의 PDF도 실제 파일 기준으로 검증할 때 재사용 (poppler 없이 Chrome 자체 PDF 뷰어를 이용하는 우회법).

## 14. "파일이 안 바뀐다" 재신고 → 실제로는 TOC 박스에 같은 버그가 남아있었음

2차 수정 후에도 사용자가 계속 "똑같다"고 신고. 이번엔 파일명을 아예 다르게(`CHECK_v2_1015.pdf`) 만들어서 캐시 가능성을 원천 차단하고 다시 보냈는데도 "똑같다"는 반응 → `AskUserQuestion`으로 여는 방법을 물어봤으나 "닫았어"라는 답변만 받음 → 사용자가 직접 PDF를 페이지별 PNG로 변환해서 프로젝트 폴더에 저장(`CHECK_v2_1015_페이지_01~14.png`), 1·2번 이미지를 지목.

**직접 확인 결과**: 1페이지(표지)는 정상. **2페이지(프롤로그)도 텍스트 자체는 새 버전이 정확히 반영되어 있었음** ("AI는 더 이상..." 확인됨). 그런데 텍스트 아래로 페이지의 절반 이상이 텅 비어있었음 — 이전에 잡았던 것과 똑같은 유형의 버그가 **다른 곳(TOC 박스)에 남아있었던 것**.

**원인**: `.toc{ break-inside:avoid; }` — 목차 전체(16개 항목)를 절대 안 쪼개지게 강제했는데, 프롤로그 문단들 뒤 남은 공간에 16개 항목이 다 안 들어가니 목차 전체가 통째로 다음 페이지로 밀려나면서 프롤로그 페이지 하단이 크게 비었음. 13번 항목에서 정리한 교훈("큰 컨테이너에 break-inside:avoid를 걸면 안 된다")을 `section.chapter`에는 적용했지만 `.toc`에는 놓쳤던 것.

**수정**: `.toc`의 배경/테두리/둥근모서리 박스 스타일과 `break-inside:avoid`를 제거하고, 대신 챕터 제목과 통일된 `border-top:3px solid gold` 라인만 남김. 개별 항목(`.toc li`)에만 `break-inside:avoid`를 걸어서 목차가 페이지 경계에서 자연스럽게 이어지되(11~16번이 다음 페이지로), 항목 하나가 중간에 잘리지는 않게 함. 재렌더링 결과 프롤로그+목차 앞부분이 2페이지에 함께 들어가고 나머지가 3페이지로 깔끔하게 이어짐. 전체 14 → 13페이지로 추가 압축.

**검증**: `screenshot_pdf_page.js`로 2페이지를 다시 캡처해서 빈 공간이 사라진 것을 직접 확인 후 전달.

**교훈 (13번 항목 보강)**: `break-inside:avoid`를 큰 박스에 걸 때는 "그 박스가 남은 페이지 공간보다 클 수 있는가"를 항상 따져봐야 한다. 프로젝트 전체에서 이런 박스형 컨테이너(둥근 테두리 + 배경)를 새로 만들 때마다 이 문제가 재발할 수 있으므로, **앞으로 다른 Day의 ebook.html을 만들 때도 목차/긴 리스트류 컨테이너는 박스 스타일 대신 border-top 라인 방식을 기본으로 쓸 것**.
