## 진행 과정

### 1. 저장소 상태 점검 및 착수 표시
- `git status`/`git log` 확인 결과 저장소가 **detached HEAD** 상태였고(`git branch -a`로 확인), 로컬 `main` 브랜치 포인터는 Day35 커밋에 머물러 있었음. detached HEAD는 Day41까지의 커밋(12개)을 포함하고 있어 로컬 `main`보다 앞서 있는 것처럼 보였음.
- `git fetch origin main` 후 다시 확인하니 `origin/main`이 이미 detached HEAD와 동일한 Day41 커밋을 가리키고 있었음 — 즉 이전 세션들이 실제로는 정상적으로 push까지 마쳤으나, 로컬 `main` 브랜치 참조만 갱신되지 않고 세션이 detached HEAD로 남아있던 상태였던 것으로 판단(push 실패가 아니라 브랜치 포인터 미갱신 문제). `git checkout -B main origin/main`으로 로컬 `main`을 `origin/main`과 동기화해 정상 상태로 복구.
- `로드맵.md`를 읽고 Day01~41이 모두 "완료", Day42가 가장 앞선 "대기" 항목임을 확인 → 상태를 "진행중"으로 갱신하고 커밋·푸시(작업 시작 표시, `git push -u origin main` 성공).

### 3. 엑셀 계산기·템플릿 5종 설계 및 제작
- 로컬에 `openpyxl`이 없어 `pip3 install openpyxl`로 설치(네트워크 정상 동작 확인).
- 전자책 방법 1~9를 5개 파일로 재구성:
  1. **카테고리별_감가율_적정가_계산기.xlsx** — 5개 카테고리 감가율 참고표(전자기기·가구·의류/신발·유아용품·명품/잡화) + 기준가·적용감가율·상태감점·구성품감점·희소성가점을 입력하면 감가적용가→최종 적정가→네고 포함 등록가까지 수식 체인으로 자동 계산.
  2. **시세밴드_등록가_계산기.xlsx** — 거래완료가 최대 10건 입력 시 `MIN`/`MAX`/`AVERAGE`/`MEDIAN` 자동 집계 + 평균 대비 40% 이상 벗어나면 "이상치 의심" 플래그. 목표 실수령가 입력 시 빠른판매(+5%)/적정가(+7.5%)/최고가(+10%) 3가지 시나리오의 등록가와 네고 마지노선(목표가의 95%) 자동 계산.
  3. **플랫폼별_판매카피_템플릿.xlsx** — "물건정보" 시트에 모델명·구매시기·상태·구성품 등을 한 번 입력하면, 당근마켓/번개장터/중고나라 각 시트에서 `CONCATENATE` 수식으로 제목 후보를 자동 미리보기(플랫폼별로 강조하는 정보가 다르게 구성: 당근=상태, 번개장터=거래방식, 중고나라=구매시기·사유). 본문은 5단 구조(후킹/판매사유/상태구성품/거래방식/마무리) 빈 칸에 AI 판매글을 옮겨 적는 방식.
  4. **가격재조정_끌올_판단표.xlsx** — 경과일수·조회수·채팅·찜 수 입력 시 `IF`+`AND` 조합으로 3가지 신호(채팅 저조/관심 대비 전환 부족/노출 부족) 자동 판정. 현재 등록가 입력 시 1차·2차 인하가(각 −7.5%)와 네고 마지노선(−15%) 자동 계산.
  5. **의뢰접수_상담진행_체크리스트.xlsx** — 접수 질문지(14개 항목) + 접수→리서치→계산→카피작성→납품→사후관리 16단계 체크리스트, `COUNTIF`/`COUNTA`로 진행률(%) 자동 집계.
- 모든 수식은 `openpyxl.load_workbook(..., data_only=False)`로 재오픈해 셀 참조(예: `물건정보!B7`이 실제로 "상태" 필드인지)를 표 형태로 출력해 육안 대조, 초기 작성 시 있었던 셀 참조 오류(당근마켓 제목 수식이 "사용빈도" 필드를 잘못 참조한 것 등) 2건을 발견해 수정.
- `soffice`(LibreOffice)로 수식 재계산 검증을 시도했으나 클라우드 환경에서 `soffice --headless --convert-to`가 트리비얼한 테스트 파일조차 "source file could not be loaded" 오류로 실패(프로필 디렉토리를 새로 지정해도 동일) — 환경 제약으로 판단하고 수식 재계산 검증은 생략, 대신 모든 수식을 셀 참조 단위로 육안 재검토하는 방식으로 대체.

## 이슈/트러블슈팅
- **저장소가 detached HEAD로 시작함.** 세션 시작 시 `git status`가 "HEAD detached from refs/heads/main"을 출력했고, 로컬 `main` 브랜치가 Day35에 머물러 있어 처음엔 "12개 커밋이 push 안 된 것 아닌가" 의심했음. `git fetch origin main`으로 원격을 새로 확인한 결과 `origin/main`이 이미 detached HEAD와 동일 커밋(Day41)이라 실제로는 정상 push된 상태였고, 단순히 로컬 `main` 참조가 갱신 안 된 것뿐이었음. `git checkout -B main origin/main`으로 정상화. **다음 세션도 시작 시 `git branch -a`로 detached 여부를 확인하고, `main`이 `origin/main`보다 뒤처져 있으면 먼저 동기화할 것.**
- **`soffice`(LibreOffice) headless 변환이 이 클라우드 환경에서 동작하지 않음.** 트리비얼한 1셀짜리 xlsx조차 `--convert-to`가 "source file could not be loaded" 오류. 프로필 디렉토리(`-env:UserInstallation=...`)를 새로 지정해도 동일 — 이 세션에서는 엑셀 수식 실행 검증(재계산) 자체가 불가능한 환경 제약으로 판단. 대신 `openpyxl`로 모든 수식 문자열을 셀 좌표와 함께 출력해 참조 정확성을 육안 재검토하는 방식으로 대체 검증했고, 이 과정에서 실제로 2건의 셀 참조 오류를 잡아냄.
- **`poppler-utils`(`pdftoppm`) 미설치, `apt-get install`도 404로 실패.** PDF 여백 검증은 기존 `scripts/screenshot_pdf_page_exact_cloud.js`(Playwright 기반, `#page=N` 해시 이동)로 대체 — 오히려 poppler보다 브라우저 렌더링 그대로를 보여줘 실제 인쇄 결과에 더 가까웠음.
- **연속 스크롤 캡처(`screenshot_pdf_pages_cloud.js`)의 페이지 간 "다크 갭"을 콘텐츠 내부 여백으로 착각할 뻔함.** 뷰어 줌이 68%로 낮게 잡혀 한 스크린샷에 페이지 2개가 걸쳐 보였고, 페이지 사이 뷰어 배경(짙은 회색)을 얼핏 보면 "페이지 내부의 큰 빈 공간"처럼 보임. `screenshot_pdf_page_exact_cloud.js`로 페이지 단위 재캡처해 실제로는 문제없음을 재확인 — **다음 세션도 여백 확인은 반드시 `#page=N` 해시 방식(exact) 스크립트로 할 것, 연속 스크롤 방식은 1차 스크리닝 이상으로 신뢰하지 말 것.**
