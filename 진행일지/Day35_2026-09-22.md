### 4. 콘텐츠 조사 — 2026년 대출·전세 계산 기준
- `WebSearch`로 "2026 전월세전환율 계산법 주택임대차보호법 상한" 조사 — 법정 상한 공식(한국은행 기준금리 + 2%p와 연 10% 중 낮은 값, 2026년 7월 기준금리 2.75% 적용 시 4.75%), 계산식(월세 = 줄어드는 보증금 × 전환율 ÷ 12), 법정 상한은 **갱신 계약에만 강제**되고 신규 계약은 시장 협상이라는 점, 실제 시장 전환율(7.4%)이 법정 기준보다 높다는 점을 확인.
- `WebSearch`로 "2026 주택담보대출 원리금균등상환 원금균등상환 계산법 중도상환수수료" 조사 — 원리금균등 월 상환액 공식(원금 × 월이율 ÷ (1 − (1+월이율)^−개월수)), 중도상환수수료 체감 구조(통상 3년 경과 시 0%, 고정금리 1~3%·변동금리 0.1~0.5% 수준)를 확인.
- 두 조사 모두 수시로 바뀌는 정책 수치라, 책 본문에 특정 숫자를 단정적으로 박아넣기보다 "계산 공식 + 최신 기준은 AI로 재조사" 구조로 서술하기로 결정 (Day33의 수수료 챕터 설계 패턴을 그대로 재사용).

### 5. 콘텐츠 설계 — 11가지 방법 구조
- Day33의 "방법1~9(핵심 방법) + 방법10(흔한 실수) + 방법11(나만의 시스템)" 11단 구조를 그대로 차용해, 대출 계산(원리금균등/원금균등 → 대환대출 비교 → 중도상환수수료)과 전세 계산(전월세전환율 → 갱신 상한 → 전세대출 vs 월세)을 순서대로 배치하고, DSR·대출한도 계산(방법8)과 상담형 부업 수익화(방법9)로 마무리하는 구조를 설계.
- 표지 문구를 Day23("세무사가 아니어도, 계산기는 팔 수 있습니다")의 "자격 없어도 계산은 할 수 있다" 패턴을 이어받아 **"은행원도 아닌데, 대출 계산은 해드릴 수 있습니다"**로 결정 — 대출과 전세 두 주제를 아우르면서도 시리즈 톤(짧고 대비되는 문장)을 유지.
- 이 부업이 법률·투자 자문과 다르다는 점(계산과 정보 정리까지만 제공, 최종 결정은 고객 몫)을 방법1과 방법9에 명시적으로 반복 서술 — 상담형 서비스이니만큼 책임 범위를 처음부터 명확히 하는 것이 중요하다고 판단.
- 프롬프트 15개를 4개 카테고리로 구성: A. 대출 상환 계산(4개) / B. 대환대출·비용 비교(4개) / C. 전세·월세 계산(4개) / D. 상담·서비스화(3개) — Day33의 4색 카테고리 시스템(`.cat`/`cat-b`~`cat-d`)에 1:1로 맞춤.

### 7. PDF 렌더링 및 페이지 여백 검증
- 세션에 `pdftoppm`(poppler-utils)과 `pillow`/`numpy`가 없어서 `apt-get install -y poppler-utils` → `pip install --break-system-packages pillow numpy` 순서로 설치 (Day29 이후 정착된 순서, 이번에도 1차 시도부터 정상 완료).
- `scripts/render_pdf_cloud.js`로 렌더링 → **13페이지** 생성 (Day33과 동일한 페이지 수). `pdftoppm -r 150`으로 래스터화 후 `scan_page_margins.py`로 정량 스캔한 결과, 표지(1p, 37.9%)만 30% 기준을 초과했고 — 표지는 독립 페이지 관례상 정상 — 본문 전체(2~13p)는 7.3%~21.7% 범위로 전부 정상.
- Read 툴로 표지(1p), 흔한 실수 표+나만의 시스템(10p), 프롬프트 그리드 A·B 카테고리(11p), 체크리스트+에필로그(13p) 등 총 4개 페이지를 직접 열어 육안 확인 — 4색 프롬프트 카드, 표(흔한 계산 실수), 원형 배지 체크리스트가 페이지 경계에서 자연스럽게 이어지고 카드가 통째로 다음 페이지로 밀리는 현상이 없음을 확인. Day33 템플릿(카드 구조·패딩 값)을 그대로 재사용한 덕분에 이번에도 여백 문제가 처음부터 발생하지 않음.

### 8. 표지 인쇄 폭(673px) 검증 및 1차 수정
- `scripts/screenshot_element_cloud.js`로 `.cover`를 673×950, deviceScaleFactor 2로 캡처. 최초 버전(`<h1>은행원도 아닌데<br>대출 계산은 해드릴 수 있습니다</h1>`)에서 두 번째 줄이 자동 줄바꿈되며 "있습니다"가 "있습"/"니다"로 **단어 중간에서 갈라지는 문제**를 발견 — 673px 폭에서 두 번째 줄 전체 문장이 한 줄에 들어가지 못해서 발생.
- `<br>`을 하나 더 추가해 `대출 계산은<br><span class="nowrap">해드릴 수 있습니다</span>` 3줄 구조로 수정하고 재렌더링. 673px 스크린샷과 최종 PDF 표지 양쪽 모두에서 "해드릴 수 있습니다"가 한 줄에 깨지지 않고 들어가는 것을 확인. 부제·컨텐츠 프리뷰 숫자("11가지 방법", "15개 프롬프트", "3단계 체크리스트")는 처음부터 `<span class="nowrap">`으로 감싸 작성했기 때문에 추가 수정 불필요.

### 9. 최종 PDF·썸네일 생성
- 수정된 `ebook.html`을 `은행원도_아닌데_대출계산은_해드릴수있습니다.pdf`로 재렌더링(13페이지 유지, 여백 재검증 결과 동일)해 `ebook/`에 저장.
