### 2. 엑셀 계산기 3종 + 체크리스트 1종 설계·제작 (openpyxl)
`python3 -m pip install --break-system-packages openpyxl python-docx pillow numpy`로 먼저 설치(매 Day 반복 보고된 `pip`/`python3` 인터프리터 불일치 패턴 재확인 — 이번엔 처음부터 전부 미설치 상태였음). day52 스타일을 재현하는 공용 헬퍼 모듈(`xlsx_helpers.py`, 스크래치패드)을 먼저 작성해 4개 파일에서 색상·폰트·행 생성 로직을 일관되게 재사용.

- **결혼준비_예산_계산기.xlsx** — 지역별 평균 비용 참고표(한국소비자원 조사) → 예식장 대관료+식대(보증인원 비율 반영) → 스드메 입력(기본가+숨은비용) → 혼수 4분류 입력 → 신혼여행 4항목 입력 → 준비비용 합계 → 하객 관계별(가족·친척/직장동료/친구/지인) 보수적·평균 2가지 축의금 시나리오 → 순지출 → 예비비(12%) 반영 최종예산 → 분담비율 3가지 방식(50:50/전통관례: 신랑측 예식장·신혼여행, 신부측 스드메·혼수/소득비율)까지 전부 수식으로 구현.
- **스드메_비교_계산기.xlsx** — 업체 3~4곳의 기본가·포함 항목(드레스 벌수·2부 포함 여부·메이크업 등급)·숨은 추가비용(원본사진·피팅추가비·리터치비·앨범업그레이드) 입력 → 실질 비교가(기본가+숨은비용) → `INDEX/MATCH`로 최저가 업체 자동 판정. 1차 버전에서 "업체D(직접 입력)"의 기본가를 0원으로 뒀더니 숨은비용도 0이라 항상 최저가로 오판정되는 버그를 발견해, 플레이스홀더 값을 현실적인 숫자(400만원대)로 교체해 해결.
- **신혼집_자금_계산기.xlsx** — 주거 유형(전세/월세/매매)+주택가액+부대비용율 → 초기 필요자금 → 자기자금+양가 부모 증여예정금액 입력 → 혼인증여재산공제(기본공제 5,000만원+혼인증여공제 1억원=최대 1.5억원, 혼인신고 전후 2년 이내 요건 Y/N 드롭다운으로 자동 분기) → 비과세/과세대상 증여액 → 증여세 누진세율표(day52와 동일 0~50% 구간) `VLOOKUP` 적용 → 신고세액공제 3% 반영 최종 납부 증여세 → 부족자금(대출 필요액) → 원리금균등상환(`PMT` 함수) 월 상환액·총 이자액까지 자동 계산. 기본 시나리오를 신랑측 증여 2억원(1.5억 한도 초과)으로 설정해 공제 초과분 과세 로직이 실제로 작동함을 증명(초과분 5천만원에 대한 세액 4,850,000원 — 공교롭게 Day52 증여세 계산기 예시와 같은 금액이 나와 세율표 재사용이 정확함을 교차 확인).
- **결혼준비_체크리스트.xlsx** — '준비타임라인' 시트(예식일 입력 → 예식장 계약 12개월 전~폐백 음식 준비 0.2개월 전까지 12개 항목을 `=예식일-ROUND(개월수*30,0)` 방식으로 역산, day52 신고기한계산기의 EOMONTH 패턴을 날짜 역산 구조로 응용) + '혼수체크리스트' 시트(대형가전·소형가전·가구·생활용품 4분류×5품목=20개 품목, 보유여부/완료여부/선택등급 드롭다운 + `SUMIF`로 신규구매 합계 자동 계산).
- 전체 수식을 LibreOffice(`soffice --headless --calc --convert-to xlsx`)로 재계산해 `data_only=True`로 재로드하는 방식으로 4개 파일 전부 검증 — 수식 오류(#N/A, #VALUE! 등) 없음을 확인. 기본 시나리오 계산 결과(예식장 14,700,000원/준비비용 합계 42,300,000원/예비비 포함 최종예산 47,376,000원/스드메 최저가 4,250,000원/신혼집 증여세 4,850,000원/월 상환액 586,821원/혼수 신규구매 12,400,000원)를 kit.html·마케팅 문서 예시 수치로 그대로 재사용.

- **`pip`/`python3` 인터프리터 불일치 재발** — Day43·45·47~52에 이미 보고된 패턴과 동일하게, 컨테이너에 openpyxl·python-docx·pillow·numpy가 전혀 설치돼 있지 않았음. `python3 -m pip install --break-system-packages openpyxl python-docx pillow numpy`로 한 번에 해결. 매 세션 작업 시작 시 이 패턴을 먼저 점검하는 절차가 계속 유효함을 재확인.
- **스드메 비교 계산기 "업체D(직접 입력)" 0원 플레이스홀더로 인한 최저가 오판정** — 초기 설계에서 업체D(사용자가 직접 입력해서 쓸 빈 슬롯)의 기본가를 0원으로 두었더니, 실질 비교가도 0원이 되어 `INDEX/MATCH` 최저가 로직이 항상 업체D를 "가장 저렴한 업체"로 잘못 판정하는 버그를 LibreOffice 재계산 검증 단계에서 발견. 업체D에도 현실적인 플레이스홀더 값(기본가 400만원+숨은비용 28만원)을 채워 넣어 해결하고, 안내 문구도 "예시이니 실제 견적으로 바꿔 쓰라"로 수정. **교훈** — "직접 입력용" 빈 슬롯이라도 0이나 빈 값을 기본값으로 두면 MIN/MAX/INDEX-MATCH 로직이 의도와 다르게 그 칸을 항상 선택해버릴 수 있으니, 다음 Day에서 비교형 계산기를 만들 때는 플레이스홀더에도 반드시 현실적인 범위의 숫자를 넣고 재계산 검증 단계에서 결과가 상식과 맞는지 확인할 것.
- **신혼집 자금 계산기 기본 시나리오 조정** — 최초 시나리오(신랑측 증여 1억원, 전세 3.5억)에서는 양가 증여액이 모두 혼인증여공제 한도(1.5억) 이내라 과세대상 증여액이 0원으로만 나와 세율표 수식이 실제로 작동하는지 증명되지 않았음. 시나리오를 매매(4.5억)+신랑측 증여 2억원으로 바꿔 공제 한도를 의도적으로 초과시켜, 초과분 5천만원에 대한 증여세 4,850,000원이 정확히 계산됨을 확인 — 비교·공제형 계산기는 기본 입력값을 "한도를 넘지 않는 안전한 값"으로만 두면 핵심 분기 로직이 검증되지 않으므로, 다음에도 한도 초과 케이스를 기본값에 포함시킬 것.
