### 3. 최신 트렌드 조사 (WebSearch)
- "AI 데이터 분석 리포트 자동화 부업 크몽 가격 2026" 검색 — 크몽에 720개의 AI 자동화 프로그램 서비스가 있고, 최저 5,000원부터 시작하는 데이터분석·리포트 서비스가 다수 등록돼 있음을 확인.
- "클로드 코드 인터프리터 엑셀 데이터 분석 리포트 자동 생성 방법" 검색 — 클로드의 파일 분석 기능이 엑셀·CSV를 직접 열어 수식 구조를 이해하고 파이썬 코드 실행으로 집계·시각화까지 처리하는 수준임을 확인. "사용자는 다중 수식을 짜내는 능력보다 데이터를 어떤 방향성으로 분석할지에 대한 기획력만 갖추면 된다"는 논지를 프롤로그/방법1의 핵심 근거로 채택.
- "소상공인 자영업자 매출 데이터 분석 리포트 대행 서비스 AI 활용" 검색 — 중소벤처기업부의 AI 기반 소상공인 매출 예측 서비스가 시범 운영에서 도입 업체 평균 매출 7.2% 상승, 재고 폐기율 34% 감소라는 결과를 냈다는 보도자료를 확인. 이 구체적 수치를 프롤로그와 반박형 홍보글의 신뢰도 근거로 사용.
- **콘텐츠 설계에 반영한 핵심 논지**: "데이터는 이미 쌓이고 있는데, 그걸 리포트로 바꿔줄 시간과 안목이 없는 사람이 대부분"이라는 문제를 표지 카피("그 엑셀, 아무도 안 읽습니다")와 프롤로그의 축으로 삼음. 통계 전문성보다 "AI가 계산한 숫자를 결론으로 바꾸는 순서"를 핵심 가치로 정의해, Day13의 "AI 초안에 지원자 본인 경험을 채워 넣는" 논리 구조를 데이터 분석 도메인에 맞게 재구성.

### 4. 콘텐츠 설계
- 목차를 기존 시리즈와 동일한 16단 구조로 설계: 리포트 유형별 템플릿 → 데이터 클렌징 → KPI 추출 → 시각화 설계 → 인사이트 문장화 → 액션 아이템 → 업종별 맞춤 → 정기 자동화 파이프라인 → 검증·오류체크 → 패키지·가격 → 채널 등록 → 고객응대·정기구독전환.
- 표는 세 곳에 배치: 방법 1(리포트 유형별 핵심지표/주고객), 방법 7(업종별 강조포인트/피해야 할 표현 — 카페·이커머스·마케팅대행·1인창작자 4개 업종), 방법 10(패키지 가격표: 스팟/정기/대시보드/컨설팅 4단계).
- 프롬프트는 데이터 정제·구조화(A) / 지표·인사이트 추출(B) / 리포트 작성·시각화(C) / 운영·가격·확장(D) 4개 카테고리로 설계, **각 카테고리 정확히 4개씩 총 16개**로 처음부터 짝수 설계 — 과거 Day07에서 겪었던 "홀수 카테고리 → 2열 그리드 마지막 줄 카드 1개 단독 → 페이지 하단 빈 공간" 버그 재발을 원천 차단.
- 특히 방법 5(인사이트 문장화)와 방법 9(검증·오류체크)에는 "AI 계산 결과를 과장하지 말고 확인 필요로 표시하라", "합계·비율은 반드시 원본 데이터 일부와 직접 대조하라"는 주의 콜아웃을 넣어, 리포트 대행 서비스의 신뢰도 문제(숫자가 틀리면 신뢰가 무너짐)를 명시적으로 다룸.

## 이슈/트러블슈팅
- **로컬 저장소 detached HEAD**: 세션 시작 시 detached HEAD 상태였음. `git fetch origin main` → `git checkout main` → `git pull origin main`으로 정리. Day13 진행일지에도 동일한 이슈가 기록돼 있어, 클라우드 세션마다 반복되는 패턴으로 보임 — 매 실행 시작 시 습관적으로 fetch+checkout을 먼저 하는 것을 계속 유지.
- **manuscript.md의 콜아웃 문법 불일치**: 초안 작성 시 워크시트 노트를 HTML `<div>`로 넣었다가, 기존 Day들의 manuscript.md가 마크다운 blockquote(`> 참고 —`, `> 주의 —`) 관례를 쓰는 것을 뒤늦게 발견해 정규식으로 일괄 치환. 다음 Day 작성 시 처음부터 blockquote 문법으로 쓸 것.
- **표지 인쇄 폭 검증(673px)**: `.cover`를 673px 뷰포트로 캡처해 확인 — 숫자+단위 조합(12가지 방법, 16개 프롬프트, 3단계 체크리스트, "16개")이 모두 `.nowrap`으로 감싸져 있어 분리되지 않음. 부제 문장도 자연스러운 지점에서 줄바꿈됨. 어색한 줄바꿈 없음.
- **PDF 페이지별 빈 공간 검사**: 14페이지 전부 육안으로 확인. 프롬프트 카테고리를 처음부터 4개씩(짝수) 설계해서 과거(Day07) 겪었던 "홀수 카테고리 → 2열 그리드 마지막 줄 카드 1개 단독 → 페이지 하단 대형 빈 공간" 버그가 이번에도 재발하지 않음. 표가 페이지 경계를 넘어갈 때도 빈 공간 없이 자연스럽게 이어짐을 확인.
- 그 외 렌더링/스크린샷 도구(`render_pdf_cloud.js`, `screenshot_pdf_pages_cloud.js`, `screenshot_element_cloud.js`)는 Day02~14에서 이미 검증된 그대로 문제없이 재사용됨. 특이 오류 없음.
