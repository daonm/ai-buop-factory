### 2. 주제 리서치 (WebSearch)
- "2026년 국민연금 수급 개시 연령 조기노령연금 연기연금 가산율" 검색 → 출생연도별 정상 수급 개시 연령(1969년생 이후 65세, 1953~1968년생은 61~64세로 단계적), 조기노령연금 1년당 6%(최대 5년, -30%) 감액, 연기연금 1년당 7.2%(최대 5년, +36%) 가산 확인. 손익분기 나이는 대체로 70대 중후반으로 알려짐.
- "2026 연금저축 IRP 세액공제 한도 개인연금 노후 수령액 계산" 검색 → 연금저축+IRP 합산 세액공제 한도 연 900만 원(연금저축 단독 600만 원), 공제율은 총급여 5,500만 원 이하 16.5%·초과 13.2%(지방소득세 포함) 확인.
- 두 검색 모두 출처가 블로그 위주라 공식 수치와 오차가 있을 수 있음을 인지 → 책 전체에 "계산 구조를 보여주는 기준값이며 실제 적용 값은 국민연금공단·국세청 고시로 재확인하라"는 안내 문구를 Day59와 동일한 패턴으로 반복 배치하기로 결정 (조기수령 자격요건의 소득기준, 피부양자 탈락 기준 등 검색으로 정확한 수치를 못 찾은 항목은 "~로 알려진 값" 식으로 보수적으로 서술).

### 5. PDF 렌더링 및 검증
- `NODE_PATH=/opt/node22/lib/node_modules node scripts/render_pdf_cloud.js`로 PDF 생성 (A4, 여백 18mm/16mm) → 16페이지.
- `pdftoppm -png -r 150`으로 페이지별 PNG 변환 후 `scripts/scan_page_margins.py`로 하단 여백 비율 스캔.
  - **이슈 발견**: `python3`(기본, 3.11)에 PIL이 없어 1차 `pip install pillow numpy`가 조용히 실패(다른 파이썬 버전 3.13에 설치됨). `python3 -m pip install --break-system-packages pillow numpy`로 현재 인터프리터에 정확히 설치해 해결.
  - 스캔 결과: 1페이지(표지) 43.3%, 16페이지(에필로그) 54.6%만 30% 초과 — 둘 다 설계상 의도된 독립 페이지(표지·책 마지막 페이지)라 정상. 나머지 14개 본문 페이지는 모두 6.8~22.6%로 과도한 빈 공간 없음.
  - Read 툴로 16페이지(에필로그), 2페이지(프롤로그+목차 도입부), 14페이지(프롬프트 15선 A/B/C 카테고리 그리드), 13페이지(14장→15장 전환부)를 육안 확인 — 카테고리별 색상 구분·2단 그리드·배지가 의도대로 렌더링되고, 챕터 전환도 끊김 없이 자연스럽게 이어짐.
- `scripts/screenshot_element_cloud.js`로 `.cover`를 673×950(PDF 실제 인쇄 폭) 뷰포트로 캡처해 육안 확인 — "국민연금·개인연금", "노후 수령액", "계산 대행하는 법" 등 숫자+단위 조합이 `nowrap` 처리되어 어색하게 끊기는 곳 없음.
- 같은 스크립트로 `.cover`를 1000×1000(scale 2)로 캡처해 `marketing/thumbnail.png`로 저장 — 별도 AI 이미지 생성 도구를 쓰지 않고 책 표지 디자인을 그대로 재사용.

## 이슈/트러블슈팅
- `scan_page_margins.py` 실행 시 `ModuleNotFoundError: No module named 'PIL'` — 이 클라우드 세션의 기본 `python3`가 3.11인데, 최초 `pip install pillow numpy`가 다른 인터프리터(3.13, dist-packages)에 설치되어 버전이 어긋남. `python3 -m pip install --break-system-packages pillow numpy`로 현재 실행 중인 인터프리터에 직접 설치해 해결. **다음 Day 작업 시 참고**: `pip install`이 아니라 `python3 -m pip install`로 설치해야 실제 사용할 `python3`에 맞게 들어간다.
- WebSearch 결과가 전부 블로그 출처라 국민연금공단·국세청 공식 수치와 오차가 있을 수 있음 — 책 전체에 "기준값일 뿐이며 실제 적용 값은 반드시 신청 시점 공식 고시로 재확인하라"는 고지를 반복 배치해 리스크를 낮춤 (Day59 패턴과 동일).
