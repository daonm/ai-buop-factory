### 7. PDF 렌더링 및 검증
- `python3 -c "from PIL import Image"` 실행 시 `_imaging` 네이티브 확장 모듈이 깨져 있는 것을 재확인(Day63·65·67·69·71에서 반복된 것과 동일한 증상) → `python3 -m pip install --break-system-packages --force-reinstall --no-deps --ignore-installed pillow numpy`로 즉시 복구.
- `scripts/render_pdf_cloud.js`를 기본 설정(`defaultChromiumDir` 자동 탐지)으로 실행했으나 `chromium-1243/chrome-linux/chrome` 경로가 없다는 오류 발생 — 이번 컨테이너는 디렉터리명이 `chrome-linux64`라 자동 탐지 로직과 어긋남. `PLAYWRIGHT_CHROMIUM_PATH=/opt/pw-browsers/chromium`(시스템 제공 심링크) 환경변수로 재실행해 해결. 이 경로 불일치는 컨테이너마다 Chromium 빌드 디렉터리명이 바뀔 수 있다는 뜻이므로, 다음 실행에서도 자동 탐지가 실패하면 동일한 환경변수 오버라이드를 바로 시도할 것.
- 위 설정으로 (1) `.cover` 673px 폭 검증 스크린샷, (2) 1000×1000·scale 2 썸네일, (3) A4(margin 18mm/16mm) PDF를 모두 생성.
- 생성된 PDF는 16페이지. `pdftoppm -png -r 150`으로 페이지별 PNG 변환 후 `scripts/scan_page_margins.py`(`-I` 플래그)로 하단 여백 비율을 정량 스캔.
  - 스캔 결과: 1페이지(표지) 43.3%만 30% 초과 — 설계상 의도된 독립 페이지라 정상. 16페이지(에필로그, 마지막 페이지)는 21.7%로 기준 이내. 나머지 14개 본문 페이지는 모두 6.8~14.8%로 과도한 빈 공간 없음(Day71과 거의 동일한 수치 분포).
- Read 툴로 PDF 페이지 PNG(4페이지: "시작 전에 3가지"→"근로소득금액 계산하기" 챕터 전환부, 14페이지: 프롬프트 15선 2단 그리드 A·B 카테고리, 16페이지: 체크리스트 3단계→에필로그)를 직접 육안 확인 — 카테고리별 색상 구분(골드/틸/테라코타/올리브)·2단 그리드·원형 배지·챕터 전환이 의도대로 렌더링되고 끊김 없이 자연스럽게 이어짐.
- 673px 폭 캡처로 표지 문구("연말정산 서류 제출하기 전에", "AI한테 환급액부터 물어보세요", "12/15/3 + 단위") 모두 `nowrap` 처리되어 어색하게 끊기는 곳 없음을 확인.
- 1000×1000·scale 2 캡처를 `marketing/thumbnail.png`로 저장 — 별도 AI 이미지 생성 도구를 쓰지 않고 책 표지 디자인을 그대로 재사용.
- PDF 파일명은 `연말정산서류제출하기전에_AI한테환급액부터물어보세요.pdf`로 저장(Day67·69·71의 "~전에_AI한테먼저~.pdf" 네이밍 관례를 그대로 따름).
