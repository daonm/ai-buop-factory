### 4. PDF 페이지 여백 검증 — 실제로 큰 빈 공간 문제 발견·수정
- 1차 렌더링(`render_pdf_cloud.js`) 후 `screenshot_pdf_pages_cloud.js`로 페이지를 훑어본 결과, "A. 카페·베이커리" 카테고리 라벨과 소개 박스(`cat-flow`)만 페이지 하단에 남고, 뒤이은 상세페이지 4단계 표(`domain-block`, `break-inside:avoid`)가 통째로 다음 페이지로 밀리면서 **페이지의 절반 가까이가 빈 공간**이 되는 문제를 발견. 지침에서 경고한 2026-08-21 Day02와 정확히 같은 유형의 문제.
- 원인: `domain-block`(표)과 `prompt-block`(SNS/이메일 카드) 각각에 `break-inside:avoid`가 걸려 있는데, 섹션 전체 패딩·마진이 상대적으로 넉넉해 표가 들어갈 만큼 남은 공간이 자주 부족했음.
- `section.chapter` padding(24px 0 26px → 20px 0 22px), `h2.chapter` margin/padding-top, `.lede`/`p` margin-bottom, `.cat`/`.cat-label`/`.cat-flow` margin·padding, `.domain-block` padding(12px 14px 10px → 9px 12px 7px), 표 셀 padding(7px 11px → 6px 10px), `.prompt-grid`/`.prompt-block` margin·padding을 전반적으로 10~25%씩 줄여 재렌더링.
- 수정 후 페이지 수는 10페이지로 늘었지만(표가 더 이상 통째로 밀리지 않고 대부분 같은 페이지에 붙어 들어가면서 배치가 바뀜), 문제였던 카테고리 A 블록의 빈 공간은 완전히 사라짐 — 카테고리 라벨 다음에 표가 바로 이어지거나, 표까지 통째로 다음 페이지로 넘어가더라도 이전 페이지가 거의 꽉 찬 상태로 끝나도록 개선됨.

### 5. 페이지 검증 방법 이슈 — 스크롤 방식 스크린샷의 오탐
- `screenshot_pdf_pages_cloud.js`(연속 PageDown 스크롤 방식)로 재검증하던 중, 화면에 "빈 공간처럼 보이는" 영역이 실제로는 스크롤 위치가 두 페이지 경계에 걸쳐 있어서 생기는 착시임을 뒤늦게 발견 — 같은 파일을 반복해서 열어봐도 캡처마다 페이지 번호 표시가 다르게 나오는 등 신뢰하기 어려운 결과가 나옴. 또한 이 스크립트는 문서 끝부분에서 PageDown이 더 이상 스크롤을 일으키지 못해 마지막 페이지를 중복 캡처하는 현상도 확인(`md5sum`으로 대조해 page_08~10.png이 동일 파일임을 확인).
- 스크립트 자체 주석에 있던 경고("스크롤 애니메이션 도중 캡처되어 페이지 경계가 어긋난 이미지를 만들 수 있음")를 실제로 재현한 셈. `screenshot_pdf_page_exact_cloud.js`(`#page=N` 해시로 정확히 이동 후 캡처)로 1~10페이지를 개별 캡처해 다시 확인한 결과, 실제로는 10페이지 전부 서로 다른 내용이며 큰 빈 공간 없이 자연스럽게 배치되어 있음을 최종 확인. 앞으로는 스크롤 방식 대신 `screenshot_pdf_page_exact_cloud.js`를 1차 검증 수단으로 우선 사용할 것.

## 이슈/트러블슈팅
- **PDF 빈 공간 문제 재발**: Day02(2026-08-21)에서 이미 겪었던 "표/카드가 break-inside:avoid로 통째로 다음 페이지로 밀리면서 페이지 절반이 비는" 문제가 Day22에서도 그대로 재발했다. 원인은 동일 — 카드 패딩·마진이 넉넉하면 남은 공간에 다음 블록이 못 들어가고 통째로 밀림. 이번에 적용한 수치(도메인 블록 padding 12→9px, 표 셀 padding 7→6px, 섹션·카테고리 마진 전반 10~25% 축소)를 다음 Day 제작 시 처음부터 기본값으로 적용하는 것을 고려할 것 — 특히 표(table)를 포함한 반복 카드가 많은 실습자료에서는 처음부터 더 타이트한 패딩으로 시작하는 편이 안전함.
- **스크롤 방식 PDF 스크린샷의 신뢰성 문제**: `screenshot_pdf_pages_cloud.js`가 페이지 경계에서 스크롤이 애매하게 걸려 같은 파일을 다시 읽어도 다른 내용이 나오는 것처럼 보이는 혼란을 겪음. `screenshot_pdf_page_exact_cloud.js`(`#page=N` 해시 이동)가 훨씬 신뢰할 수 있는 결과를 줬다 — 다음 Day부터는 이 스크립트를 페이지 검증의 1차 수단으로 사용할 것. 다만 이 스크립트도 뷰어 확대 비율이 61%로 자동 설정되어 한 화면에 페이지 1.x개가 걸치므로, "N/10 표시가 있는 페이지"를 화면 상단(뷰포트 최상단)에 걸친 쪽으로 판단하고 하단에 살짝 보이는 다음 페이지 미리보기는 무시하는 방식으로 읽어야 함.
- poppler(pdfinfo 등) 미설치 이슈는 Day21과 동일 — PDF 바이트에서 `/Type /Page` 정규식 카운트로 우회(단, 이 방법은 근사치이며 실제 렌더링 결과와 1~2페이지 오차가 날 수 있음을 이번에 확인 — 최종 페이지 수는 반드시 `screenshot_pdf_page_exact_cloud.js`로 실제 확인할 것).
