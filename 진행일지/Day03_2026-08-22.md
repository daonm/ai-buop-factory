## 진행 과정

### 1. 세션/저장소 상태 점검 — 이전 세션의 Day02 작업이 브랜치에 병합되지 않은 채 고립돼 있던 문제 발견 및 복구
- `git status`/`git branch` 확인 결과 세션이 `HEAD detached` 상태로 시작 (Day02 일지에서 예상했던 대로 재발).
- 그런데 이번엔 단순 detached 상태가 아니라, **로컬 `main` 브랜치가 Day01 시점(커밋 2개)에 멈춰 있고, Day02의 전체 작업(27개 커밋)이 브랜치 연결 없이 detached HEAD에만 존재**하는 것을 발견 — Day02를 진행한 이전 세션이 커밋은 잘 했지만 `main`으로 병합/푸시가 안 된 상태로 세션이 종료된 것으로 추정.
- `git log origin/main..HEAD`로 Day02의 27개 커밋이 origin/main에는 없는지 먼저 확인(당시 로컬 fetch 캐시 기준으로는 없어 보였음) → `git checkout main && git merge --ff-only <detached-HEAD-커밋>`으로 fast-forward 후 `git push` 시도.
- push 결과 "Everything up-to-date" — `git fetch origin main`으로 재확인하니 **실제로는 origin/main에 Day02 작업이 이미 다 올라가 있었고, 로컬의 origin/main 참조만 오래된 캐시였음**을 확인. 즉 데이터 유실 위험은 없었으나, 로컬 `main` 브랜치 포인터 자체가 Day01에 멈춰 있던 건 사실이라 이번에 정상화(fast-forward)함.
- **다음 세션을 위한 메모**: 이 클라우드 세션 환경은 매번 저장소를 새로 준비하면서 로컬 `main` 브랜치 포인터가 최신이 아닐 수 있다. 작업 시작 전 `git fetch origin main && git log main..origin/main`으로 로컬이 origin보다 뒤처져 있지 않은지 반드시 확인하고, 뒤처져 있다면 fast-forward 먼저 할 것.

### 5. PDF 렌더링 및 검증 — 신규 버그 발견 및 수정 (h2.chapter의 `break-after:avoid-page`)
- `scripts/render_pdf_cloud.js`로 1차 렌더링 → `scripts/screenshot_pdf_page.js`(Windows 전용, puppeteer-core)는 이 클라우드 세션에서 쓸 수 없어, 이번에 새로 **`scripts/screenshot_element_cloud.js`**(표지/썸네일 캡처, Playwright)와 **`scripts/screenshot_pdf_pages_cloud.js`**(생성된 PDF를 Chrome 내장 뷰어로 열어 페이지 단위로 스크린샷, Playwright)를 작성. 클라우드 세션에서 앞으로 계속 재사용할 것.
- 표지 문구를 뷰포트 673px(A4 실제 인쇄 폭)로 캡처해 확인 — "12가지 방법", "18개 프롬프트", "3단계 체크리스트" 등 숫자+단위 조합이 이미 `.nowrap`으로 감싸져 있어 어색하게 끊기지 않음을 확인(수정 불필요).
- 1차 렌더링(14페이지) 페이지별 스크린샷 확인 중, "방법 6 — 견적서·인보이스 자동생성" 챕터 제목과 첫 줄만 페이지 하단에 남고 나머지(진행순서 4단계 전체)가 통째로 다음 페이지로 밀리면서 **페이지의 약 60~65%가 빈 공간**으로 남는 문제 발견.
- **원인 규명**: Day01 일지의 교훈("큰 컨테이너에 break-inside:avoid 금지")을 알고 있었기 때문에 `ol.steps`에는 처음부터 `break-inside:avoid`를 걸지 않고 `li`에만 개별로 걸어뒀었는데도 문제가 재발 → CSS를 다시 훑어보니 `@media print` 블록 안에 **`h2.chapter{ break-after:avoid-page; }`** 규칙이 별도로 남아있었음("챕터 제목이 페이지 마지막 줄이 되지 않게" 하려는 의도). 이 규칙 때문에 챕터 제목이 남은 공간에 들어가더라도 "제목 다음에 최소 한 줄이 안 들어가면" 제목째로 통째로 다음 페이지로 밀려나면서 그 앞의 남은 공간이 고스란히 낭비됨.
- **수정**: `h3`의 `break-after:avoid`와 `@media print`의 `h2.chapter{ break-after:avoid-page; }`를 모두 제거. 결과적으로 챕터 제목이 페이지 맨 마지막 줄에 혼자 남는(orphan heading) 경우는 생기지만, "제목+본문 전체가 통째로 다음 페이지로 밀리며 생기는 큰 빈 공간"보다 훨씬 낫다고 판단(지침의 우선순위와 일치).
- 재렌더링 결과 **14페이지 → 13페이지**로 축소, 문제였던 페이지의 빈 공간이 거의 사라짐(제목만 페이지 하단에 남고 바로 다음 페이지에서 본문이 이어짐)을 페이지별 스크린샷으로 재확인.
- 에필로그의 "—끝—" 서명이 혼자 마지막 페이지 전체를 차지하던 것도 `.epilogue` 패딩을 줄여(56px→34px 등) 개선 시도했으나 완전히 흡수되지는 않음 — 다만 이건 "본문 중간의 큰 빈 공간"이 아니라 "책 마지막 장"이라 Day01과 동일한 수준의 관례적 여백으로 판단하고 그대로 둠.
- 최종 PDF(13페이지)를 페이지별로 전부 다시 넘겨보며 카드/섹션 하단에 30% 이상 빈 공간이 남는 곳이 없는지 육안 확인 완료.
- **교훈 (Day01 12~14번 항목에 추가)**: `break-inside:avoid`류 규칙뿐 아니라, 제목 요소의 `break-after:avoid`(-page)류 "다음 페이지로 넘어가지 못하게 막는" 규칙도 같은 방식으로 큰 빈 공간을 유발할 수 있다. **본문 padding/margin을 아무리 줄여도, 이런 "묶어서 이동시키는" break 규칙이 CSS 어딘가(특히 `@media print` 블록처럼 놓치기 쉬운 곳)에 남아있으면 소용없다 — 렌더링 후 실제로 문제가 재발하면, 새로 추가한 CSS뿐 아니라 파일 전체에서 `break-` 관련 규칙을 다시 전부 grep해서 확인할 것.**

## 이슈/트러블슈팅
- **Day02 작업이 origin/main에 병합되지 않은 것처럼 보였던 문제**: 로컬 `main` 브랜치가 Day01 시점에 멈춰 있고 Day02의 27개 커밋이 detached HEAD에만 있는 상태로 세션 시작 → `git checkout main && git merge --ff-only`로 fast-forward. `git push` 결과 "Everything up-to-date"였고 `git fetch` 재확인 결과 실제로는 origin에 이미 반영돼 있었음(로컬 캐시만 오래됨) — 데이터 유실은 없었으나 로컬 브랜치 포인터가 어긋나 있었던 것은 사실이라 정상화함. 원인은 Day02 진행 세션이 커밋 후 병합/푸시 단계를 명시적으로 밟지 않고 종료된 것으로 추정.
- **PDF 페이지 하단 큰 빈 공간 (신규 유형)**: `h2.chapter{ break-after:avoid-page; }`(제목이 페이지 마지막 줄이 되지 않게 막는 규칙)가 `@media print` 블록에 남아있어, 챕터 제목+본문이 통째로 다음 페이지로 밀리며 이전 페이지 60%가 비는 문제 발생. `h3`/`h2.chapter`의 `break-after` 규칙을 모두 제거해 해결(14→13페이지). Day01 일지에 정리된 기존 교훈("큰 컨테이너에 break-inside:avoid 금지")과는 다른 종류의 버그였음 — "제목류 요소의 break-after:avoid(-page)"도 같은 문제를 일으킬 수 있다는 점을 새로 학습.
- 클라우드 세션에는 poppler(pdftoppm)가 없어 PDF를 직접 이미지로 변환할 수 없음(Day01 때와 동일) → Chrome 내장 PDF 뷰어를 Playwright로 열어 페이지 단위 스크린샷하는 방식(`screenshot_pdf_pages_cloud.js`)으로 계속 우회. 다만 PDF 뷰어의 네이티브 UI(#pageNumber 등)는 DOM에 노출되지 않아(플러그인 방식) `PageDown` 키 입력으로만 페이지 이동이 가능했고, 뷰포트를 A4 페이지 비율(1:1.414)에 맞게 설정해야 스크린샷 한 장에 페이지 경계가 뒤섞이지 않고 명확히 보임.
