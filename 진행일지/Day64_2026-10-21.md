### 3. 엑셀 계산기 3종 + 체크리스트 1종 제작 (openpyxl, 수식 직접 작성)
Day62와 동일하게 `python3`/`pip3` 인터프리터 불일치를 피하기 위해 처음부터 `python3 -m pip install openpyxl python-docx pillow numpy`로 설치.

2. **소정급여일수_총수급액_계산기.xlsx** — 회사별(최대 3곳) 재직기간·무급휴직일수를 입력하면 산입가능일수를 합산해 피보험단위기간 180일 충족 여부를 판정하고, 연령·가입기간으로 소정급여일수(120~270일, 50세 기준 매트릭스)를 산정. 1일 구직급여액과 실업신고일을 입력하면 총수급액, 대기기간 7일 종료일, 그리고 4주 단위 수급 구간표(최대 10구간, 소정급여일수에 맞춰 자동으로 구간 수가 조정되고 마지막 구간은 잔여일수만 반영)까지 자동 계산.
3. **조기재취업수당_계산기.xlsx** — 소정급여일수·사용일수·1일 구직급여액을 입력하면 남은 일수가 전체의 1/2 이상인지 판정하고, 충족 시 남은 일수의 1/2×1일 구직급여액으로 예상 수당을 계산. 12개월 고용유지 여부(드롭다운)까지 반영해 최종 지급 가능성을 판정.
4. **실업급여_신청서류_체크리스트.xlsx** — `D-day계산기` 시트(이직일 입력 → 수급기간 시작일·만료일(12개월)·D-day·상태 자동 계산, `EDATE` 수식)와 `신청서류체크리스트` 시트(공통 신청서류 4개·이직사유별 증빙서류 4개·자격 확인서류 3개·신청 일정 3개 = 14개 항목, 드롭다운 데이터검증으로 준비 상태 선택) 2개 시트로 구성.

### 4. 수식 버그 1건 발견·수정
- **4주 단위 수급 구간표의 "구간시작일" 체인 참조 오류** — 2구간부터는 "이전 구간 종료일+1"로 시작일을 계산해야 하는데, 최초 작성 시 파이썬 코드에서 실수로 "이전 구간의 이구간일수(D열)"를 참조(`D{prev_r}+1`)해버려 1차 LibreOffice 재계산 결과에서 2구간 이후 시작일이 전부 "1900-01-29"(엑셀 날짜 체계의 사실상 빈 값)로 깨지는 것을 발견 — "구간종료일"이 있는 E열을 참조하도록(`E{prev_r}+1`) 수정해 재검증. 추가로 소정급여일수를 모두 소진한 이후 구간(8~10구간)에서 종료일/지급액은 비어있는데 시작일만 날짜가 찍히는 사소한 부자연스러움도 발견해, 해당 구간의 잔여일수가 0 이하면 시작일 자체도 공백 처리되도록 조건을 한 번 더 감싸 정리했다.
- 수정 후 재검증 결과 4주 구간표의 합계(총지급일수 180일, 총지급액 11,178,000원)가 총수급액 계산 결과(C22)와 정확히 일치함을 확인.

## 이슈/트러블슈팅
- **세션 시작 시 git 브랜치 꼬임** — 로컬 `main`이 `origin/main`보다 2커밋 뒤처진 상태에서 로드맵 갱신 커밋을 시도해 non-fast-forward로 거부됐다. 원인은 이전 세션이 detached HEAD 상태로 커밋을 남기고 끝난 것으로 추정 — `git checkout main`으로 브랜치를 다시 추적시키고 `git merge --ff-only origin/main`으로 최신화한 뒤 로드맵 수정을 다시 적용해 해결. 데이터 손실 없이 처리했으나, **다음 Day부터는 세션 시작 시 `git status`뿐 아니라 `git branch`로 detached HEAD 여부도 함께 확인할 것.**
- **4주 수급 구간표 수식 버그** — 2구간부터 "구간시작일"이 이전 구간의 "이구간일수" 컬럼을 잘못 참조해 날짜가 전부 깨지는 버그. LibreOffice 재계산 결과를 셀 단위로 눈으로 대조하는 과정에서 발견·수정 — Day62 교훈("수식을 동적으로 문자열 포맷팅할 때는 셀 참조 문자열과 파이썬 변수를 혼동하지 않도록 재계산 값을 셀 단위로 대조할 것")이 이번에도 그대로 적용됐다. 이번엔 변수 혼동이 아니라 "열(컬럼) 혼동"이었다는 점에서 **다중 열로 구성된 구간표 수식을 작성할 때는 각 열이 무엇을 담고 있는지(시작일/일수/종료일/금액) 먼저 표로 정리해두고 체인 참조를 작성하는 습관을 들일 것.**
- **PDF 페이지 하단 빈 공간(카드 밀림)** — "02 패키지 구성 & 검증 워크시트"의 Worksheet 2 카드가 통째로 다음 페이지로 밀리면서 그 앞 페이지(4페이지)에 약 36% 빈 공간이 생겼던 것을, `section.chapter`/`.worksheet`/`.domain-block`/`.task-grid`/`.task-card`/`.checklist-group`의 padding·margin을 1~2px씩 줄여 해결. `scan_page_margins.py` 정량 스캔으로 2~6페이지가 전부 22.8% 이하임을 재확인.
- **python3/pip3 인터프리터 불일치 재발** — `openpyxl`/`python-docx` 설치 시, 그리고 이후 `scan_page_margins.py` 실행을 위한 `pillow`/`numpy` 설치 시에도 Day57~62에서와 동일한 문제가 반복됐다(`python3`는 `/usr/local/bin/python3`, `pip3`는 `/usr/bin/pip3`를 가리켜 서로 다른 인터프리터에 설치됨). `python3 -m pip install` 또는 `/usr/local/bin/python3 -m pip install --force-reinstall`로 명시적으로 현재 인터프리터에 설치해 해결.
