### 3. 리서치(WebSearch) — 프리랜서 견적서·제안서 실무 정보
- "프리랜서 견적서 제안서 작성 방법 2026 AI 활용" 검색 → AI를 활용하는 프리랜서가 그렇지 않은 프리랜서보다 시간당 수입이 높다는 통계, "기존 검증된 템플릿에 AI를 결합해 반복 작업을 자동화"하는 접근이 실무에서 가장 널리 쓰인다는 점 확인 → 이 책의 핵심 원칙("AI는 가격을 대신 정해주는 도구가 아니라 근거를 빠르게 만들어주는 도구")으로 채택.
- "프리랜서 견적서 단가 산정 방법 시급 프로젝트 단가표" 검색 → IT 프리랜서 업계의 M/M(맨먼스)·M/D(맨데이)·M/H(맨아워) 단위 체계와 환산 기준(1MM≈20~22MD, 1MD=8MH, 1MM≈160~176MH) 확인, 견적서 필수 포함 항목(세부내역, 단가, VAT 여부, 계좌·세금계산서, 원천세) 확인, **원천세는 지속적 용역=사업소득 3.3%, 일시적 용역=기타소득 4.4%로 구분**된다는 것 확인 → 방법 1(단가 단위), 방법 5(견적서 구성요소), 방법 8(세금 처리) 챕터에 그대로 반영.
- "ChatGPT Claude 제안서 작성 프롬프트 프리랜서 클라이언트" 검색 → 역할·조건·톤을 구체적으로 지정한 프롬프트가 결과물 품질을 2~3배 끌어올린다는 일반 원칙 확인 → 프롬프트 16개를 작성할 때 각 프롬프트에 "무엇을, 어떤 구조로, 어떤 톤으로"가 명시되도록 설계에 반영.
- **판단**: 검색 결과에서 세율·단가 정보의 "정확한 최신 수치"까지는 확보했으나 개인 상황·경기에 따른 편차가 크므로, Day27의 "특정 날짜·수치를 단정하지 않는" 면책 패턴을 그대로 적용 — 방법 8에 "세법은 자주 바뀌니 실제 신고 전 세무 전문가 확인 필수"라는 worksheet-note를 명시적으로 추가.

### 4. 콘텐츠 설계 — 훅(제목)과 구조
- 제목을 Day25("사진은 있는데, 상세페이지가 없습니다"), Day27("글은 쓰는데, 승인이 안 됩니다")의 대구법 훅 패턴을 계승해 **"일은 잘하는데, 견적은 못 냅니다"**로 설계 — 리서치에서 확인한 "실력은 있지만 가격을 말하는 공정 자체가 없다"는 문제와 정확히 맞아떨어짐.
- 12가지 방법을 "단가 기본 개념 → AI로 단가 산정 → 견적서 구성 → 견적서 작성 → 제안서 구분 → 제안서 작성 → 업종별 차별화 → 세금 처리 → 협상 대응 → 대행 서비스화 → 반려 분석 → 템플릿 시스템화" 순서로 설계 — "가격을 정하는 법(1~4) → 문서를 쓰는 법(5~8) → 실전 대응·확장(9~12)" 3단 구조로 자연스럽게 이어지게 구성.
- 프롬프트 16개를 A(단가·견적 산정)/B(제안서 작성)/C(세금·협상 리스크 대응)/D(운영·대행 서비스화) 4개 카테고리로 나눠 Day27과 동일한 4x4 그리드 구조 유지.

### 6. PDF 렌더링 및 페이지 검증
- 이 세션에 `pdftoppm`(poppler-utils)이 설치돼 있지 않아 `apt-get install -y poppler-utils` 1차 시도 → `apt-get update` 없이 바로 설치해 404 오류로 실패 (과거 로그의 "update 먼저 실행" 교훈과 일치) → `apt-get update` 후 재시도해서 성공. PPA 저장소(`deadsnakes`, `ondrej/php`) 403 경고는 poppler와 무관한 별개 저장소라 무시.
- `scripts/render_pdf_cloud.js`로 렌더링 → **14페이지** 생성.
- `pip install --break-system-packages pillow numpy`로 `scripts/scan_page_margins.py`(절대 잉크 임계값 방식, Day27에서 정리된 버전) 실행 환경 구성 후 정량 스캔 실행 — 표지(1p, 42.8%)·에필로그(14p, 88.0%)를 제외한 본문 12페이지가 8.0%~18.8% 범위로 모두 30% 기준 이내. 표지·에필로그의 큰 여백은 책 관례상 정상(로드맵 지침에도 명시된 예외)이라 문제 없음으로 판단.
- `Read` 툴로 1, 2, 3, 4, 10, 11, 13, 14페이지를 육안으로 확인 — 표지, 목차, 프롤로그, 단가 단위 표, 프롬프트 A카테고리 그리드(2단 배치, 골드 라벨이 `display:table`로 콘텐츠와 분리 없이 자연스럽게 이어짐), 체크리스트 3그룹(원형 배지 "오늘/이번 주/이번 달"), 에필로그까지 페이지 경계에서 카드 잘림이나 라벨-콘텐츠 분리 없이 자연스럽게 이어지는 것을 확인. Day27에서 미리 반영해둔 `.cat-label{ display:table }` 덕분에 분리 버그 재발 없음.

## 이슈/트러블슈팅
- **poppler-utils 1차 설치 실패**: `apt-get update` 없이 바로 `apt-get install -y poppler-utils`를 실행하면 404 오류로 실패함을 재확인(Day26 로그와 동일 패턴). `apt-get update` 선행 후 정상 설치. 앞으로도 poppler 설치가 필요한 세션에서는 항상 `update`를 먼저 실행할 것.
- **PIL(pillow)/numpy 미설치**: `scripts/scan_page_margins.py`가 요구하는 패키지가 이 세션 환경에 없어 `pip install --break-system-packages pillow numpy`로 설치 후 정상 실행. 클라우드 세션마다 매번 재설치가 필요할 수 있음을 인지하고 다음 세션에서도 동일하게 처리할 것.
- 그 외 새로운 디자인/렌더링 버그는 발견되지 않음 — Day26~27에서 정리된 교훈(`.cat-label{ display:table }`, 여백 스캔 절대 임계값, `section.chapter`에 `break-inside:avoid-page` 걸지 않기)이 모두 선반영된 템플릿을 그대로 재사용해 1차 렌더링부터 문제 없이 통과.
