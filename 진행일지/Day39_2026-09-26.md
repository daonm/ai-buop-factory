### 2. 참고 자료 파악 및 주제 설계
- Day39는 로드맵 표 제목 그대로 "유튜브·콘텐츠 수익 구조 분석 및 채널 기획 대행" 전자책. 같은 "계산/진단 대행 부업" 계열이자 가장 최근 완성된 Day37(`products/day37_ai-창업초기비용-손익분기점-계산-대행/`)의 manuscript.md·ebook.html을 구조·분량·톤의 직접 참고 예시로 전체 정독 — 11가지 방법 + 프롬프트 15개(4개 카테고리 A~D, 4/4/4/3구성) + 3단계(오늘/이번 주/이번 달) 체크리스트 뼈대, 표지·목차·프롬프트 카드·체크리스트 CSS 클래스 관례(`--cat-a`~`--cat-d`, `.prompt-grid`, `.worksheet-note`, `.checklist-group` 등)를 그대로 재사용하기로 결정.
- `WebSearch`로 최신 정보 2건 조사해서 본문에 반영:
  - "2026년 유튜브 파트너 프로그램 가입 조건 애드센스 RPM CPM 수익 구조" → 2026년 기준 YPP가 2단계(팬 펀딩: 구독자 500명·공개 업로드 3개·최근 90일 내 3,000시간 시청 또는 300만 쇼츠 조회수 / 전체 광고수익: 구독자 1,000명·4,000시간 시청 또는 1,000만 쇼츠 조회수)로 운영되고, 2027년 2월부터 기준이 상향(1,000명+8,000시간 또는 2,000만 쇼츠)된다는 점, 유튜브가 광고 수익의 약 45%를 가져가고 크리에이터가 55%(RPM)를 받는다는 점, 니치별 RPM 편차(금융/비즈니스 $15~40, 테크 $10~25, 교육 $5~15, 엔터/게임 $2~5, 라이프스타일 $3~8)를 확인. 방법 1(수익 구조 기본 이해)·방법 4(니치별 수익성 진단)·방법 10(YPP 로드맵)에 반영.
  - "유튜브 채널 기획 콘텐츠 전략 니치 선정 방법 2026" → 채널 기획의 5단계(목표 설정→타깃 정의→주제 선정→포맷/제작방법→업로드 일정), 니치 선정이 대형 채널 노출보다 특정 오디언스와의 신뢰가 실제 구매 전환을 높인다는 점, "콘텐츠→팬→구매→재구매" 구조 설계 트렌드를 확인. 방법 6(타깃·포지셔닝)·방법 9(수익 다각화)에 반영.
- 위 조사를 바탕으로 11가지 방법을 설계: ①수익 구조 기본 이해 ②니치별 예상 수익성 진단 ③경쟁 채널 벤치마킹 ④타깃 시청자·포지셔닝 설계 ⑤채널 기획서(컨셉·시리즈·캘린더) ⑥영상 아이디어 30개+제목·썸네일 ⑦수익 다각화(협찬·제휴·멤버십) ⑧YPP 자격요건 진단·로드맵 ⑨채널 기획 컨설팅형 부업 수익화 ⑩흔한 실수 ⑪나만의 컨설팅 시스템. 프롬프트는 A(수익 구조 분석)·B(경쟁·타깃 리서치)·C(채널 기획·콘텐츠)·D(상담·서비스화) 4개 카테고리 × 4/4/4/3개로 총 15개.

### 3. manuscript.md / ebook.html 제작
- `ebook/manuscript.md`: 15개 섹션(시작하며+목차+11가지 방법+프롬프트 15선+체크리스트), 프롬프트 15개, 3단계 체크리스트로 Day37과 동일한 뼈대에 유튜브 수익 구조·채널 기획 내용을 채워 작성.
- `ebook/ebook.html`: Day37 `ebook.html`의 CSS(색상 토큰, Gowun Batang+Noto Sans KR+Nanum Gothic Coding, 라이트/다크 테마, `--cat-a`~`--cat-d` 4색 카테고리, `.prompt-grid` 2단 배치, `.checklist-group`+원형 배지, 표 zebra stripe)를 그대로 복사해 본문만 교체. 표지 카피는 "구독자가 없어도, 유튜브 채널 기획은 대신 해드릴 수 있습니다" / "AI로 유튜브·콘텐츠 수익 구조 분석 및 채널 기획 대행하는 법"으로 신규 작성.

### 4. 표지 인쇄 폭(673px) 검증
- `scripts/screenshot_element_cloud.js`로 `.cover`를 673×950으로 캡처. 숫자+단위 조합("11가지 방법", "15개 프롬프트", "3단계 체크리스트")과 부제의 복합 명사구를 처음부터 `<span class="nowrap">`으로 감싸 작성했기 때문에 별도 수정 없이 한 번에 정상 출력 확인(부제 "채널 기획 대행/하는 법" 줄바꿈은 일반적인 한글 어절 단위 줄바꿈이라 문제로 보지 않음).

### 5. PDF 렌더링 및 페이지 여백 검증
- `scripts/render_pdf_cloud.js`로 렌더링. Day37 진행일지의 트러블슈팅 인수인계에 따라, 처음부터 `scripts/screenshot_pdf_page_exact_cloud.js`(`#page=N` 해시로 정확히 이동해 794×1123px A4 크기로 캡처)를 페이지 1~17까지 순차 실행해 총 14페이지(Chrome 뷰어 툴바 "1/14" 기준)임을 바로 확인 — PageDown 스크롤 방식이나 정규식 기반 페이지 카운트 추정 없이 처음부터 신뢰할 수 있는 방식으로 검증 완료.
- 14페이지 전체를 Read 도구로 육안 확인한 결과: 표지(1p)는 독립 페이지로 정상, 본문 카드(표·`.worksheet-note`·프롬프트 그리드·체크리스트)가 페이지 경계에서 자연스럽게 이어지며 중간에 30% 이상 비는 페이지 없음. 프롬프트 D 카테고리(3개, 12페이지)는 2단 그리드에서 셀 하나가 비지만 이는 Day37과 동일한 의도된 레이아웃(D 카테고리 프롬프트가 3개뿐이라 자연스러운 여백)이라 문제로 보지 않음. 마지막 14p는 에필로그 클로징 문구만 있어 하단 여백이 있으나 시리즈 공통의 책 말미 통상 여백 패턴.
