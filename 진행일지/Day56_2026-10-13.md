### 4. 엑셀 계산기 3종 + 체크리스트 1종 설계·제작 (openpyxl)
스크래치패드에 `make_xlsx.py`를 작성해 4개 파일을 한 번에 생성.

- **반려동물_평생양육비_계산기.xlsx** — 종류별 월평균 양육비 참고표(농림축산식품부 2025년 조사) → 기본 조건(동물 종류/크기/입양경로/예상수명, 드롭다운) → 입양 초기비용(분양·입양비+예방접종+중성화+초기용품, SUM) → 월 고정비(사료·병원·미용·용품, SUM) → 의료비 변동 반영 월 적립 권장액(무사고/사고 시나리오+사고 발생 주기로 가중평균) → 생애주기별(유아기 1년/성년기 1~7년/노령기 7년~예상수명) 총비용 → 돌봄비(펫시터 횟수×기간×단가)+장례비 → 평생 양육비 최종 총액과 월 평균 환산액까지 전부 수식으로 구현.
- **다두사육_비교_계산기.xlsx** — 마리 수+동시진료 할인율 입력 → 항목별(사료·병원·미용·용품·대형용품·돌봄) 1마리 기준 비용과 '규모의 경제' 배율(비례 항목은 1.0에 가깝게, 대형용품·돌봄처럼 규모의 경제가 강한 항목은 0.3~0.35) 입력 → 단순 n배 적용 총액 vs 배율+할인 적용 실제 총액 → 절감액·절감률까지 자동 계산.
- **펫보험_가입여부_비교_계산기.xlsx** — 월 보험료·가입연수·보장비율 입력 → 총 납입액 → 무사고/사고 치료비 시나리오 입력(사고 발생 주기 포함) → 무사고 시나리오·사고 시나리오 각각 가입 시 비용 vs 미가입 시 비용 비교 → 손익분기 연간 치료비·손익분기 사고 횟수까지 자동 계산.
- **반려동물_입양체크리스트.xlsx** — '입양전_준비타임라인' 시트(입양예정일 입력 → 입양경로 상담 45일 전~당일 준비물까지 9개 항목을 `=입양예정일-일수` 방식으로 역산, 동물등록제 의무기한 항목 포함) + '초기용품_체크리스트' 시트(이동·생활/배변·위생/외출·안전/식사·건강/놀이·훈련 5분류×12품목, 보유여부·구매여부 드롭다운 + `SUMIF`로 신규구매 합계 자동 계산).

### 5. 수식 버그 발견 및 수정 — 생애주기 구간 중복 계산
- 1차 검증에서 평생양육비 계산기의 "성년기(1~7년)" 구간 길이 수식을 `=MAX(B13-1-7,0)+6`으로 작성했는데, 예상수명 14년 기준으로 성년기 12년+노령기 7년=19년이 나와 입력한 예상수명(14년)을 초과하는 오류를 재계산 검증 단계에서 발견(유아기1+성년기12+노령기7=20년 ≠ 14년).
- 원인은 "노령기에 포함돼야 할 7년 이후 구간"이 성년기 수식에도 중복 가산된 것. `=MAX(MIN(B13,7)-1,0)`로 수정해 성년기를 항상 "1~7년(최대 6년)"으로, 노령기는 기존 `=MAX(B13-7,0)`을 그대로 둬서 유아기+성년기+노령기 합계가 예상수명(B13)과 정확히 일치하도록 함(14년 기준 1+6+7=14 확인).

## 이슈/트러블슈팅
- **`pip`/`python3` 인터프리터 불일치 재발** — 이전 Day들에서 반복 보고된 패턴과 동일하게, 컨테이너에 openpyxl·python-docx·pillow·numpy가 전혀 설치돼 있지 않았고 `pip`가 `python3`과 다른 인터프리터(3.13 dist-packages)를 바라보고 있었음. `python3 -m pip install <패키지>`로 현재 실행 중인 인터프리터에 정확히 설치해 해결. 매 세션 작업 시작 시 이 패턴을 먼저 점검하는 절차가 계속 유효함을 재확인.
- **생애주기 구간 수식 중복 계산 버그** — 평생양육비 계산기의 "성년기" 구간 길이 수식(`=MAX(B13-1-7,0)+6`)이 예상수명이 7년을 초과하는 모든 경우에 "7년 이후" 구간을 노령기와 성년기 양쪽에 중복 반영해, 구간 합계가 입력한 예상수명을 초과하는 오류를 재계산 검증 단계에서 발견. `=MAX(MIN(B13,7)-1,0)`로 수정해 유아기+성년기+노령기 합계가 항상 예상수명과 정확히 일치하도록 함. **교훈** — 생애주기·구간별 합산형 계산기를 만들 때는 각 구간 길이 수식을 따로따로 검증하지 말고, 반드시 "구간 길이 합계 = 전체 기간 입력값"이 되는지 별도로 교차 확인하는 단계를 둘 것 (다음에도 유사한 구간 분할 계산기에서 재점검).
- **PDF 페이지 하단 대형 공백 — Worksheet 카드 통째로 밀림** — 과제 설명에서 경고한 패턴이 Day56에서도 실제로 재현됨: Worksheet 1 카드 뒤 남은 공간(약 450px 추정)에 Worksheet 2 카드(`break-inside:avoid`)가 들어가지 못해 카드 전체가 다음 페이지로 밀리면서 원래 자리가 40% 가까이 빈 채로 남음. `.worksheet` padding과 `th,td` padding을 각각 2px 안팎 줄여서(13px 16px 10px→11px 15px 8px, 5px 10px→4px 9px) 해결 — 페이지 수는 유지하면서 Worksheet 2가 같은 페이지로 재배치됨. **교훈** — kit.html 작성 시 처음부터 타이트한 padding을 썼더라도, Worksheet/도메인 블록이 섹션 경계 바로 앞뒤에 배치되는 구간은 반드시 margin 스캔 + 육안 확인을 거치고, "확인 필요" 플래그가 뜨면 표지/에필로그처럼 의도된 페이지인지부터 먼저 구분한 뒤 실제 레이아웃 문제라면 padding을 미세 조정해 재렌더링할 것.
- **체크리스트 기본 날짜값이 "오늘" 기준으로 이미 과거가 되는 문제** — D-day 역산형 체크리스트의 예시 날짜를 너무 가까운 미래로 잡으면(처음 설정한 2026-11-15는 오늘 2026-10-13 기준 33일 뒤라, 45일 전 항목이 이미 지나버림) 첫 캡처에서 음수 D-day가 나와 비현실적인 예시가 됨을 LibreOffice 재계산 검증 단계에서 발견, 2027-02-15로 조정. **교훈** — D-day 역산형 계산기의 예시 날짜는 "가장 이른(가장 많은 일수를 빼는) 항목도 오늘 기준 미래가 되는지"를 역산해서 기본값을 정할 것.
