### 3. 엑셀 계산기 4종 설계 — A→B→C 이어받기 구조로 차별화
- Day72(해외주식)는 A·B·C 계산기가 각각 독립적인 반면, 연말정산은 "근로소득금액→과세표준→산출세액→세액공제→결정세액→환급액"이 하나의 긴 체인이라 계산기 3개(A/B/C)가 이전 계산기의 결과값을 다음 계산기 입력 칸에 그대로 옮기는 구조로 설계하기로 결정:
  - **A_소득공제_과세표준_계산기.xlsx** — 연봉·비과세소득 입력 → 총급여·근로소득공제(구간별 자동)·근로소득금액 → 인적공제(기본공제+4종 추가공제, 인원수 입력) → 특별소득공제(보험료 전액+주택자금 한도) → 과세표준.
  - **B_산출세액_세액공제_계산기.xlsx** — A계산기의 과세표준·총급여 값을 입력받아 8단계 누진세율 적용 산출세액 계산 → 근로소득세액공제(산출세액 구간별)·자녀세액공제(인원수)·연금계좌세액공제(총급여 기준 공제율 차등)·특별세액공제(보험료·의료비·교육비·기부금)·신용카드 등 사용액공제(최저사용액 25% 차감 로직)까지 7개 항목 합산.
  - **C_결정세액_환급액_계산기.xlsx** — B계산기의 산출세액·세액공제 합계를 입력받아 결정세액 계산 → 기납부세액과 비교해 환급/추가납부 자동 판정. '가족비교' 시트를 별도로 추가해 부부 등 최대 3인을 나란히 비교할 수 있게 함(전자책 방법 2의 "부부 중 한쪽에만 기본공제" 포인트를 실제로 시뮬레이션할 수 있는 도구로 구현).
  - **D_공제서류체크리스트_경정청구Dday_계산기.xlsx** — Day72의 D(신고기한Dday+서류체크리스트) 패턴을 재사용하되, "신고기한"이 아니라 "경정청구 가능 기한"(법정신고기한으로부터 5년)으로 주제를 바꿔 D-day계산기 시트를 구성. 체크리스트 시트는 연말정산 간소화 서비스 증빙자료 20종(인적공제·특별소득공제·세액공제·신용카드공제·월세공제·기타·제출처·최종확인 8개 구분)으로 재설계.
- 신용카드 등 사용액 공제 수식이 가장 복잡한 부분이라 별도로 설계: 최저사용액(총급여×25%)을 신용카드(15%)→체크카드·현금영수증(30%)→전통시장·대중교통(40%) 순으로 먼저 차감한 뒤, 남는 초과분에만 각 공제율을 적용하는 실제 국세청 계산 순서를 그대로 수식화(`MAX(신용카드-MAX(최저사용액-0,0),0)*0.15 + MAX(체크카드-MAX(최저사용액-신용카드,0),0)*0.3 + ...`).

### 4. 엑셀 계산기 4종 제작 및 수식 검증
- `python3 -m pip install openpyxl python-docx`로 환경 준비(Day72 진행일지에 남겨둔 "python3 -m pip install로 실행 중인 인터프리터에 명시적으로 설치" 메모를 그대로 따름 — 이번엔 바로 성공, 멀티 파이썬 버전 이슈 없었음).
- `openpyxl`로 A~D 4개 xlsx 파일 생성 스크립트(`/tmp/.../scratchpad/build_xlsx.py`, `build_xlsx_b.py`, `build_xlsx_c.py`, `build_xlsx_d.py`)를 작성. 안내 시트(경계 문구) + 계산기 시트(노란 입력칸/올리브 결과칸) 공통 구조로 제작. 예시값은 연봉 48,000,000원·비과세 2,400,000원·배우자+자녀 1명 부양·경로우대 1명을 기준으로 전 계산기에 일관되게 사용.
- `libreoffice --headless --convert-to xlsx`로 4개 파일을 재저장시켜 수식을 강제 재계산시킨 뒤 `openpyxl(data_only=True)`로 다시 읽어 전수 검증(Day72에서 겪은 한글 파일명 인코딩 문제는 이번엔 재현되지 않아 ASCII 우회 없이 바로 변환 성공). 검증 결과:
  - A: 총급여 45,600,000원 → 근로소득금액 33,570,000원 → 인적공제 5,500,000원 → 특별소득공제 3,360,000원 → **과세표준 24,710,000원**
  - B: 산출세액 2,340,000원(15% 구간), 근로소득세액공제 660,000원·자녀세액공제 150,000원·연금계좌세액공제 600,000원·보험료공제 96,000원·의료비공제 424,800원·교육비공제 450,000원·기부금공제 75,000원·신용카드등공제 2,190,000원 → **세액공제 합계 4,645,800원**
  - C: 결정세액 660,000원, 기납부세액 1,150,000원 → **차감징수세액 -490,000원 → 환급 490,000원**
  - D: 귀속연도 2025 입력 시 법정신고기한 2026-05-31, 경정청구 마감일 2031-05-31, 오늘(2026-10-31) 기준 남은 일수 1,673일 — "여유 있음" 판정 정상 작동.
- 신용카드 등 사용액 공제 수식을 손계산으로 교차검증: 최저사용액 11,400,000원(45,600,000×25%), 신용카드 12,000,000원 중 초과분 600,000원×15%=90,000원, 체크카드 5,000,000원 전액(최저사용액 소진됨)×30%=1,500,000원, 전통시장·대중교통 1,500,000원 전액×40%=600,000원 → 합계 2,190,000원으로 엑셀 결과와 정확히 일치 확인.
- A계산기의 "과세표준 값을 B계산기 B2 셀에 입력하라"는 안내 문구가 실제 B계산기 입력 셀 위치(C3)와 달라 틀려있던 것을 발견·수정(`B2` → `C3·C4`로 정정 후 A계산기 재생성).

- `screenshot_element_cloud.js`로 `.cover`를 1000×1000(scale 2)로 캡처해 `marketing/thumbnail.png`로 저장(실제 출력 크기 1600×1354px, Day72·73과 동일한 비율대). 별도 AI 이미지 생성 도구 없이 책 표지 디자인을 그대로 재사용. PDF 파일명은 `연말정산환급액계산대행_실행키트.pdf`로 저장.
- `scan_page_margins.py` 실행 과정에서 시스템 PIL(`/usr/lib/python3/dist-packages/PIL`)이 `_imaging` 바이너리 확장 모듈 누락으로 깨져있는 것을 발견 — `python3 -m pip install --force-reinstall pillow numpy`로 재설치해 해결.

## 이슈/트러블슈팅
- A계산기 안내 문구에서 "B계산기의 B2 셀에 입력하라"고 썼다가 실제 B계산기 입력 셀 위치(C3·C4)와 어긋나있던 것을 LibreOffice 재계산 검증 단계에서 발견·수정. 계산기 간 이어받기 구조를 쓸 때는 "다음 계산기 어느 셀에 입력하라"는 안내 문구도 반드시 실제 셀 좌표와 대조 검증해야 한다는 걸 재확인.
- 시스템 Pillow(`/usr/lib/python3/dist-packages/PIL`)가 `_imaging` 네이티브 확장 모듈 없이 깨진 상태로 설치돼 있어 `scan_page_margins.py` 실행이 즉시 실패 — `python3 -m pip install --force-reinstall pillow numpy`로 재설치해 해결. 다음 Day에서 동일 오류(`cannot import name '_imaging'`)가 재현되면 바로 이 명령으로 해결할 것.
- 신용카드 등 사용액 공제처럼 "최저사용액을 낮은 공제율 항목부터 먼저 차감한다"는 실제 국세청 계산 순서를 수식 하나로 표현해야 해서 수식이 길어졌는데, 손계산 교차검증(2,190,000원)과 엑셀 결과가 정확히 일치해 로직 신뢰도를 확보. 이후 유사한 "단계적 차감" 구조가 필요한 계산기를 만들 때 이번 수식 패턴을 재사용할 수 있음.
- Day72에서 발견해 해결했던 `.worksheet`의 `break-inside:avoid` 중간 페이지 블랭크 문제는 CSS를 그대로 물려받았기 때문에 이번 Day74에서는 재발하지 않음 — 디자인 시스템을 계속 재사용하는 방식의 장점이 실제로 확인됨.
