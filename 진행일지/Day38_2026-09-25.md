### 3. 최신 정보 조사 (WebSearch)
사업자유형 비교 계산기와 사업자등록 체크리스트에 넣을 2026년 기준 정보를 4건 조사:
- 2026년 간이과세자 업종별 부가가치율(소매·음식점 15%, 제조업 20%, 숙박업 25%, 건설·서비스업 30%, 금융·부동산 40%) 및 간이과세 기준금액(연매출 1억 400만원, 부동산임대업 등은 4,800만원)
- 2026년 종합소득세 누진세율(1,400만원 이하 6%부터 10억 초과 45%까지 8단계) 및 법인세율(2억 이하 9%, 2억~200억 19%, 이후 21%/24%) — 검색 결과가 세부 누진공제액까지는 제공하지 않아, 2023년 세법 개정 이후 고정된 표준 8단계 누진공제표(공지된 세율 구간과 일치하는 값)를 그대로 적용
- 2026년 4대보험 사업주 부담률(국민연금 4.75%, 건강보험+장기요양 약 4.06%, 고용보험 약 1.15%, 산재보험 업종별 상이) → 합산 참고치 약 10.9%로 반영, 계산기 안내 문구에 "매년 변경되니 재확인" 명시
- 법인 설립 비용(등록면허세 자본금 1천만원 기준 비과밀지역 112,500원/과밀억제권역 3배 중과, 법원 등기수수료 2~2.5만원, 정관공증 5~30만원, 법무사 대행수수료) → 사업자유형 비교 계산기의 초기 설립비용 비교표 기본값으로 반영

### 4. 계산기 4종 + 체크리스트 1종 설계 및 openpyxl로 제작
Python(openpyxl)으로 5개 파일을 생성하는 빌드 스크립트를 세션 스크래치패드에 작성해 실행(Day34~36 선례를 따라 저장소에는 커밋하지 않음). 공통 스타일 헬퍼(입력 셀/결과 셀/헤더/노트 색상, 테두리)를 함수화해서 5개 파일에 일관되게 적용.
- **A. 초기비용_견적_계산기.xlsx** — 업종·항목별(보증금·권리금·인테리어·설비·초도재고·인허가·마케팅·기타) 예상 금액을 입력하면 소계를 구하고, 예비비율(기본 15%)과 운영자금(손익분기 도달 예상 개월수×월 예상 적자)까지 더한 총 초기비용을 계산.
- **B. 손익분기점_목표매출_계산기.xlsx** — 월 고정비·판매가·개당 변동비·영업일수로 공헌이익률과 BEP 판매량·매출액을 구하고, 목표 순이익(200/300/500만원) 3개 값에 대한 필요 매출액을 역산 비교표로 제공, 마지막에 초기투자금 대비 회수기간까지 계산.
- **C. 인건비_대출상환_현금흐름표.xlsx** — 직원 수·월급·4대보험 사업주부담률(기본 10.9%)로 월 인건비를, 대출 원금·연이율·상환개월수·거치개월수로 PMT 공식 기반 월 상환액을 구해 최종 월 고정비에 합산. 12개월 현금흐름표와 낙관(120%)·중립(100%)·비관(70%) 시나리오, 비관 시나리오에서 운영자금으로 버틸 수 있는 개월수까지 계산.
- **D. 사업자유형_비교_계산기.xlsx** — 예상 연매출·순이익으로 간이 vs 일반과세자 부가세를 비교하고, 종합소득세 8단계 누진세율표(IF 중첩 수식)와 법인세 2단계 세율로 개인·법인 세부담을 비교, 초기 설립비용(등록면허세·법원수수료·정관공증·법무사수수료) 비교표까지 포함. "법인세율이 낮아도 배당소득세가 추가된다"는 주의 문구를 안내 시트에 명시.
- **E. 사업자등록_체크리스트.xlsx** — 개인사업자 등록 7단계, 법인사업자 설립 7단계, 공통 사후관리 4단계(총 18단계)를 순서·준비서류·완료 여부 컬럼으로 정리.

### 5. 계산기 값 검증 — LibreOffice는 이번에도 시도하지 않고 바로 손계산
- Day34~36 진행일지에 이미 "이 클라우드 이미지의 LibreOffice headless 변환이 깨져있다"는 기록이 남아있어, 이번엔 재확인 시도 자체를 생략하려 했으나 혹시 환경이 갱신됐을 가능성을 배제하지 않기 위해 `pip install openpyxl` 직후 `soffice --headless --convert-to csv`로 방금 만든 최소 예제 파일(`/tmp/minimal.xlsx`, 셀 3개짜리)까지 시도 → 여전히 `Error: source file could not be loaded`로 실패, 로케일을 `en_US.UTF-8`로 바꿔도 동일. **3개 세션 연속 재현이므로 이 클라우드 이미지 자체의 문제로 최종 확정**하고 즉시 손계산 검증으로 전환.
- 순수 Python으로 각 계산기의 핵심 수식을 동일한 기본값으로 재계산해 교차검증:
  - A: 항목 소계 1억 4,150만원 + 예비비 15%(2,122만 5천원) + 운영자금(3개월×300만원=900만원) = 총 1억 7,172만 5천원.
  - B: 고정비 500만/판매가 8천원/변동비 3천원 → 공헌이익 5천원, 공헌이익률 62.5%, BEP 판매량 1,000개(=8,000,000원과 일치), 목표 순이익 200만원 시 필요매출 1,120만원(검산: 1,400개×5,000원 공헌이익−500만원 고정비=200만원 ✓).
  - C: 직원 2명·월급 220만원·부담률 10.9% → 월 인건비 4,879,600원. 대출 5천만원·5.5%·60개월 → PMT 약 955,200원. 최종 월 고정비 약 883만원(기존 고정비 300만원 포함). 매출 1,200만원·변동비율 35% 가정 시 월손익 약 -303만원(적자 시나리오 — 사용자가 실제 조건으로 교체해 쓰는 기본 예시임을 README·kit.html에 명시).
  - D: 연매출 8천만원 기준 간이과세(부가가치율 15%) 120만원 vs 일반과세(매입세액 300만원 가정) 500만원, 차이 380만원. 순이익 3천만원 기준 종합소득세 324만원(=3,000만×15%−126만), 법인세 270만원(=3,000만×9%) — 두 값 모두 국세청 고시 표준 세율표와 일치.
  - 모든 값이 상식적인 범위에 들어 수식이 논리적으로 올바름을 확인. 셀 참조 패턴은 Day34~36에서 이미 실제 판매용으로 검증된 형태(`=B4*B9*(1+B9)^B6/((1+B9)^B6-1)` 등)를 그대로 재사용했으므로 Excel/Google 시트에서 정상 작동할 것으로 판단.

### 8. PDF 렌더링 및 페이지 여백 검증
- `scripts/render_pdf_cloud.js`로 렌더링 → **7페이지** 생성. `scripts/screenshot_pdf_pages_cloud.js`(Chrome 내장 PDF 뷰어 스크롤 캡처)로 페이지별 이미지를 확보하고, Read 툴로 1·3·5·6·7페이지를 직접 열어 육안 확인.
- 표지(1p)는 독립 페이지로 정상. 3p(섹션01 계산기 4종 참고표, cat-b/cat-c/cat-d 도메인 블록)는 색상 구분된 카드가 페이지 경계에서 자연스럽게 이어지고 큰 빈 공간 없음. 5p(사업자등록 체크리스트 task-grid 2단 배치)도 개인/법인/공통 그룹이 색상별로 선명하게 구분되며 빈 공간 없이 이어짐. 6~7p(판매 준비 체크리스트 후반+에필로그)는 체크리스트가 한 페이지를 채우고 에필로그는 짧은 클로징 문구만 있어 마지막 페이지 하단이 비는데, 이는 Day34~36에서도 동일하게 확인된 책 말미 에필로그의 통상적인 여백이라 "본문 중간 카드 사이 빈 공간" 문제에 해당하지 않는다고 판단.

- **세션 시작 시 로컬 HEAD가 detached 상태**였음 — `git fetch origin main` → `git checkout main` → `git reset --hard origin/main`으로 정상 복구 후 작업 시작. 원인은 불명확하나(직전 세션 종료 방식 추정) 매 세션 시작 시 `git status -sb`로 브랜치 상태를 먼저 확인하는 습관을 유지할 것.
