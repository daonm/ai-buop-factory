### 2. 엑셀 계산기 3종 설계·제작 (openpyxl)
컨테이너에 openpyxl·python-docx가 python3(3.11) 인터프리터에 설치돼 있지 않아 `python3 -m pip install --break-system-packages openpyxl python-docx`로 먼저 설치(Day43·45·47~51에 반복 보고된 `pip`/`python3` 인터프리터 불일치 패턴 재확인).

- **상속세_계산기.xlsx** — 세율표 참고 → 상속재산(부동산/금융자산/기타재산/채무) 입력 → 상속인 구성(배우자 생존·실제 상속액, 자녀 수, 미성년 자녀 수+평균 잔여연수, 65세 이상 인원) 입력 → 자녀/미성년자/연로자공제 자동 계산 → 기초+인적공제 vs 일괄공제 `MAX()` 비교 → 배우자공제(`MIN(MAX(실제상속액,5억),30억)`) → 과세표준 → `VLOOKUP(...,TRUE)` 근사일치로 세율표 구간 자동 판정 → 산출세액 → 신고세액공제 3% 반영 최종 납부세액까지 전부 수식으로 구현.
- **증여세_계산기.xlsx** — 관계별 공제한도 참고표(배우자 6억/성년자녀 5천만원/미성년자녀 2천만원/기타친족 1천만원) → 이번 증여재산가액 + 10년 이내 기증여재산 합계 + 기존 납부 산출세액 입력 → 10년 합산 과세표준 → 세율표 적용 → **합산 산출세액에서 기존 납부세액을 차감**하는 방식으로 10년 합산과세 로직을 수식으로 명시적으로 구현(단순 차감형이 아니라 실제 국세청 방식인 "합산 후 재계산→기납부세액공제"를 반영).
- **상속_vs_사전증여_비교_계산기.xlsx** — 가장 복잡한 계산기. 시나리오 A(전부 상속)와 시나리오 B(지금 일부 사전증여+잔여 상속)를 각각 계산하고, B에서는 "경과연수 < 합산기준연수(상속인 10년/상속인 외의 자 5년)"일 때만 사전증여재산을 상속재산에 가산하고 이미 낸 증여세액을 상속세 산출세액에서 공제(이중과세 방지)하는 로직을 `IF` 분기로 구현. 마지막에 두 시나리오 총세액 차이와 판정 문구까지 자동 출력.
- **상속증여세_신고서류_체크리스트.xlsx** — '신고기한계산기' 시트(신고유형·기준일·거주자구분 입력 → `EOMONTH`로 그 달 말일 기산 → 신고기한·D-day·상태 자동 계산)와 '체크리스트' 시트(상속세 12종·증여세 10종 구비서류를 완료/미완료 드롭다운으로 체크, 총 22종)로 구성.
- 전체 수식을 LibreOffice(`soffice --headless --convert-to xlsx`)로 재계산해 `data_only=True`로 재로드하는 방식으로 4개 파일 전부 검증 — 수식 오류(#N/A, #VALUE! 등) 없음을 확인. 특히 상속_vs_사전증여 비교 계산기는 기본 입력값(합산 케이스)에서 시나리오A=시나리오B=38,800,000원으로 동일하게 나와, "10년 이내 사전증여는 완전히 합산·공제되어 경제적으로 상속과 동일한 결과가 나온다"는 법 취지를 수식이 정확히 구현했음을 역으로 검증. 경과연수를 10년 밖으로 바꾼 별도 케이스(재산 20억, 사전증여 5억, 12년 경과)에서는 시나리오A 87,300,000원 vs 시나리오B 77,600,000원으로 970만원 차이가 나 "합산 제외 시 사전증여가 유리"한 결과도 확인 — 이 수치를 kit.html 참고표와 threads_posts.md 증거형 글에 그대로 사용.

## 이슈/트러블슈팅
- **`pip`/`python3` 인터프리터 불일치 재발** — Day43·45·47~51에 이미 보고된 패턴과 동일하게, 시스템 `pip install openpyxl python-docx`은 python3.13 dist-packages에 설치되는데 `python3` 명령 자체는 3.11을 가리켜 `ModuleNotFoundError`가 발생. `python3 -m pip install --break-system-packages openpyxl python-docx pillow numpy`로 올바른 인터프리터에 설치해 해결. 매 세션 작업 시작 시 이 패턴을 먼저 점검하는 것이 효율적임을 재확인.
- **kit.html 표 셀 텍스트 길이로 인한 PDF 렌더링 버그** — A(상속세 계산기) 카테고리의 예시 표에 "부동산10억+금융2억+기타0.3억-채무0.5억, 배우자(6억 상속)+자녀2명"처럼 긴 문구를 하나의 셀에 그대로 넣었더니, 4열 테이블의 좁은 열 폭 안에서 글자가 한 글자씩 세로로 쪼개지는 심각한 렌더링 붕괴가 발생(page_margins 스캔에서도 38.9%라는 비정상 수치로 간접 포착됨). day50 패턴처럼 셀 텍스트를 "입력 설명 / 가장 짧은 가능 수치 / 결과 라벨 / 숫자" 식으로 짧게 분리해 2행으로 재구성한 뒤 정상 렌더링됨을 확인. **교훈** — 참고표 셀에 긴 복합 조건문을 한 셀에 몰아넣지 말고, 반드시 day50/49 등 기존 상품의 셀당 텍스트 길이(대략 20자 이내)를 기준으로 분리할 것.
- **상속_vs_사전증여_비교_계산기 기본 입력값 우연 일치** — 초기 예시 입력(재산 15억, 사전증여 3억, 경과연수 7년→합산)에서는 시나리오A와 시나리오B 총세액이 우연히 완전히 같게 나와(둘 다 38,800,000원) 처음엔 "계산기 오류인가" 의심했으나, 수식을 다시 검토한 결과 이는 **10년 이내 합산 시 증여세액공제가 상속세 산출세액을 정확히 상쇄해 경제적으로 사전증여를 안 한 것과 동일해지는 세법 취지를 계산기가 정확히 구현한 결과**임을 확인. 이후 경과연수를 10년 밖(12년)으로 바꾼 별도 케이스로 "합산 제외 시 970만원 차이"라는 명확한 대비 예시를 만들어 kit.html·마케팅 문서에 사용.
