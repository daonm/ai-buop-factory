### 5. PDF 생성 및 페이지 여백 QA
- `scripts/render_pdf_cloud.js`로 1차 렌더링 → 14페이지 생성.
- 페이지별 검증을 위해 기존 `scripts/screenshot_pdf_pages_cloud.js`(연속 스크롤+PageDown 방식)를 먼저 썼으나, 캡처된 이미지 순서가 실제 페이지 번호와 어긋나는 문제를 발견(페이지 간 앵커가 매번 정확히 일치하지 않아 스크린샷-페이지 매핑이 신뢰하기 어려움). 원인 규명에 시간을 쓰는 대신, `file:///경로.pdf#page=N&zoom=page-width` 방식으로 페이지를 하나씩 명시적으로 이동하며 스크린샷하는 새 스크립트(`/tmp/.../screenshot_pdf_each_page.js`, 스크래치패드에만 저장, 저장소에는 커밋 안 함)를 즉석에서 작성해 1페이지=1이미지로 정확히 매핑되도록 함. (첫 시도에서는 같은 문서 내 해시(#page=N)만 바뀌는 네비게이션이 재로딩을 트리거하지 않아 14장 모두 1페이지만 캡처되는 문제가 있었음 → 매 반복마다 `about:blank`를 먼저 거쳐 강제 리로드하도록 수정해서 해결.)
- **발견한 버그**: 4페이지(방법 2 "콘텐츠 캘린더 자동 설계하기") 도입 문단 이후 약 20~25%의 빈 공간이 나타남 — 원인은 `ol.steps { break-inside:avoid; }`가 스텝 리스트 전체를 하나의 쪼갤 수 없는 블록으로 취급해서, 남은 페이지 공간에 리스트 5개 항목 전체가 들어가지 않으면 리스트 전체를 통째로 다음 페이지로 밀어버리는 것이었음(Day01 진행일지 13~14번 항목에서 이미 기록된 것과 동일 계열의 버그).
- **수정**: `ol.steps`의 `break-inside:avoid`를 리스트 전체가 아니라 `ol.steps li`(개별 항목)로 옮김. 이렇게 하면 "항목 하나가 중간에 잘리는 것"만 방지되고, 항목과 항목 사이에서는 자연스럽게 페이지가 나뉠 수 있어 빈 공간이 사라짐.
- 재렌더링 후 14페이지 전체를 다시 1페이지=1이미지로 캡처해서 전수 육안 검사. 4페이지는 리스트가 절반씩 자연스럽게 나뉘며 빈 공간이 사라진 것을 확인. 나머지 페이지 중 8·9·13페이지에 챕터 도입 문단 뒤로 약 20~25% 정도의 여백이 남는 경우가 있었으나 30% 미만이라 지침 기준 내로 판단, 추가 수정 없이 통과. 마지막 14페이지(에필로그)는 책의 끝이라 여백이 남는 게 정상(표지와 마찬가지로 예외).
- **표지 줄바꿈 검증**: `.cover`를 뷰포트 673×950(A4 실제 인쇄 폭 근사치)로 스크린샷해서 확인한 결과, 부제 문장에서 "AI 파이프라인"이 "AI 파이프라\n인"으로 어색하게 끊기는 문제 발견 → `<span class="nowrap">AI 파이프라인</span>`으로 감싸서 수정, 재스크린샷으로 정상 줄바꿈 확인. 숫자+단위 조합("12가지 방법", "15개 프롬프트", "7가지 SNS 톤", "5개 포맷")은 이미 `nowrap`으로 감싸둔 상태라 문제없었음.

## 이슈/트러블슈팅
1. **PDF 페이지별 스크린샷 매핑 오류**: 기존 `screenshot_pdf_pages_cloud.js`(연속 스크롤 + PageDown 방식)로 캡처한 이미지가 실제 페이지 번호와 어긋나는 현상 발견. 급하게 새 파일명 스크린샷 스크립트(`file:///...pdf#page=N&zoom=page-width`, 매 호출 전 `about:blank`로 강제 리로드)를 스크래치패드에 작성해 1:1 매핑을 확보했다. 이 새 스크립트는 저장소에는 추가하지 않음(1회성 QA 도구, 필요시 다음 Day에서 정식으로 `scripts/`에 추가 검토 가능).
2. **페이지 하단 빈 공간 버그(Day02류 재발)**: `ol.steps`에 걸린 `break-inside:avoid`가 리스트 전체를 하나의 쪼갤 수 없는 블록으로 취급해 4페이지에 20%대 빈 공간을 만듦. `break-inside:avoid`를 리스트 전체가 아니라 개별 `li`로 옮겨서 해결. **교훈(Day01 13~14번 항목 재확인)**: 챕터 콘텐츠 안의 리스트류 컨테이너에 `break-inside:avoid`를 걸 때는 반드시 "리스트 전체" 대신 "개별 항목"에 걸어야 한다 — 앞으로 다른 Day의 `ebook.html`을 만들 때도 `ol.steps`, `ul` 등 리스트 컨테이너는 이 패턴을 기본으로 적용할 것.
3. **표지 줄바꿈**: "AI 파이프라인"이 673px 인쇄 폭에서 단어 중간(파이프라\n인)에 끊기는 문제 → `nowrap` span으로 해결. 숫자+단위 조합은 처음부터 nowrap 처리해서 문제없었음.
