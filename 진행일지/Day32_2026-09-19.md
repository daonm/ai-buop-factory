### 5. PDF 렌더링 및 페이지 여백 검증
- `scripts/render_pdf_cloud.js`로 1차 렌더링 → 8페이지 생성. `apt-get update` 선행 후 `poppler-utils` 설치, `pip install --break-system-packages pillow numpy` 설치(이번 세션은 1차 시도부터 정상 완료, Day29~31의 반복된 트러블슈팅 패턴을 그대로 예상하고 순서를 지킨 덕분으로 판단).
- `pdftoppm -r 150`으로 래스터화 후 `scan_page_margins.py`로 정량 스캔 → 표지(1p, 41.3%)·마지막 에필로그 페이지(8p, 87.8%)는 정상 범위(책의 시작·끝 페이지 특성)이나, **본문 중간인 3페이지가 33.4%로 30% 기준을 초과**하는 것을 발견.
- Read 툴로 3페이지를 직접 확인 — 업종 참고표(섹션 01) 끝 + 섹션 02(대표 템플릿) 헤더·리드 문단까지는 3페이지에 들어갔지만, 그 아래 첫 `.prompt-grid`(카테고리 A의 script-block 2개)가 남은 공간에 들어가지 못해 통째로 4페이지로 밀리면서 페이지 하단 1/3이 비는 것을 육안으로도 확인 — 로드맵.md에 명시된 "카드가 통째로 다음 페이지로 밀리는" 문제가 실제로 재현됨.
- **수정**: `section.chapter` padding(20px 0 22px→16px 0 18px), `.domain-block` padding/margin, `.cat` margin-bottom(13px→9px), 표 셀 padding(6px 10px→5px 9px), `.script-block` padding(9px 11px 10px→7px 10px 8px)과 `.script-field`/`.script-caption` 여백을 로드맵 가이드라인(카드 10~15px, margin/gap 9~14px 대역)에 맞춰 전반적으로 줄임.
- 재렌더링 결과 **8페이지 → 7페이지로 축소**, 문제였던 3페이지가 11.8%로 정상화됨을 확인. 나머지 본문 페이지(2~6)도 모두 8.9%~18.9%로 안정적. 1페이지(표지, 41.3%)·7페이지(체크리스트 마무리+에필로그, 52.7%)는 각각 책의 시작·끝 페이지라 정상으로 판단(Day30~31에서도 동일 기준 적용).
- Read 툴로 2~6페이지 전체를 육안 재확인 — 카테고리별 색상 참고표, 2단 script-block 그리드(훅/본론/CTA/캡션/해시태그 5개 필드가 카드 안에 압축되어 잘림 없이 표시), 프롬프트 그리드, 원형 배지 체크리스트가 페이지 경계에서 자연스럽게 이어지는 것을 확인.

### 6. 표지 인쇄 폭(673px) 검증
- `scripts/screenshot_element_cloud.js`로 `.cover`를 673×950, deviceScaleFactor 2로 캡처. 1차 캡처에서 부제 "카페·옷가게·학원·부동산·병원&뷰티 5개 업종 — 그대로 찍는 훅·대본·캡션·해시태그 세트 50개"의 **"그대로"라는 단어가 "그"/"대로"로 줄 경계에서 분리되는 것을 발견** — 숫자+단위 조합은 아니지만 일반 단어가 어색하게 끊기는 사례로, Day30 진행일지의 "숫자+단위 아닌 일반 단어도 육안 확인 필요" 교훈이 그대로 재현됨.
- `<span class="nowrap">그대로 찍는</span>`으로 감싸 수정 → 재캡처해서 "그대로 찍는" 한 단위로 자연스럽게 줄바꿈됨을 확인. "5개 업종"/"50개"(숫자+단위)는 처음부터 nowrap 적용으로 문제 없었음.

## 이슈/트러블슈팅
- **저장소가 detached HEAD 상태로 시작**: Day30·Day31과 동일한 패턴 재현. `git fetch` + `git checkout -B main origin/main`으로 복구. 다음 세션에서도 세션 시작 직후 기본 점검 항목으로 유지할 것.
- **본문 중간(3페이지) 33.4% 빈 공간 실제 재현**: 섹션 헤더+리드 문단 직후 오는 2단 카드 그리드(`.prompt-grid`)가 `break-inside:avoid`로 인해 페이지에 부분적으로 걸치지 못하고 통째로 다음 페이지로 밀리는 현상을 직접 확인·수정. 원인은 새로 추가한 `.script-block`이 기존 `.prompt-block`보다 필드가 많아(훅/본론/CTA/캡션/해시태그 5개) 카드 높이가 커진 것 — 카드 내부 padding·margin을 전반적으로 좁혀 대응. **교훈**: 새 카드 컴포넌트를 추가할 때는 필드 수가 늘어날수록 카드 높이가 커져 페이지 넘김 위험이 커지므로, 처음부터 패딩을 로드맵 가이드라인 하한(10~15px)에 가깝게 잡고 시작할 것.
- 표지 부제의 "그대로" 단어 분리 1건을 제외하고 새로운 디자인/렌더링 버그는 발견되지 않음.
- poppler-utils, pillow/numpy 설치 절차는 이번 세션에 1차 시도부터 정상 완료됨(Day29~31의 반복 트러블슈팅과 달리 순서를 미리 지킨 덕분으로 추정) — 다음 세션에서도 `apt-get update` 선행 → `apt-get install -y poppler-utils` → `pip install --break-system-packages pillow numpy` 순서를 기본값으로 유지할 것.
