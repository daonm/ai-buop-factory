### 6. PDF 렌더링 및 검증
- `/opt/pw-browsers/chromium`과 `NODE_PATH=/opt/node22/lib/node_modules`의 `playwright` 패키지를 사용하는 자체 캡처 스크립트(`capture.js`, 스크래치패드에 작성)로 (1) 673px 표지 검증 스크린샷, (2) 1000×1000·scale 2 썸네일, (3) A4(margin 18mm/16mm) PDF를 한 번에 생성.
- 생성된 PDF는 16페이지. `pdftoppm -png -r 150`으로 페이지별 PNG 변환 후, `python3 -m pip install --break-system-packages --force-reinstall --no-deps --ignore-installed pillow numpy`로 Day63·65·67·69와 동일하게 pillow/numpy 네이티브 확장을 먼저 복구(이번에도 `_imaging` 모듈 깨짐 재발)한 뒤 `scripts/scan_page_margins.py`(`-I` 플래그)로 하단 여백 비율을 정량 스캔.
  - 스캔 결과: 1페이지(표지) 43.3%, 16페이지(에필로그, 마지막 페이지) 38.2%만 30% 초과 — 둘 다 설계상 의도된 독립 페이지라 정상. 나머지 14개 본문 페이지는 모두 7.3~19.9%로 과도한 빈 공간 없음(Day69와 거의 동일한 수치 분포).
- Read 툴로 PDF 페이지 PNG(2페이지: 프롤로그+목차, 5·6페이지: 방법1·2 본문과 취득원가 표, 9페이지: 세율 계산+신고기한 챕터 전환부, 13~16페이지: 흔한 실수 표→프롬프트 15선 2단 그리드→체크리스트 3단계→에필로그)를 직접 육안 확인 — 카테고리별 색상 구분(골드/틸/테라코타/올리브)·2단 그리드·원형 배지·줄무늬 표가 의도대로 렌더링되고, 챕터 전환도 끊김 없이 자연스럽게 이어짐.
- 673px 폭 캡처로 표지 문구("5월에 세금 폭탄 맞기 전에", "해외주식 양도소득세", "계산 대행하는 법", "그대로 쓰는", "해외주식 양도소득세 프롬프트 15개", "12/15/3 + 단위") 모두 `nowrap` 처리되어 어색하게 끊기는 곳 없음을 확인.
- 1000×1000·scale 2 캡처를 `marketing/thumbnail.png`로 저장 — 별도 AI 이미지 생성 도구를 쓰지 않고 책 표지 디자인을 그대로 재사용.
- PDF 파일명은 `5월에세금폭탄맞기전에_AI한테먼저계산시키세요.pdf`로 저장(Day67·69의 "~전에_AI한테먼저~.pdf" 네이밍 관례를 그대로 따름).

- 세션이 main이 아닌 detached HEAD(Day70 작업 커밋 2개 선두)로 시작 — `git checkout main && git pull origin main --ff-only`로 즉시 해결, fast-forward라 충돌 없음. Day65~68에서 반복됐던 것과 같은 유형의 문제라 원인(이전 실행이 브랜치를 옮기지 않은 채 커밋했을 가능성)은 동일하게 추정.
