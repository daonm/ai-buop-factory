### 4. 최신 트렌드 조사 (WebSearch)
- "온라인 강의 커리큘럼 설계 크몽 재능마켓 가격 2026" 검색 — 영상/커리큘럼형 강의 컨설팅이 10만~20만 원대에 형성되어 있고, 1:1 맞춤형은 단가가 높고 그룹형은 인당 단가가 낮다는 시장 구조를 확인. 이를 방법 12(패키지 설계)의 3단계 가격표 근거로 반영.
- "클래스101 인프런 온라인 강의 만들기 AI 커리큘럼 설계 프롬프트" 검색 — 클래스101은 기획안 제출 후 담당자 심사를 거치는 반면 인프런은 자유 업로드형에 개발/IT 분야에 강하다는 플랫폼별 차이를 확인. 이 차이를 방법 1(플랫폼별 특성 표)과 방법 9(플랫폼 심사 통과 기획안) 설계에 반영.
- **콘텐츠 설계에 반영한 핵심 논지**: "잘 아는 것"과 "가르치는 순서로 아는 것"은 다르다는 문제의식을 표지 카피("그 지식, 아직 커리큘럼이 아닙니다")와 프롤로그의 축으로 삼음. 커리큘럼 설계를 "전문가 지식을 인터뷰로 캐내고 AI로 구조화한 뒤, 사람이 그 구조를 검증하는 번역 작업"으로 정의해, Day17의 "AI에게 초안을 맡기고 사람이 다듬는" 논리 구조를 교육 도메인에 맞게 재구성.

### 5. 콘텐츠 설계
- 목차를 기존 시리즈와 동일한 16단 구조로 설계: 플랫폼별 특성 파악 → 인터뷰로 원료 수집 → 학습목표 도출 → 모듈 구조 설계 → 난이도 곡선 설계 → 회차별 상세안 작성 → 실습·과제 설계 → 강의소개 카피 → 플랫폼 심사 기획안 → 파일럿 피드백 개선 → 패키지·가격 → 채널 등록.
- 표는 세 곳에 배치: 방법 1(플랫폼별 등록·심사 방식/적합 분야 — 클래스101·인프런·탈잉·유데미 4개), 방법 11(패키지 가격표: 컨설팅/상세설계/풀패키지/심사대행 4단계).
- 프롬프트는 지식 인터뷰·원료 수집(A) / 커리큘럼 구조·모듈 설계(B) / 회차별 콘텐츠·실습 설계(C) / 운영·가격·판매(D) 4개 카테고리로 설계, **각 카테고리 정확히 4개씩 총 16개**로 처음부터 짝수 설계 — Day15~18 진행일지에 기록된 "홀수 카테고리 → 2열 그리드 마지막 줄 카드 1개 단독 → 페이지 하단 빈 공간" 버그를 원천 차단하는 관례를 그대로 따름.
- 방법 4(난이도 곡선 설계)에는 "전문가는 자기 지식의 난이도를 과소평가하는 경향이 있다"는 주의 콜아웃을, 방법 2(인터뷰)에는 "인터뷰 없이 AI에게만 맡기면 일반론만 나온다"는 주의 콜아웃을 넣어 이 서비스의 핵심 가치(인터뷰 기반 차별화)를 명시적으로 강조.

### 7. 표지 인쇄 폭(673px) 검증 — 문제 발견 및 수정
- `scripts/screenshot_element_cloud.js`로 뷰포트 673px(A4 실제 인쇄 폭)에서 `.cover` 요소 캡처 후 육안 확인.
- **문제 발견**: 부제 문장 "AI로 온라인 강의 커리큘럼 설계 대행하는 법 — 그대로 쓰는 인터뷰·설계 프롬프트 16개"가 673px 폭에서 "대행하" / "는 법 —"으로 줄바꿈되어, 어절("대행하는")이 중간에 쪼개져 보이는 문제 확인. Day17 진행일지에 기록된 "일반 어절도 인쇄 폭에 따라 갈라질 수 있다"는 교훈이 이번에도 그대로 재현됨.
- **수정**: `<span class="nowrap">대행하는 법</span>`으로 감싸 해당 구절이 한 줄 안에서만 등장하도록 강제. 재검증 결과 "AI로 온라인 강의 커리큘럼 설계 대행하는 법 —" / "그대로 쓰는 인터뷰·설계 프롬프트 16개" 2줄로 자연스럽게 나뉘며 어절 중간 분리 없음을 확인.
- **교훈 재확인**: Day17에서 처음 기록된 "숫자+단위 조합뿐 아니라 일반 서술어 어절도 갈라질 수 있다"는 패턴이 이번에도 그대로 발생. 표지 부제를 쓸 때마다 673px 검증을 생략하면 안 되는 이유가 다시 한번 확인됨 — 앞으로도 매번 스크린샷 검증을 기본 절차로 유지.

### 8. PDF 페이지별 육안 검수

- 확인 결과: 표지 부제 2줄 모두 자연스러움. 목차가 2페이지에 걸쳐 나뉘지만 항목이 중간에 잘리지 않고 이어짐. 방법 1(플랫폼별 표), 방법 11(가격표) 모두 골드 헤더+줄무늬로 페이지 경계를 넘어갈 때도 빈 공간 없이 자연스럽게 이어짐. 프롬프트 16개(A~D 4개 카테고리 × 4개)가 2열 그리드에 정확히 맞아떨어져 홀수 잔여 카드로 인한 빈 공간 문제 없음. 체크리스트(16장)의 pill 배지("오늘"/"이번 주"/"이번 달")도 정상 렌더링, 좌측 골드 바와 함께 시각적 앵커 역할을 함.
- 페이지 하단에 30% 이상 비는 페이지 없음. 마지막 14페이지(에필로그)만 "— 끝 —" 한 줄로 끝나는 의도적 여백으로, 시리즈 관례와 동일.

## 이슈/트러블슈팅
- **세션 시작 시 detached HEAD + 미병합·미푸시 커밋 4개 발견**: 직전 세션(Day17·Day18)이 작업을 완료했지만 `main` 브랜치로 병합/푸시하지 못한 채 종료된 것으로 추정. 커밋 내용을 먼저 검증(`git show --stat`으로 산출물 목록 확인)한 뒤 `git merge --ff-only`로 안전하게 병합, 이후 정상 진행. **다음 세션부터는 작업 시작 전에 항상 `git status`·`git log --oneline -20`·`git branch -a`로 detached HEAD 여부와 로컬-원격 동기화 상태를 먼저 점검할 것.**
- **표지 부제 어절 중간 분리(Day17에서 처음 발견된 패턴이 재발)**: 673px 인쇄 폭에서 "대행하는"이라는 어절이 "대행하" / "는"으로 쪼개지는 문제 재현 — `<span class="nowrap">대행하는 법</span>`으로 해결. 숫자+단위뿐 아니라 일반 서술어 어절도 인쇄 폭에 따라 갈라질 수 있다는 점이 두 번째로 확인된 만큼, **표지 부제 작성 직후 673px 검증은 이제 선택이 아니라 필수 절차로 확정.**
- 프롬프트 카테고리를 처음부터 4개씩(짝수) 설계해서 Day07~18에서 겪었던 "홀수 카테고리 → 2열 그리드 마지막 줄 카드 1개 단독 → 페이지 하단 대형 빈 공간" 버그가 이번에도 재발하지 않음.
- 이 환경에 `pdfinfo` 같은 PDF 메타데이터 CLI 도구가 없어, PDF 페이지 수 확인을 Python으로 PDF 바이트 스트림에서 `/Type /Page`, `/Count` 패턴을 직접 카운트하는 방식으로 대체함 (참고용 기록 — 다음에도 같은 방식 사용 가능).
- 그 외 렌더링/스크린샷 도구(`render_pdf_cloud.js`, `screenshot_pdf_pages_cloud.js`, `screenshot_element_cloud.js`)는 Day02~18에서 이미 검증된 그대로 문제없이 재사용됨. 특이 오류 없음.
