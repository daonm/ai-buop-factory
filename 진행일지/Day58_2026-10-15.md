## 진행 과정

### 1. 저장소 상태 점검 및 밀린 커밋 정리
- 세션 시작 시 `git status`가 `HEAD detached from refs/heads/main` 상태였고, `git log`를 보니 detached HEAD(`7cac556`, Day57 완료 커밋)가 로컬 `main` 브랜치(`b2d72b5`, Day55에서 멈춤)보다 2커밋(Day56 작업시작/완료) 더 앞서 있었음 — Day42~57에 거의 매일 반복되는 패턴(로컬 main 참조만 갱신이 안 됨)과 동일.
- `git checkout main && git merge --ff-only 7cac556`으로 로컬 main을 fast-forward. `git push`를 실행했더니 "Everything up-to-date" — `git fetch origin main`으로 재확인한 결과 origin/main은 이미 `7cac556`(Day57까지)으로 최신이었음. 즉 이번엔 로컬 main 포인터만 밀려 있었고 원격 푸시 자체는 이전 세션에서 이미 정상적으로 끝나 있었던 것으로 확인.
- `로드맵.md`를 읽고 Day58(AI로 재산세·종합부동산세 계산 대행 — 계산기+절세체크리스트 템플릿팩, 실습자료)이 "대기" 상태인 첫 행임을 확인. Day53~62 큐는 2026-10-10에 이미 추가되어 있어 신규 주제 추가 단계 없이 바로 진행.
- Day58 행을 "진행중"으로 갱신 후 커밋·푸시(작업 시작 표시, 1단계 커밋).

### 3. 엑셀 계산기 3종 + 절세체크리스트 설계·검증
- `openpyxl`로 4개 파일 생성: `재산세_계산기.xlsx`(과세표준→세율→도시지역분·지방교육세→세부담상한 최종 고지액), `종합부동산세_계산기.xlsx`(과세대상판단→과세표준→세율→고령자·장기보유공제→이중과세조정 최종 순액), `단독명의_vs_공동명의_절세비교_계산기.xlsx`(1인 단독명의 vs 부부 공동명의 50:50 종부세 비교), `재산세_종부세_절세체크리스트.xlsx`(주요일정계산기 시트 + 절세체크리스트 시트, 재산세5/종부세5/공통2 총 12개 항목).
- 재산세 세율표(4단계 누진, 일반 0.1~0.4%/1세대1주택 특례 0.05~0.35%)와 종부세 세율표(2주택이하/3주택이상, 7단계 누진)는 Day57 책에 서술된 구조를 바탕으로 누진공제액을 직접 구간 경계에서 연속이 되도록 역산해 채움(예: 재산세 3억 구간 경계에서 일반세율 적용액과 다음 구간 세율 적용액이 정확히 일치하도록 누진공제액 계산).
- 세션 환경에 `openpyxl`·`python-docx`가 없어 `python3 -m pip install openpyxl python-docx`로 설치. 이 과정에서 Day57 진행일지에 기록된 것과 동일한 문제(시스템에 `python3.11`/`python3.13`이 공존해 `pip install`이 엉뚱한 인터프리터에 설치되는 현상)를 다시 겪어, `python3 -m pip install`(현재 실행 중인 인터프리터에 직접 설치하는 방식)로 바꿔 해결 — Day57이 남긴 "다음 세션에서 동일 에러가 재발하면 python3/pip3가 가리키는 인터프리터가 다를 수 있다는 점부터 의심할 것"이라는 메모가 정확히 들어맞음.
- **수식 검증**: `libreoffice --headless --convert-to csv`로 각 계산기를 실제로 재계산시켜 수동 계산값과 전부 대조. 재산세 계산기(공시가격 10억·1세대1주택·도시지역)는 과세표준 4.5억→세부담상한 적용 전 합계 2,034,000원으로 수기 계산과 일치, 종부세 계산기(공시가격합계 15억·1세대1주택·보유8년)는 최종 종부세 순액 720,000원, 절세비교 계산기(공시가격합계 20억)는 공동명의가 2,160,000원 유리, 절세체크리스트의 주요일정계산기는 오늘 날짜(2026-10-15) 기준 종부세(12/15)까지 D-day 61일로 정확히 계산됨을 확인. `libreoffice`는 이 환경에 사전 설치되어 있어 별도 설치 불필요했음 — **앞으로 수식 기반 xlsx를 만들 때는 매번 `soffice --headless --convert-to csv`로 재계산 검증하는 것을 표준 절차로 삼을 것**.
- 검증 과정에서 절세체크리스트의 "신용카드 무이자할부 행사 기간" 항목에 `行사`라는 깨진 한자가 섞여 들어간 것을 CSV 출력에서 발견, 정규식(`[一-鿿]`)으로 전체 생성 스크립트와 산출물 텍스트 파일을 스캔해 추가 오염이 없는지 확인 후 "행사"로 수정 — Day57이 매 Day 공통 점검으로 유지해온 오타 스캔 패턴(`핸들|빠뜻|쪻|젴`)에 이 사례를 참고해 CJK 유니코드 블록 전체 스캔으로 확장 적용.

## 이슈/트러블슈팅
- **로컬 `main` 브랜치 참조 정체** — Day42~57에서 거의 매번 보고된 패턴이 이번에도 재발(로컬 main이 Day55 커밋에 멈춰 있고 detached HEAD·origin/main은 Day57까지 최신). `git checkout main && git merge --ff-only <최신커밋>`으로 해결. 이번엔 `git push`가 바로 "Everything up-to-date"를 반환해, 원격 자체는 이미 정상이고 로컬 포인터만 갱신이 안 됐던 경우였음을 확인 — 매 세션 시작 시 `git fetch origin main` 후 로컬 main과 비교하는 절차를 계속 1순위로 유지할 것.
- **pip install이 다른 Python 인터프리터에 설치되는 문제 재발** — Day57에서 이미 겪은 `python3`(3.11)과 `pip3`(3.13행)가 가리키는 인터프리터가 다른 문제가 `openpyxl`·`python-docx` 설치 시에도 동일하게 재발. `python3 -m pip install <패키지>` (현재 실행 중인 인터프리터에 직접 설치) 방식으로 즉시 해결 — 이 방식을 표준 설치 절차로 다음 세션에도 그대로 사용할 것.
- **엑셀 수식 자체 검증 방법 신규 확립** — 지금까지 Day들의 진행일지에는 "예시 조건으로 손으로 계산해 대조했다"는 서술만 있었는데, 이번엔 이 환경에 `libreoffice`(soffice)가 사전 설치되어 있는 것을 발견해 `soffice --headless --convert-to csv`로 실제 LibreOffice 수식 엔진이 재계산한 값을 CSV로 뽑아 자동 검증하는 절차를 추가했음. 이 방식이 수작업 계산 대조보다 훨씬 빠르고 정확해, **앞으로 수식이 들어간 xlsx를 만드는 모든 Day에서 이 절차(계산기 시트만 분리한 임시 사본을 만들어 `soffice --headless --convert-to csv`로 변환 후 결과값 확인)를 표준으로 사용할 것을 다음 세션에 권장**.
- **생성 스크립트 내 오타(`行사`) 발견** — 절세체크리스트의 한 항목 설명에 "행사"를 쓰려다 유사 한자 `行`이 섞여 들어간 것을 LibreOffice CSV 검증 과정에서 발견. 정규식(`[一-鿿]`)으로 모든 생성 스크립트와 산출물을 스캔해 추가 오염이 없음을 확인 후 수정 — 기존에 Day57이 유지해온 특정 오탈자 패턴(`핸들|빠뜻|쪻|젴`) 그렙 점검을, 이번부터는 "CJK 한자 유니코드 블록 전체 스캔"으로 일반화해서 앞으로도 매 Day 공통 점검 단계에 포함시킬 것을 권장.
