### 0. 세션 시작 시 발견한 이슈 — 로컬/원격 git 상태 확인
작업을 시작하기 전 `git status`를 확인했는데, 현재 컨테이너의 HEAD가 detached 상태였고 로컬 `main` 브랜치 포인터는 Day08 시점(`c71fc17`)에 멈춰 있는 반면 detached HEAD는 Day09~11까지 진행된 커밋(`8abf533`)을 가리키고 있어, 로컬 `main`이 origin과 3일치 뒤처진 것처럼 보였다. `git fetch origin main`으로 재확인한 결과 **실제로는 origin/main이 이미 Day11(`8abf533`)까지 정상 반영되어 있었고**, 로컬의 원격 추적 참조(`remotes/origin/main`)가 fetch되지 않아 오래된 상태로 표시되었을 뿐 — 유실은 없었다. `git checkout main && git merge --ff-only 8abf533`로 로컬 main을 detached HEAD와 맞춘 뒤 확인차 `git push`했으나 "Everything up-to-date" 응답으로 이미 반영되어 있었음이 재확인됐다. 실제 작업(Day12) 착수 전 상태 정리 차원의 조치였고, 데이터 유실은 없었다.

## 이슈/트러블슈팅
1. **로컬 git 브랜치가 origin보다 뒤처진 것처럼 보인 문제**: 위 "0. 세션 시작 시 발견한 이슈" 참고. 원인은 fetch 미실행으로 인한 원격 추적 참조 캐시 오래됨이었고, 실제 데이터 유실은 없었음. 앞으로 세션 시작 시 `git status`만으로 판단하지 말고 `git fetch origin main` 후 비교할 것.
2. **페이지 하단 빈 공간 버그(Day02·Day11류 재발)**: 인트로 섹션에 문단을 하나 더 추가했다가 워크시트1 카드 전체가 다음 페이지로 밀리며 65~70%의 빈 공간이 생김. Day02 원본과 동일한 길이로 인트로를 다시 압축해서 해결. **교훈(Day01 13~14번, Day11 항목 재확인)**: 레퍼런스 파일(day02 kit.html)을 재사용할 때는 구조뿐 아니라 **텍스트 분량까지 원본과 비슷하게 유지**해야 페이지 나눔이 깨지지 않는다. 원본보다 문단을 늘리면 그 페이지 이후의 카드 배치가 통째로 밀릴 수 있으므로, 부득이하게 문단을 추가한다면 반드시 재렌더링 후 여백을 재검증할 것.
