### 3. 계산 로직 중 두 가지를 WebSearch 서브에이전트로 사실 검증
Day65 전자책 본문에서 "일정 기한 이내"·"재산등급별 점수표(수시 고시)"처럼 의도적으로 뭉뚱그려 둔 두 수치를, 실습자료는 "바로 쓸 수 있는 결과물"이어야 하므로 정확한 값으로 확정하기 위해 백그라운드 조사 에이전트 2개를 병행 실행했다.
1. **임의계속가입 신청기한·자격·유지기간** — law.go.kr·nhis.or.kr 원문 접속이 세션 네트워크 문제로 막혀(WebFetch DNS 오류) 2차 자료(블로그·뉴스) 교차검증으로 확인: 신청기한은 퇴직일이 아니라 "지역가입자로서 최초로 고지받은 보험료 납부기한으로부터 2개월 이내"(국민건강보험법 제110조), 자격 요건은 "퇴직일 이전 18개월 중 직장가입자 보험료 납부 기간 통산 1년 이상", 최대 유지기간은 36개월(2018년 24개월→36개월로 재확대, 이후 추가 개정 확인 안 됨). 이 세 수치를 `임의계속가입_유불리_비교_계산기.xlsx`와 `건강보험_전환대응_체크리스트.xlsx`의 수식에 그대로 반영.
2. **재산등급별 점수표(2024년 2월 개편, 1억 원 공제 후 기준) 60등급 전체 구간·점수, 점수당 금액** — 역시 WebFetch 장애로 WebSearch 스니펫 교차검증에 의존했으나, nhis.or.kr 공식 페이지 스니펫에서 상당수 등급(1~22등급, 31~51등급, 60등급)을 직접 확인했고, 중간 구간(23~30, 52~59등급)은 앞뒤로 확인된 두 등급 사이의 등비(금액)·등차(점수) 패턴이 소수점까지 정확히 들어맞아 신뢰도 높은 수학적 재구성으로 보완. 점수당 금액은 2026년 기준 **211.5원**(공단 공식 공지 페이지로 직접 확인, 상한액 4,591,740원·하한액 20,160원도 함께 확인)으로 확정 — Day65 전자책의 "약 208~211원", "약 459만 원"이라는 뭉뚱그린 서술과도 수치상 정확히 일치함을 재확인. 자동차보험료가 2024년 2월부터 완전 폐지된 것도 복수 언론 보도로 재확인.
- 두 에이전트 모두 보고서에 "네트워크 제약으로 원문 직접 대조 실패, 2차 자료 교차검증에 의존했으니 실무 적용 전 재확인 권고"라고 스스로 명시했다 — 계산기 안내 시트와 README, 상세페이지 카피에도 이 불확실성을 반영해 "일부 구간은 공개 자료를 바탕으로 재구성한 근사값"이라는 문구를 넣고, 참고용 추정 도구라는 면책을 더 강하게 명시했다.

### 4. 엑셀 계산기 3종 + 체크리스트 1종 제작 (openpyxl, 수식 직접 작성)
Day64와 동일하게 `python3 -m pip install openpyxl python-docx pillow numpy`로 현재 인터프리터(`/usr/local/bin/python3`)에 명시적으로 설치.
1. **피부양자_자격판정_계산기.xlsx** — 연간 소득 5종(사업·근로·연금·금융·기타) 합계를 소득 기준(2,000만 원)과 비교하고, 보유 재산세 과세표준 3종 합계를 재산 기준(9억 원 또는 5.4억 원+소득 1,000만 원)과 비교해 각각 판정한 뒤, 둘 중 하나라도 초과하면 "지역가입자 전환 대상"으로 종합 판정.
2. **지역가입자_건강보험료_계산기.xlsx** — 연간 종합소득÷12×7.19%로 월 소득보험료를, 재산세 과세표준에서 1억 원 공제 후 별도 "점수표" 시트(60등급 VLOOKUP 테이블)를 참조해 재산 점수를 구하고 점수당 211.5원을 곱해 월 재산보험료를 계산. 둘을 합산한 건강보험료에 장기요양보험료율(12.95%)을 곱해 장기요양보험료를 더하고, 월 상한액(4,591,740원)·하한액(20,160원)을 적용한 최종 월 납부액까지 자동 계산. 예시(연 소득 3,000만 원, 재산과표 3억 원)로 월 소득보험료 179,750원·월 재산보험료 128,803.5원(재산점수 609점)·장기요양보험료 39,957.68원·최종 월 납부액 348,511.18원을 확인.
3. **임의계속가입_유불리_비교_계산기.xlsx** — 퇴직일 이전 18개월 중 직장가입자 보험료 납부 기간(개월)이 12개월 이상인지로 신청 자격을 판정하고, 퇴사 직전 보험료와 지역가입자 전환 시 예상 보험료(위 계산기 결과를 그대로 입력)를 비교해 유리한 쪽과 36개월 예상 절감액을 계산. 지역가입자 전환 후 최초 고지서 납부기한에 2개월을 더해 신청기한·D-day를 계산하고, 자격 취득일에 36개월을 더해 유지 만료 예상일까지 계산. 예시(18개월 중 재직 14개월, 퇴사 직전 보험료 135,000원, 지역가입자 예상 보험료 348,511원)로 월 차액 213,511원·36개월 예상 절감액 7,686,396원·"임의계속가입이 유리" 판정을 확인.
4. **건강보험_전환대응_체크리스트.xlsx** — `D-day계산기` 시트(고지서 수령일 입력 → 이의신청 기한(수령일+90일, 국민건강보험법 제87조)·D-day·상태 자동 계산)와 `전환대응체크리스트` 시트(공통 점검 4개·퇴사 시나리오 4개·은퇴 시나리오 3개·피부양자 탈락 시나리오 3개 = 14개 항목, 드롭다운 데이터검증으로 준비 상태 선택) 2개 시트로 구성.
- **모든 수식을 LibreOffice headless로 실제 재계산해 검증** — `soffice --headless --convert-to xlsx`로 왕복 변환 후 `data_only=True`로 캐시된 계산값을 읽어 4개 파일 전체에 수식 오류가 없는지 확인. VLOOKUP을 포함한 재산보험료 계산까지 수동 계산값(609점×211.5원=128,803.5원)과 정확히 일치함을 재확인.

- **컬럼 배치 버그** — `건강보험_전환대응_체크리스트.xlsx`의 D-day계산기 시트에서 컬럼 너비(B=2/C=42/D=22)와 실제 셀 쓰기 좌표(라벨 B열, 값 C열)가 어긋나는 버그를 작성 직후 코드 리뷰로 발견·수정. Day64의 "열 혼동" 교훈이 이번엔 "수식의 셀 참조"가 아니라 "레이아웃 설계와 실제 쓰기 좌표의 불일치"로 재발 — **다음부터는 column_dimensions를 설정하는 줄 바로 아래에 "라벨=N열, 값=N+1열"처럼 주석으로 명시해두고 작성할 것.**
- **PDF 페이지 하단 빈 공간(카드 밀림), Day64 템플릿을 그대로 복사했음에도 재발** — Day64의 `kit.html`은 이미 한 차례 패딩을 줄인 수정본이었는데도, Day66은 섹션별 텍스트 분량 차이로 "02 패키지 구성 & 검증 워크시트"의 Worksheet 2 카드가 다시 다음 페이지로 밀리며 4페이지에 약 34% 빈 공간이 발생했다. `section.chapter`/`.worksheet`/`.domain-block`/`.task-grid`/`.task-card`/`.checklist-group`의 padding·margin을 추가로 1~2px씩 더 줄여 해결 — **"이전 Day의 이미 수정된 CSS를 복사해왔다"는 것이 이번 Day의 페이지 분할도 안전하다는 보장은 아니므로, 매 Day마다 `scan_page_margins.py` 정량 스캔은 생략하지 말고 반드시 실행할 것.**
- **재산등급별 점수표·임의계속가입 신청기한 조사 중 WebFetch 네트워크 장애** — 두 조사 에이전트 모두 `law.go.kr`·`nhis.or.kr` 원문에 WebFetch/curl로 직접 접속하지 못하고(DNS 오류) WebSearch 스니펫 교차검증에 의존했다. 다행히 재산등급표는 양 끝(1~22등급, 31~51등급, 60등급)이 공식 스니펫으로 확인되고 중간 구간은 등비·등차 패턴이 소수점까지 정확히 들어맞아 재구성 신뢰도가 높았고, 임의계속가입 수치(2개월/18개월 중 1년/36개월)도 여러 독립 출처에서 일관되게 확인됐다. 그래도 **계산기 안내 시트·README·상세페이지에 "일부 구간은 공개 자료를 바탕으로 재구성한 근사값"이라는 문구를 명시적으로 추가**해 불확실성을 숨기지 않았다 — 다음 Day에서도 유사하게 WebFetch가 막히면 같은 방식(교차검증 + 불확실성 명시)으로 대응할 것.
- **python3/pip3 인터프리터 불일치 재발** — `openpyxl`/`python-docx`/`pillow`/`numpy` 설치 시 Day57~64에서와 동일한 문제가 반복됐다(`python3`는 `/usr/local/bin/python3`, `pip3`는 `/usr/bin/pip3`를 가리켜 서로 다른 인터프리터에 설치됨). `python3 -m pip install` 또는 `--force-reinstall`로 명시적으로 현재 인터프리터에 설치해 해결 — 이 패턴이 Day마다 반복되는 만큼, 세션 환경이 바뀌지 않는 한 앞으로도 매번 동일하게 대응하면 된다.
