### 5. 구간 분류 버그 1건 발견·수정 (VLOOKUP 방향성 오류)
- 국가장학금 구간표를 처음에는 "소득인정액 **상한**(이 값 이하면 해당 구간)" 방식으로 설계하고 `VLOOKUP(조회값, 구간표, 1, TRUE)`로 구간 번호를 반환하려 했는데, LibreOffice 재계산 후 검증 단계에서 두 가지 문제를 동시에 발견했다.
  1. VLOOKUP의 반환 열 인덱스를 범위 시작 열(상한 열) 기준 1로 지정해, 실제로는 구간 번호가 아니라 상한값 자체(예: 1,948,421)가 그대로 반환되는 버그.
  2. 더 근본적으로, "상한" 배열에 대한 VLOOKUP 근사일치(TRUE)는 "조회값보다 작거나 같은 값 중 가장 큰 값"을 찾기 때문에, 예를 들어 소득인정액 300만 원(2구간 상한 324만 원 이하, 1구간 상한 194만 원 초과)을 넣으면 "194만 원"(1구간의 상한)이 가장 큰 매치가 되어 **1구간으로 잘못 분류**되는 구조적 오류였다(상한 배열로는 "이 값 이하"라는 경계 판정이 거꾸로 적용됨).
  - 재산등급표(Day66)·반환비율표(이번 파일 D)처럼 올바르게 작동했던 기존 패턴을 다시 확인한 결과, 공통점은 모두 "**하한**(이 값 이상이면 해당 구간)" 방식이었다는 것. 구간표를 상한 10개 값(1,948,421~19,484,214) 대신 **하한** 10개 값(0, 1,948,422, 3,247,370, …, 19,484,215 — 각 구간 상한값+1원을 다음 구간의 하한으로)으로 재구성하고, 구간 판정 수식을 `MATCH(조회값, 구간표!$B$2:$B$11, 1)`로 교체(MATCH의 반환 위치가 곧 구간 번호와 일치하도록 행 순서를 맞춤)해 해결. 수정 후 소득인정액 300만 원→"구간 2"(정상), 2,500만 원(300% 초과)→"구간 10"(정상)임을 별도 테스트 파일로 재확인.
  - **교훈** — VLOOKUP 근사일치는 반드시 "하한(이 값 이상)" 배열에만 적용해야 하고, "상한(이 값 이하)" 배열로 구간을 분류하려 하면 거꾸로 분류되는 구조적 버그가 생긴다는 점을 다음 Day를 위해 명시적으로 기록해둔다. 상한값을 그대로 가진 공개 자료(이번 경우 "1구간 30%(1,948,421원) 이하" 식의 발표 수치)를 엑셀 VLOOKUP에 쓸 때는, 그 값 그대로 쓰지 말고 "다음 구간 하한 = 이번 구간 상한+1"로 변환하는 과정이 반드시 필요하다.

## 이슈/트러블슈팅
- **VLOOKUP 근사일치의 방향성 오류 (구간 분류 버그)** — "상한값(이 값 이하면 해당 구간)" 배열에 `VLOOKUP(값, 범위, 열, TRUE)` 근사일치를 적용하면 구간이 한 단계 낮게(더 느슨하게) 잘못 분류되는 구조적 버그를 LibreOffice 재계산 검증 단계에서 발견했다. "하한값(이 값 이상이면 해당 구간)" 배열로 재구성하고 `MATCH(값, 범위, 1)`로 교체해 해결 — **다음부터 구간·등급 분류용 근사일치 룩업 테이블을 설계할 때는 처음부터 "하한" 기준으로 배열을 구성할 것. 공개 자료가 "~이하"(상한) 형태로 발표돼 있다면 반드시 "다음 구간 하한 = 이번 구간 상한+1"로 변환하는 과정을 거칠 것.** 이번에는 LibreOffice 재계산 값을 셀 단위로 수동 검산하는 절차(Day62·64·66에서 확립) 덕분에 작성 직후 발견했지만, 수동 검산을 생략했다면 가격·구간 안내가 통째로 틀린 채 판매될 뻔한 사례라 다음 Day에서도 이 검증 절차를 반드시 유지할 것.
- **국가장학금 소득분위 구간표 조사 — 공식 자료 직접 확인 어려움** — 한국장학재단 공식 페이지가 검색 결과 상단에 바로 노출되지 않아, 여러 블로그·언론 기사를 교차검증하는 방식으로 진행했다. 구간별 지원 단가(1~3구간 600만 원 등)는 여러 독립 출처에서 일관되게 확인됐으나, 2~9구간의 정확한 소득인정액 경곗값은 확장 검색(extended 모드)을 추가로 수행한 뒤에야 "한국장학재단 공식 페이지"를 인용한 자료로 확보할 수 있었다 — 1차 표준 검색만으로 끝내지 않고, 핵심 계산 로직에 들어가는 수치는 신뢰도가 애매하면 확장 검색을 추가로 수행하는 것이 유효했다. 그럼에도 불확실성이 남는 부분은 계산기 안내 시트·README·상세페이지에 "공개 자료를 바탕으로 정리한 기준값, 재단 확인 필요" 문구로 명시했다.
- **Playwright Chromium 경로 / python3·pip3 인터프리터 불일치 / PIL 임포트 오류** — Day64·Day66 진행일지에서 예고된 대로 세 가지 문제(Chromium 기본 경로 탐색 실패, python3/pip3가 다른 인터프리터를 가리킴, pillow가 시스템 설치본과 충돌)가 이번에도 모두 재발했다. 이번엔 사전에 알고 있었기 때문에 `PLAYWRIGHT_CHROMIUM_PATH` 환경변수 지정, `python3 -m pip install`, `--force-reinstall pillow numpy`를 처음부터 표준 절차로 적용해 지연 없이 진행했다 — **세션 환경이 바뀌지 않는 한 앞으로도 매번 이 세 가지를 기본 절차로 적용할 것.**
