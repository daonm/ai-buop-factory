### 3. 콘텐츠 설계
- 전자책의 "방법 1(첨삭 기준표)"과 "방법 5(직무별 맞춤 첨삭)"를 워크시트 2·3으로, "방법 9(패키지·가격)"를 워크시트 4로, 신규로 "고객 접수 양식"(워크시트 1)과 "고객 기록·후기 트래커"(워크시트 5)를 추가해 총 5개 워크시트로 구성 — 전자책에 없던 실무 도구(접수 양식, 트래커)를 보강해 "책 그대로 옮긴 것"이 아니라 "책을 실행 가능하게 만든 것"이 되도록 설계.
- 체크리스트는 전자책의 12가지 방법을 시간 순서(주차)가 아니라 **첨삭 한 건이 처리되는 실무 프로세스 4단계**(접수&진단 → 본 첨삭 → 납품&부가서비스 → 후속관리)로 재구조화 — Day02의 "30일 체크리스트"(시간 흐름형)와 달리 이 상품은 "고객 1건당 반복되는 워크플로우"이므로 프로세스 단계형이 더 적합하다고 판단.
- 프롬프트는 전자책의 16개(A 진단·구조/B 문항별/C 직무·ATS/D 운영)를 실무 단계에 맞춰 A 진단·스크리닝(8)/B 직무별 맞춤 첨삭(10)/C ATS·키워드(8)/D 면접·부가서비스(6)/E 운영·확장(8) 5개 카테고리 총 40개로 확장 — 특히 B 카테고리에 개발자/마케터/디자이너/영업/신입 5개 직무군별 첨삭 프롬프트(B6~B10)를 신설해, 전자책 표(방법 5)에서 "직무별로 다르다"고만 설명했던 것을 실제로 각 직무마다 바로 쓰는 프롬프트로 구현.
- 카테고리 5개 × 8개(A/C/E) 또는 10/6개(B/D)로 설계 — Day13 일지에서 언급된 "홀수 카테고리 → 2열 그리드 마지막 줄 카드 1개 단독 → 빈 공간" 버그를 피하기 위해 카테고리별 프롬프트 개수를 모두 짝수로 맞춤.

## 이슈/트러블슈팅
- **detached HEAD 재발**: Day13 일지에서 예상했던 대로 이번 세션도 detached HEAD로 시작함. `git fetch origin main` → `git checkout -B main origin/main`으로 정리. 클라우드 세션이 매번 새 컨테이너에서 시작하는 구조상 계속 재발할 가능성이 높으므로, 다음 실행 때도 작업 전 이 순서를 습관적으로 먼저 수행할 것.
- **워크시트 안내 문구 오타**: 초안 작성 중 "스피드가price 근처로"라는 한/영 혼용 오타 발생 — PDF 육안 검수 단계에서 즉시 발견해 수정. 초안을 빠르게 쓸 때 영단어 자동完성/자기 교정 없이 그대로 남는 경우가 있으므로, 앞으로도 PDF 페이지별 육안 확인을 오타 검수 단계로도 활용할 것.
- **체크리스트 4단계 페이지 분리로 인한 여백**: 기준(30%) 이내였으나 완전히 없애지는 못함. 체크리스트 카드 자체를 더 줄이면 가독성이 떨어질 수 있어 이번엔 기준 통과 선에서 유지 — 추후 비슷한 4단계 이상 체크리스트 설계 시, 카드 3개 단위로 페이지가 자연스럽게 나뉘도록 그룹 순서를 미리 계산해보는 것을 고려.
- 그 외 렌더링/스크린샷 도구(`render_pdf_cloud.js`, `screenshot_pdf_pages_cloud.js`, `screenshot_element_cloud.js`)는 Day02~13에서 이미 검증된 그대로 문제없이 재사용됨. 특이 오류 없음.
