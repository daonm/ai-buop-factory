### 4. 콘텐츠 구조 설계
Day67 패턴(기준값·자격 확인 + 핵심 계산 단계 + 수익화 1챕터 + 실수 1챕터 + 시스템화 1챕터 + 프롬프트 15선 + 체크리스트, 총 16섹션·12가지 방법)을 그대로 따라 아래 순서로 설계:
1. 왜 지금 AI로 이혼 재산분할·위자료 계산 대행인가 / 2. 준비물 3가지 / 3. 방법1 분할 대상 재산 목록화(공동재산 vs 특유재산) / 4. 방법2 기여도 비율 추정 / 5. 방법3 순재산 계산(총재산-채무) / 6. 방법4 재산분할액 계산(순재산×기여도) / 7. 방법5 퇴직금·연금 분할 계산 / 8. 방법6 위자료 산정 요소 점검 / 9. 방법7 위자료 예상 범위 추정 / 10. 방법8 양육비와 재산분할·위자료 구분 / 11. 방법9 재산분할 청구기한(제척기간) 점검 / 12. 방법10 대행 부업 수익화 / 13. 방법11 흔한 실수 6가지 / 14. 방법12 대행 시스템 구축 / 15. 프롬프트 15선(A.재산목록화·기여도 B.재산분할액계산 C.위자료·기한점검 D.대행서비스화, 각 4·4·4·3개) / 16. 실전 체크리스트(오늘/이번주/이번달 3단계)
- 이 주제만의 핵심 함정(재산분할 비율을 확정 수치처럼 안내, 채무 미반영, 장래 퇴직급여·연금 누락, 위자료를 유책사유 하나만으로 단정, 양육비와 재산분할·위자료 혼동, 2년 제척기간 누락)을 13장 실수표에 명시적으로 반영.
- Day61~68 시리즈(연금·실업급여·건강보험료·학자금대출)와 달리 이번 주제는 "재산분할"과 "위자료"라는 서로 완전히 다른 두 법적 성격을 가진 항목을 함께 다뤄야 해서, 방법 1~5(재산분할 계산 트랙)와 방법 6~9(위자료·기한 트랙)로 전반부를 명확히 2분할하고, 방법 8에서 "양육비는 또 다른 제3의 항목"이라는 점을 별도로 구분하는 챕터를 추가해 세 항목(재산분할/위자료/양육비)을 혼동하지 않도록 설계. 법률 인접 주제인 만큼 방법 10(수익화)에 변호사법 위반 소지 관련 경고 문구를 Day67 패턴에는 없던 내용으로 추가.

### 6. PDF 렌더링 및 검증
- `/opt/pw-browsers/` 디렉터리 확인 결과 이번 컨테이너도 `chromium-1243/chrome-linux64` 구조였고, `/opt/pw-browsers/chromium` 심링크가 이미 올바른 실행파일을 가리키고 있음을 확인 → `PLAYWRIGHT_CHROMIUM_PATH=/opt/pw-browsers/chromium` 환경변수로 `render_pdf_cloud.js` 실행, 첫 시도에 바로 PDF 16페이지 생성 성공.
- `python3 -c "import PIL"` 테스트 결과 Day63·65·67과 동일하게 `_imaging` 네이티브 확장이 깨져 있어 `python3 -m pip install --break-system-packages --force-reinstall --no-deps --ignore-installed pillow numpy`로 선제 해결(pillow 13.0.0, numpy 2.4.6 설치).
- `pdftoppm -png -r 150`으로 페이지별 PNG 변환 후 `scripts/scan_page_margins.py`(-I 플래그로 실행)로 하단 여백 비율 정량 스캔.
  - 스캔 결과: 1페이지(표지) 43.3%, 16페이지(에필로그, 마지막 페이지) 38.2%만 30% 초과 — 둘 다 설계상 의도된 독립 페이지라 정상. 나머지 14개 본문 페이지는 모두 6.8~20.2%로 과도한 빈 공간 없음.
- `scripts/screenshot_element_cloud.js`로 `.cover`를 673×950(PDF 실제 인쇄 폭) 뷰포트로 캡처해 육안 확인 — "이혼 재산분할·위자료", "계산 대행하는 법", "이혼 재산분할 프롬프트 15개" 등 숫자+단위 조합이 `nowrap` 처리되어 어색하게 끊기는 곳 없음.
- Read 툴로 PDF 페이지 PNG(7페이지: 재산분할액 계산→퇴직금·연금 분할 챕터 전환부, 14페이지: 프롬프트 15선의 A·B 카테고리 2단 그리드, 16페이지: 체크리스트 3단계+에필로그)를 직접 육안 확인 — 카테고리별 색상 구분·2단 그리드·배지·줄무늬 표가 의도대로 렌더링되고, 챕터 전환도 끊김 없이 자연스럽게 이어짐.
- `scripts/screenshot_element_cloud.js`로 `.cover`를 1000×1000(scale 2)로 캡처해 `marketing/thumbnail.png`로 저장 — 별도 AI 이미지 생성 도구를 쓰지 않고 책 표지 디자인을 그대로 재사용.
- PDF 파일명은 `이혼서류에도장찍기전에_AI한테먼저물어보세요.pdf`로 저장(Day67의 `등록금고지서받기전에_AI한테먼저물어보세요.pdf` 네이밍 관례를 그대로 따름).
