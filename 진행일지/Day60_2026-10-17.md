### 3. 육아휴직급여·출산휴가급여 최신 수치 WebSearch 검증 (2회)
Day59 진행일지에서 "6+6 특례 월별 상한액은 자료마다 수치가 크게 달라 책 본문에 정확한 구간표를 넣지 않았다"고 기록해뒀던 부분을, 이번엔 계산기가 실제로 숫자를 내야 하므로 다시 검색해 구체적인 기준값을 확정했다.
- 검색 1 "2026년 육아휴직급여 상한액 하한액 6+6 부모육아휴직제 월별 상한액표": 여러 출처(대부분 블로그)에서 **일반 육아휴직급여 1~3개월 상한 250만원·4~6개월 200만원·7개월이후 160만원, 하한 70만원**으로 일치. 6+6 특례는 "부부 합산 최대 약 3,900만원, 월 최대 450만원"이라는 총액 정보만 확인(구간별 표는 미확인).
- 검색 2 "2026년 출산전후휴가급여 상한액 배우자 출산휴가 20일 급여 고용24": **출산전후휴가급여 월 상한액 220만원**(2026년 기준, 기존 210만원에서 인상), **배우자 출산휴가 20일**로 확인.
- 판단: 검색으로 확인한 "일반 구간 상한액 250/200/160만원·하한 70만원·출산휴가 상한 220만원·배우자휴가 20일"은 Day59 전자책에 이미 쓴 수치와도 일치해 계산기에 그대로 반영. 6+6 월별 구간표는 공식 출처를 확보하지 못했지만, 세션 전 이미 설계해둔 1~6개월 200/250/300/350/400/450만원 구간표(부부 각 1인 기준)의 **6개월 합계(1,950만원)를 2배 하면 3,900만원**이 되어 검색으로 확인한 "부부 합산 최대 약 3,900만원"과 정확히 일치함을 확인 — 이 구간표를 그대로 채택하되, kit.html·엑셀 안내시트·README 모두에 "기준값, 신청 시점 고용24 고시로 재확인" 문구를 명시해 리스크를 낮췄다(Day57~59에서 반복해온 것과 동일한 원칙).

### 4. 엑셀 계산기 3종 + 체크리스트 1종 제작 (openpyxl, 수식 직접 작성)
Python 환경에 `openpyxl`·`python-docx`가 없어 `python3 -m pip install openpyxl python-docx`로 먼저 설치(시스템에 python3.11과 python3.13 두 인터프리터가 공존하는 환경이라, `python3 -I` 실행 커맨드가 실제로 쓰는 인터프리터에 직접 설치되게 함).
1. **출산전후휴가_배우자출산휴가_급여계산기.xlsx** — 월 통상임금·다태아 여부·우선지원대상기업 여부를 입력하면 1일 통상임금 환산 → 사업주 100% 부담일수(대규모기업 60/75일)와 고용보험 지급일수 구분 → 상한액(월 220만원) 적용까지 자동 계산. 배우자 출산휴가(20일, 우선지원대상기업만 5일 고용보험 지원)도 같은 시트 하단에 이어서 계산.
2. **육아휴직급여_계산기.xlsx** — 월 통상임금과 휴직 전체 기간(1~18개월)을 입력하면 구간별(1~3/4~6/7개월이후) 상한액(250/200/160만원) 적용 → 하한액(70만원) 보정까지 반영한 18행 월별표와 전체 기간 총 수령액을 자동 계산.
3. **특례적용_재계산기.xlsx** — 부모 각각 휴직 여부·한부모·장애아 여부·기간연장 조건을 입력하면 6+6 특례(월별 상한 200~450만원, 100% 지급률)·한부모 특례(1~3개월 상한 300만원)·기간연장(최대 18개월) 대상 여부를 자동 판정하고, 일반구조/6+6+일반/한부모+일반/연장18개월 4가지 시나리오의 총 수령액을 비교.
4. **신청일정_체크리스트.xlsx** — `주요일정계산기` 시트(EDATE 함수로 신청 가능 시작일·신청 마감일 자동 계산, TODAY() 기준 D-day·상태 표시)와 `신청서류체크리스트` 시트(출산전후휴가 5개·육아휴직 5개·공통/특례 2개 = 12개 항목, 드롭다운 데이터검증으로 준비 상태 선택) 2개 시트로 구성.
- **모든 수식을 LibreOffice headless로 실제 재계산해 검증** — `soffice --headless --convert-to xlsx`로 왕복 변환 후 `data_only=True`로 캐시된 계산값을 읽어 수작업 검산과 전부 일치하는 것을 확인(출산휴가급여 6,600,000원/배우자휴가급여 1,966,667원, 육아휴직 12개월 총액 22,800,000원, 특례 시나리오1~4 = 22,800,000/26,100,000/22,800,000/32,400,000원, 신청마감 D-day 746일 — 전부 재계산 결과와 1원 단위까지 일치). 이 과정에서 날짜 입력 셀을 처음에 문자열("2026-11-01")로 넣어 EDATE 수식이 깨질 뻔한 버그를 발견해 `datetime.date` 객체로 수정.

- **kit.html 예시 숫자 암산 오류 3건** — 01장 참고표의 B(월별 총수령액)·C(시나리오 비교)·D(D-day) 예시를 처음엔 암산으로 작성했다가 각각 25,200,000→22,800,000원, 21,750,000→26,100,000원·34,800,000→32,400,000원, 380일→746일로 정정. 엑셀 수식을 LibreOffice로 실제 재계산해 대조하는 절차를 먼저 거친 뒤에야 발견됐다 — **다음 Day부터는 kit.html에 예시 숫자를 적기 전에 반드시 해당 엑셀 파일을 LibreOffice headless 왕복 변환으로 먼저 계산해두고, 그 결과값을 그대로 복사해 넣는 순서로 작업할 것** (암산 → 나중에 검증하는 순서가 아니라, 계산 → 그 결과를 베껴 쓰는 순서로 바꾸면 이런 오류 자체가 생기지 않는다).

- **python3 인터프리터 불일치 재발** — 이번 세션에서도 `pip3 install`과 세션이 실제 실행하는 `python3`가 가리키는 인터프리터가 달라(`pip3`는 python3.13 경로, `python3`는 python3.11) `ModuleNotFoundError: No module named 'openpyxl'`이 발생했다. `python3 -m pip install openpyxl python-docx`로 해결(Day57~59에서도 같은 유형의 문제가 Pillow/numpy로 반복 발생했던 것과 동일 원인) — **스크립트 실행 전에는 항상 `pip3 install`이 아니라 `python3 -m pip install`로 설치할 것**을 이번에도 재확인.
